# Interior kit: element schema (MajibangBuilder "Interior kit" region)

Spec-driven generators that turn zone-spec elements into meshes with metre UVs, library materials and colliders.
The code lives in `AgentScripts/MajibangBuilder.cs` (section `Interior kit`). The same schema summary sits at the top of that section.

## Entry points
| Entry | Use |
|---|---|
| `KitBuild(args)` | `args[0]` = zone spec JSON (`{"zone", "elements":[...]}` or a bare array); `args[1]` = root path `Parent/Child` (the parent must exist and be active) or `Root`. Builds a fresh root (world origin, rotation Euler(0,16.2,0), so local = station UVY). It replaces the old child of the same path only after a successful build. Meshes go to `Assets/ChooGuard/Art/StationInterior/Kit/<zone>/` and stale meshes of the previous receipt are deleted. The receipt `<spec>.receipt.json` holds per-element triangles, lights, surfaceArea, meshes and materials. Does not save the scene. |
| `KitPreview(args)` | `args[0]` = PNG prefix; `args[1]` (optional) = showcase spec (default `kit-preview/showcase.json`, generated by `kit-preview/make_showcase.py`). Builds under a `HideAndDontSave` root at U/V 400, Y 50 with in-memory meshes and materials, renders each view with a temporary camera and destroys everything in `finally`. Writes `<prefix>-<view>.png` and `<prefix>-report.json`. |
| `KitValidate(args)` | `args[0]` = spec JSON. Dry build through the same KitElement path (real frames and positions) under a `HideAndDontSave` root with in-memory meshes and materials. No AssetDatabase, scene or receipt writes. Per-element exceptions (param rules, unknown types, duplicate ids) are caught and the build continues. Also runs a read-only mesh-folder ownership check against `kit-folders.json` (root = `args[1]` or the spec's top-level `root`; a conflict counts as an error). Writes `<spec>.validate.json` {zone, folder, root, folderOwner, folderConflict, elements:[{id,type,tier,ok,built,error,triangles}], errors}. |
| `KitMaterials(args)` | Persists kit-owned materials (`KitDefs`, `KitDerived`, `KitTextureFinishes`) and their exterior PBR texture assets to `Kit/Materials/`. |

Commands:
```
unity command run_script --file <abs>/AgentScripts/MajibangBuilder.cs --entry MajibangBuilder.KitBuild --dry_run true      # compile check
unity command run_script --file <abs>/AgentScripts/MajibangBuilder.cs --entry MajibangBuilder.KitValidate --args '[["<spec.json>"]]'
unity command run_script --file <abs>/AgentScripts/MajibangBuilder.cs --entry MajibangBuilder.KitBuild --args '[["<spec.json>","<Parent>/<Child>"]]'
python3 .planning/2026-09-24-interior-twin/kit-preview/make_showcase.py
unity command run_script --file <abs>/AgentScripts/MajibangBuilder.cs --entry MajibangBuilder.KitPreview --args '[[".planning/2026-09-24-interior-twin/kit-preview/kit"]]'
```

## Element envelope
```json
{"type": "Storefront", "id": "1F-sf-03", "zone": "1F", "tier": "b", "evidence": ["path", "..."],
 "frame": "root", "geometry": {...}, "params": {...}}
```
- `tier`: only `a`, `a-failed` and `b` are built. `c` or a missing tier is skipped and reported as `built: false` (positions are never invented).
- `frame`: `root` (station UVY) or `box` (majibang-plan `boxFrame`: a along the box axis, b across).
- Units: metres in source-model units; `y` values are absolute heights; angles in degrees; colours `"#RRGGBB"`.
- Geometry vocabulary: `point [u,v]`, `edge [[u,v],[u,v]]`, `polyline [[u,v],...]`, `polygon [[u,v],...]`, `holes [[[u,v],...],...]`.
  Holes may touch, overlap or cross the outer ring. Filled = inside the outer ring and outside the union of the holes.
  Large regions with many holes are trapezoidated. A one-polygon test (2F main region, 32 holes) built at 6,707.4 u², equal to the shapely result: `kit-preview/stress-2f-one-polygon-*`.
- Facing: `params.faceToward [u,v]` (preferred) or `params.side "left"|"right"`, where left = (-dv,du) of the edge direction.
  Point elements take `params.heading [du,dv]` or `faceToward` (front / upward-travel direction).
Materials (any `finish`/`colour`/`frame`/... field): a finish keyword from `KitFinishes`, `KitDerived`, or `KitTextureFinishes`; a kit material name, `"#RRGGBB"` paint, or an `Assets/...mat` path.
  - Keywords: `ceiling600` (Kit_Ceiling600 = OfficeCeiling003 maps, albedo .86 + self-emission), `ceilingPan`, `ceilingMetal`, `ceilingLouver`,
    `gypsum`, `plaster`, `panel`, `granite`, `stone`, `stainless` / `hairline` (metallic .45) / `stainlessSatin` (lighter, low metallic), `steelWhite`,
    `tactileLine`, `tactileDot`, `seat`, `rubber`, `signCase`, `glass`, `steel`, `dark`, `white`, `yellow`, `counterWood`, `gateBody`,
    `machineBlue`, `locker`, `escalatorBody`, `ledPanel`, `downlight`, `linearLight`, `navy`, `stepTread` (official escalator step).
  - Exterior PBR keywords: `lawn`, `sand`, `paving`, `asphalt` (CC0 ambientCG 1K maps; textures use metre UVs and are persisted under `Kit/Materials/ExteriorTextures` during a real build).
  - Kit-owned (`Kit/Materials`): `Kit_SignNavy`, `Kit_SignGreen`, `Kit_Glyph*`, `Kit_Screen`, `Kit_ScreenBlue`, `Kit_Emit{Green,Red,Amber,Cyan}`,
    `Kit_Rubber`, `Kit_Backlight`, `Kit_GridWhite`, `Kit_Product*`, `Kit_Bread`, `Kit_SteelWhite`, `Kit_StainlessSatin`, `Kit_Exterior_*`.
- Colliders are renderless double-sided meshes (`Kit_Colliders` batch) plus prop BoxColliders.
  `FloorFinish` overlays, ceilings and signs have no collider by default; `Slab` / `Room` floors use their documented settings. Canopy roof colliders are opt-in; side-glass panels always block traversal.

## Integration notes
- Storefront hand-off: `"storefronts": "kit"` at the top level of `interior-spec.json` (1F) or in `majibang-plan.json` (2F) leaves unit fronts open
  (no builder glass, frames, fascia band or signs). Walls, shop ceilings, lights and fixtures are kept. `CorrectOpenFrontages` forces
  builder fronts; `RefreshFascias` refuses to run on a kit-storefront plan.
- Lighting below slabs: ceilings use self-lit kit ceiling materials. Add `fixtures.lights` or `Lighting` elements only where a zone has no light from elsewhere.
- Enclosure shadows: batches whose name contains `Kit_Ceiling_`, `Kit_CeilingGrid`, `Kit_Bulkhead`, `Kit_Clad_`, `Kit_Joint`, `Kit_Fascia_`,
  `Kit_ShopWall_`, `Kit_ShopCeiling_` or `ShopCeiling` (builder 2F `Majibang_ShopCeiling`, 1F `Ground_ShopCeiling`) cast two-sided shadows.
  Materials without a ShadowCaster pass (URP Unlit ceiling panels) get a `_ShadowCaster` child: shadows-only, cull-off `Kit_ShadowCaster` material.
  Proof: the showcase has no roof box, and no sun reaches the floor under the kit ceilings (`kit-hall.png`).
- 2F slab openings (`majibang-plan.json` top-level `slabOpenings`): `[{id, polygon [[u,v],..] (root frame), guard {height 1.1,
  finish "glass"|<material>, edges "all"|[indices], open [edge indices left unguarded for escalator/stair landings]} | false, evidence}]`.
  SecondFloor clips every cell run exactly against the polygons (outer minus union), keeps top 7.0 / underside 6.7 elsewhere and closes the
  vertical faces on the opening edges. It then builds a glass guard (stainless shoe, posts <= 1.2 m, top rail, collider) .06 m outside each guarded edge.
  `majibang-build.json` records `slabOpenings` [{id, polygon, area, guardedEdges, evidence}]. Proof: `kit-opening.png`, `kit-opening-below.png`
  (the same ClippedSlab/OpeningGuard code runs through the showcase `runs` scaffold).
- Box hall appearance (`majibang-plan.json` top-level `hallAppearance: "white"`, evidence BL-05 / CX-19): trusses keep every hallStructure
  line, node and radius but become smooth round white tubes (`Kit_TrussWhite`). A white deck liner (`Hall_DeckLiner`, `Kit_DeckWhite`) is sampled
  30 mm under the original roof underside on a 1.5 m grid (only where the deck is >= minDeckY 19.5). Skylight strips (`Hall_Skylights`,
  Lane `roof_daylight_glazing`, 1.2 m wide) run along a between each pair of constant-b truss lines. `majibang-build.json` records `hallAppearance`.
- Builder appearance fixes (EnhanceBox2F `builderRequests`, evidence in `specs/enhance/2f-box-report.json`), previewed through KitPreview scaffold hooks
  (`lantern`, `infoDesk`, `bench` in `kit-preview/showcase-builder.json`; renders `kit-preview/builder-fix-{lantern,desk,bench}.png`):
  - Lantern (G-B07 / BL-09, always on): frame in dark bronze `#2B2F33` instead of Tube_White, a tapered base cone (radius -> .5 over .6 m),
    warm translucent emissive panes (`Kit_LanternGlass`, ~#FFE2B0).
  - Info desk (G-B09 / G-B10 / BL-12): `secondFloorExtras.info.customerSide [du,dv]` (desk frame) puts "KORAIL 부산역" lettering directly on the
    canopy (front and back, no fin boards), one lightbox with a closed dark housing on the customer side, a KORAIL + blue "K" plaque on the body,
    and three acrylic counter screens with monitors. It must point away from the +u staff opening (within 40 deg of +u throws).
    `info.kit: true` skips the builder desk so a kit spec can model it. With neither field, the output is unchanged.
  - KorailBench (G-B11 / BL-27, always on): one wood material with metric UVs on all faces, stainless U grab bars lying on the seat between places,
    blue KORAIL decals on the outer leg faces. `seating.decalText: false` drops the lettering (264 world-text objects for 132 benches).
  - wallPanels (G-B17 / BL-26, always on): the texture panel housing is a closed dark box from the panel plane back to `depth`, so back-to-back
    panels (sign_Tickets_1F / sign_FoodCourt_Tickets) share one solid backer. The 3F EdgeBand tenant panels were already single-sided
    (Unlit, back-culled) over a band wound toward the void, so they are unchanged.
- Kit mesh-folder ownership (Main, 2026-09-25): batches are named by material, so two roots that share a spec `zone` would overwrite each
  other's meshes in `Kit/<zone>/` (including `Kit_Colliders`). `KitBuild` reads `.planning/2026-09-24-interior-twin/kit-folders.json`
  (folder -> owning root path), throws if a different root claims the folder, and registers the folder after a successful build.
  Every root therefore needs its own zone; the enhancement specs use `"<zone> 보강"`. `KitValidate` reports the same conflict read-only.
- 3F rail guard (Main, 2026-09-25): `thirdFloor.railGuard` (default true); `false` skips the builder `Rail()` guards on `thirdFloor.rails`
  but keeps the `Majibang_3F_EdgeFascia` slab-edge band, so a kit Balustrade can replace the rails without losing the fascia.
