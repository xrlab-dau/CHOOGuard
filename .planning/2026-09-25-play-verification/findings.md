# Findings: 켜 보니 나온 것들

## 1. 가장 큰 것 — 점검표는 그려지지 않고 있었다

전날 나는 "점검표가 보이지 않는다" 를 고쳤다고 보고하고 영수증에 PASS 로 적었다.
실제로 한 일은 **"렌더러 없는 빈 오브젝트" 를 "렌더러 있는, 그래도 안 보이는 쿼드" 로 바꾼 것**이었다.

판정 근거가 된 단언은 이랬다.

```
Assert.IsNotNull(facility.AttachedTag);
Assert.IsNotNull(tagRenderer);
Assert.IsTrue(tagRenderer.enabled);
```

셋 다 통과한다. 그리고 화면에는 아무것도 없다. 부착 전/후 프레임을 같은 각도로 찍어
픽셀 비교했더니 **상단에서 다른 픽셀이 0 개**였다(달라진 것은 하단 안내 문구뿐).

계측값은 전부 정상으로 보였다는 점이 함정이었다.

| 항목 | 값 |
|---|---|
| 위치 | 조준점 정중앙, 눈에서 1.10m |
| 월드 크기 | 0.090 × 0.130 |
| `isVisible` | **True** |
| 머티리얼 | `korean_fire_extinguisher_01_paper` / URP Lit |

`isVisible` 은 절두체 안에 있다는 뜻이고 **뒷면 컬링을 반영하지 않는다.**

### 원인 두 겹

**(a) 방향.** Unity `Quad` 는 한쪽 면만 그리고 보이는 면이 `-Z` 쪽이다. `AttachTag` 가
`localRotation=identity` 로 붙이는데 앵커에 회전이 없어, 보이는 면이 본체 안쪽을 향했다.
→ 생성기에서 앵커에 `Euler(0,180,0)` 을 넣었다. 방향을 앵커에 고정해 두면 `AttachTag` 는
계속 identity 로 붙이면 된다 — 런타임이 방향을 계산하기 시작하면 계층이 뒤집힌다.

**(b) 재질.** 소화기 본체의 종이 라벨 재질을 재사용해, 쿼드 UV 가 2k 텍스처 전체를 끌어와
24px 짜리 흑백 체커 무늬로 보였다. → 텍스처 없는 전용 재질 `tutorial_inspection_tag.mat`.

### 검증

부착 전/후 상단 픽셀 차이 **0 → 578 개**, 차이 영역 `(401,187)–(425,212)`.
"단언이 통과한다" 가 아니라 이 수치로 판정했다.

## 2. 시작 지점이 목표에서 44.41m 떨어져 있다

| 계측 | 값 |
|---|---|
| 플레이어 시작 | `(26.00, 7.05, -47.00)` |
| 첫 소화기 | `(-10.00, 6.70, -73.00)` |
| 수평 거리 | **44.41m** |
| 15m 이내 렌더러 | 2,322 개 중 **5 개** |
| 직진 결과 | 11m 전진 후 **벽** |

시작 시야에는 빈 하늘만 있다. 처음 찍은 프레임이 온통 청록색이라 렌더링이 깨진 줄 알았는데,
방향을 돌리자 역사 내부(바닥·벽·천장·기둥·빨간 소화기)가 멀쩡히 나왔다. **렌더링 문제가 아니라
배치 문제다.** 생성기가 소화기 12 개는 좌표로 배치하면서 플레이어 시작 지점은 건드리지 않는다.

## 3. 첫 소화기 앞 설 자리가 1m 뿐이다

정면·뒷면 × 1.0 / 1.3 / 1.6 / 2.0m 여덟 자리를 탐색해 **정면 1.0m 한 곳만** 통과했다.
0.8m 물러섰더니 등 뒤 셔터에 카메라가 박혔다.

## 4. 점검표 자리를 조준하면 상호작용이 끊긴다

점검표는 본체 아래쪽(로컬 y=.26)에 붙는다. 1.0m 거리에서 눈높이 1.60m 로 그 지점을 보면
각도가 가팔라 **레이캐스트가 아무것도 맞히지 못한다**(`CurrentTargetCollider` 없음, 안내 빈 문자열).
붙은 점검표를 확인하려고 고개를 숙이는 순간 소화기와의 상호작용이 끊긴다.
점검표가 보이게 된 지금 오히려 더 걸리는 문제가 됐다.

## 5. 내 하네스 버그 세 건 (제품 문제로 세지 않는다)

- **판독면 방향 계산.** 판독면 중심에서 방향을 구했는데 생성기가 고유번호판을 좌우로 치우치게
  붙여(`side` 오프셋) 방향이 옆으로 끌렸고 플레이어가 벽에 박혔다. → 생성기가 쓰는 기준(로컬 +Z)으로 교체.
- **중력에 맡긴 착지.** 틈으로 빠져 바닥보다 0.57m 아래로 내려앉았다. → 위에서 아래로 레이캐스트해
  바닥을 먼저 찾고, 설 자리를 여덟 곳 탐색하도록 바꿨다.
- **조준 순서.** 점검표 자리를 본 채로 E 를 눌러 실패했다. → 조작은 판독면을 보고 하도록 분리.
  이 실수가 4 번 문제를 드러냈다.

그리고 **하네스의 진단 로그 자체가 틀렸다.** `dot` 부호를 반대로 해석해, 실제로는 그려지고 있는데
"뒷면을 보고 있다" 로 찍혔다. 로그를 믿었으면 또 틀렸을 것이다 — 판정은 픽셀 비교로 한다.

## 6. 정상 작동을 프레임으로 확인한 것

첫 화면 → Enter → 진입 / 조준 시 안내(`소화기의 고유번호를 먼저 확인하세요`) / 시선 체류로 관측 4 종 /
1·2 판정 선택 / E 기재 / **F 현장 수리 거부**(`소화기의 수리·구입 예산은 소방관리 책임자가 요구합니다`) /
점검표 부착 / 절차 8 단계 완주 / 한국어 HUD·조준점.

역할 경계 거부 문구가 화면에 실제로 뜨는 것까지 확인했다. 전날까지는 **누를 방법조차 없던** 기능이다.

## 7. 교훈

세 번 연속 같은 형태로 틀렸다.

1. 시험이 통과한다 → 사람이 도달하지 못했다 (전날)
2. 배선이 맞다 → 켜면 화면이 다르다 (오늘 시작)
3. 렌더러가 켜져 있다 → 그려지지 않는다 (오늘)

공통점은 **증거의 층위를 한 칸씩 낮게 잡은 것**이다. 다음 층위는 "그려진다 → 읽힌다" 이고,
그건 사람이 봐야 한다. 9×13cm 흰 카드가 점검표로 읽히는지는 아직 아무도 확인하지 않았다.
