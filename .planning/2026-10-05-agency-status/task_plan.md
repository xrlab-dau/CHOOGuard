# #271 출동 기관 상태의 상단 표시 및 지도 위치 추적

기준: `develop 84851835`. PR #269(지도 이름표)는 별도 검토 중이라 **쌓지 않고 develop 에서 시작**한다.

## 읽어서 확인한 사실

기관 상태 4단계가 **이미 데이터에 있다.** 새로 만들 상태 기계가 아니라, 있는 것을 읽어 보여 주는 일이다.

| 단계 | 코드 근거 |
|---|---|
| 출동 요청 | `IncidentDirector.cs:612 Call()` → `calledBy[agency]`, `arriveAt[agency] = Time.time + 지연` |
| 역 도착 | `:172-173 UpdateConsequences` → `Time.time >= arriveAt` 이면 `arrived.Add` + `SpawnTeam` |
| 현장 이동 | `SpawnTeam:691` 이 **생성 시 한 번만** `SetMarker("agency-"+agency, start, …)` |
| 현장 도착 | `OnResponderArrived:739` 이 **도착 시 한 번만** `SetMarker(…, responder.transform.position, …)` |

**그 사이에 갱신이 없다.** 이슈가 지적한 "이동 도중 좌표를 반영하지 않는다" 가 코드와 정확히 일치한다.

대표 좌표는 `responders` 중 `Lead == true` 인 `Responder.transform.position` 이다 — 표식을 거는 조건(`i == 0`, `responder.Lead`)과 같은 대상이라 기준이 흔들리지 않는다.

### 화면 자리

| 요소 | 앵커 · 위치 |
|---|---|
| `CompassBar` | `(.5, 1)` y −16 — **상단 가운데를 이미 쓴다** |
| `targetName` / `targetAction` / `toast` | 가운데, 조준점 아래 (y −44 / −72 / −150) |
| `slotRow` | `(.5, 0)` — **장비 칸**(무전기·빈손). 상태용이 아니다 |
| `status`(시각+상황) | `(0, 0)` 좌하단 |
| `hints` | 우하단 |

→ 상태 영역은 **나침반 아래**, 조준점 위의 빈 띠에 둔다. 기존 요소를 밀어내지 않는다.

## 할 일

1. **기관 상태 조회** — `IncidentDirector` 가 기관별로 (단계, 대표 좌표 유무, 현재 위치 이름)을 내준다. 상태 판정은 위 표의 기존 자료만 쓴다.
2. **표식 추적** — lead responder 가 있는 동안 `agency-<기관>` 표식을 주기적으로 갱신한다. 매 프레임은 과하므로 기존 `nextSight`(0.25초)와 같은 간격을 쓴다.
3. **상단 표시** — 나침반 아래 한 줄. 기관별로 `경찰 출동 중` / `소방 현장 이동 중 (2층 남측 출입구)` / `구급 현장 도착`.
4. **없는 것을 지어내지 않는다** — 팀이 생기기 전에는 좌표가 없다. `출동 중 · 위치 확인 전` 으로만 적고 역 밖 위치나 경로를 만들지 않는다. (하드룰: 인지하지 못한 것을 드러내지 않는다.)

## 바꾸지 않는 것

출동 시간(`Teams.Delay`), 사건 합성, 기관 판단·이동·조치, 종료 조건. 표시만 고친다.

## 검수

- PlayMode 회귀가 통과할 것.
- **좋은 경우와 나쁜 경우를 가르는 시험**: 기관을 부르고 팀이 걷는 동안 표식 좌표가 **실제로 바뀌는지** 본다. 지금 코드에서는 바뀌지 않으므로, 시험을 먼저 쓰면 실패하는 것이 맞다.
- 팀 생성 **전**에는 위치 문자열이 비어 있을 것(지어내지 않음을 단정으로 둔다).

## 미정

- 두 기관이 동시에 출동할 때 한 줄에 둘 다 쓸지, 줄을 나눌지 — 화면 폭을 보고 정한다.
- 층 표시를 `MapOverlay.Floor` 로 할지 `World.Describe` 에 맡길지.
