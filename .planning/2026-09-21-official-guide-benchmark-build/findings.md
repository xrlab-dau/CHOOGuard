# Findings

- Assigned URLs: construction, enclosures, attractions, guests, tips-and-tricks, park build ideas, attraction build ideas under the official JWE3 en-US site.
- Existing `catalog.json` confirms all seven assigned paths appear in the official sitemap candidate list.
- Live `urllib.request` checks returned HTTP 200 at every exact en-US URL with no redirect. Responses are about 3.66–4.28 MB; relevant visible bodies are 4,162–12,640 characters.
- Player guides use article class `v-jwe3-player-guides-detail`; toolbox pages use `v-jwe3-news-detail`. Whole-page extraction would mix navigation, workshop cards, related guides, and news, so visible text must come from the relevant article only.
- Analysis priority is build/gameplay method: modular/preset/snap/pivot/grouping workflows and operational consequences, not cinematic or cosmetic copying.
- Archived full HTML plus article-only visible text and a receipt for each page under `asset-library/research-public/2026-09-21/jwe-official/build-guides/`. The manifest covers seven pages, all HTTP 200, all exact final URLs.
- Construction directly ties buildings to a path network/arrival point, uses capacity-aware path widths and an overcrowding view, exposes terrain-adjust toggles, grid size/height and auto-stacking, multi-select/group/split, axis-constrained transforms with snap values, undo/redo with money reversal, blueprints, and required structure/module proximity.
- Enclosures directly model topology and operational prerequisites: closed boundaries can combine fences/terrain/objects, gates provide team access, modules snap at edges, attached powered hatcheries enable monitoring, security rating/power changes breach risk, and powered camera coverage plus assigned teams automates response.
- Attractions and guests directly connect spatial coverage to outcomes: sight lines and visibility views drive appeal, popular nodes create congestion, route placement can auto-insert crossings, every functional attraction generally needs path and power, management views reveal comfort/coverage gaps, and incident/safety ratings recover over time after response.
- Tips and toolbox pages reinforce fast bootstrapping from blueprints, blank core plus requirement modules, terrain-flattening foundations, staff automation with finite resources, natural barriers with capability exceptions, first-person inspection, and spatial separation of dangerous/research versus public zones. Cosmetic theme advice is lower transfer value.
- Current exact seams: `MvpStationZones.Layout/Reserved/Fits` already authors a metre-based kit with reserved aisles; `MvpInteriorBuilder.FunctionalZone` builds fixed functional archetypes but has no player build/edit loop; `MvpOperationsPort.TargetIds` exposes only platform/concourse/exit; `MvpWorkspace` already owns compact notices, planned orders, target selection, command receipts and feedback; `MvpTrainingDirector` owns ordinary→incident→resolved/incomplete continuity and debrief; `MvpStationView` owns team paths/anchors and floor/cutaway rendering.
- Current limitations: the station kit is editor-generated, static, visual, and explicitly not measured; no placement validity, snap sockets, connectivity graph, coverage field, undo ledger, blueprint serialization, congestion-management view, or persistent build state was found in the inspected MVP seams.
