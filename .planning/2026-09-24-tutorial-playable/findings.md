# Findings: 시험이 잡지 못한 것들

## 1. 왜 61 개 시험이 넷 다 놓쳤는가

공통 원인은 하나다. **시험이 세션의 공개 API 를 직접 불렀고, 사람은 그 API 에 도달하는 경로를 지난다.**

| 시험이 한 것 | 사람이 해야 하는 것 | 그 사이에 비어 있던 것 |
|---|---|---|
| `session.PendingVerdict = UNFIT` 대입 | 1·2 키를 눌러 고름 | 입력 컴포넌트 자체 |
| `session.AttachTag()` 호출 | 눈으로 붙은 것을 봄 | 렌더러 달린 프리팹 |
| `session.TryFieldRepair()` 호출 | F 를 눌러 시도 | 호출처 0 건 |
| 씬을 직접 열고 시험 시작 | 실행 → 첫 화면 → 튜토리얼 | `LoadScene` 0 건 |

**교훈:** "시험이 통과한다"는 그 코드가 옳다는 뜻이지, 사람이 거기 도달한다는 뜻이 아니다. 도달 경로마다 한 개씩 시험이 필요하다.

## 2. 세 번의 설계 오류

### (a) 즉시 전환은 화면을 지운다
`SceneEntryPoint.LoadOnStart=true` 로 두자 `CSBOOT0101PlayModeTests` 가 깨졌다 — 두 프레임 만에 씬이 바뀌어 카메라·캔버스 개수가 0 이 됐다. 첫 화면에 표시할 것이 있다면 입력을 기다려야 한다. `LoadOnStart=false`, `WaitForInput=true` 로 고정.

### (b) 코드를 고쳐도 씬은 그대로다
(a) 를 고친 뒤에도 시험이 계속 깨졌다. `Bootstrap.unity` 에 직렬화된 값이 여전히 `LoadOnStart: 1` 이었다. 생성기를 고치고 씬을 다시 만들어야 끝난다.

**이 작업에서만 세 번 반복했다:** ① `TechnicianDispatch` 배선 누락, ② `Target` 직렬화 이름 변경, ③ `LoadOnStart`. 앞의 두 번을 겪고도 세 번째를 또 했다.

### (c) 아무 입력이나 받으면 남의 UI 를 파괴한다
진입점이 마우스 클릭도 받게 했더니 `IntegratedInputPlayModeTests.ActualButtons_...` 가 깨졌다. 부트 씬이 남아 있는 상태에서 합성 클릭이 진입점에 걸려, 그 시험이 쓰던 패널이 씬 전환에 통째로 사라진 것이다. Enter·numpadEnter 만 받도록 좁혔다. 버튼을 붙일 때는 `WaitForInput` 을 끄고 `Load()` 를 직접 연결한다.

## 3. ECC 가 잡은 두 건 (모두 CRITICAL)

### 판정이 유닛 사이로 샌다
`PendingVerdict` 를 세션 전역 필드로 둔 탓에, A 에서 고른 판정이 B 로 넘어가 **아무것도 고르지 않은 B 의 게이트가 열렸다.** 다중 대상으로 만들면서 다른 상태는 전부 `UnitState` 로 옮겼는데 이것만 남겨뒀다. `UnitState.PendingVerdict` 로 이동, 공개 프로퍼티는 현재 유닛에 위임.

### 되감기가 거짓말을 한다
오판정 시 "되감기로 돌아가세요" 라고 안내하는데, 되감아도 설비에 기재된 `Verdict` 가 그대로 남아 다시 고를 수 없었다. 게다가 재기재하면 `MisjudgementCount` 가 한 번 더 올라 같은 실수가 두 번 집계됐다. `RevertEffect(unit, step)` 가 `record-serial`·`record-verdict`·`attach-tag` 가 남긴 월드 상태를 되돌리고 집계도 함께 내린다. 기술자가 이미 출발했으면 되감기를 거부하고 이유를 말한다.

## 4. 남은 것

- **④ 인계 시각 피드백.** 기술자는 상태 기계만 있고 몸이 없다. 요청 후 약 1 분간 문자열 외에 볼 것이 없다.
- **⑥ 소리.** 저장소에 `AudioSource` 0 건.
- **사람 플레이 검수.** 이 작업이 바로 "사람이 켜면 작동하게" 하는 것이었는데, 사람이 켜서 확인한 기록은 여전히 없다. 자동 시험으로는 대체되지 않는다.
- **2.00m 근접 경고** (`BSN-CONC-FE-004` ↔ `-006`). 상호작용 상한 3m 안이라 조준이 모호할 수 있다. 사람이 해봐야 안다.
