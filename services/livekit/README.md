# Local voice service

**Integration is in progress.** Service configuration alone does not establish microphone, PTT or internet acceptance.

The Foundation uses self-hosted LiveKit **1.13.6** and Unity SDK **2.0.0**. This recipe binds only loopback ports and has no monthly hosting charge. It provides no recording or egress service.

1. On supported macOS hosts, run `python3 services/livekit/configure_local.py --output <private-directory>`. Keep this directory outside Git; it contains service credentials. The creator stages the files privately and publishes them with an exclusive no-replace rename.

**Staging ownership boundary (P0).** Before the first credential byte, the creator binds the opened staging descriptor to the parent entry: `fstat` on the descriptor and `stat` on the entry must report the same `(st_dev, st_ino)`, both resolving to a directory. That evidence is re-derived immediately before the exclusive rename, where the trusted-parent precondition (`0700`, current-user-owned, no additional ACL) is re-verified too. Renaming moves the whole directory, so the gate requires exactly the entries this run acquired, each still resolving to the identity and bytes it was acquired with: an injected entry, an acquired name recreated with other bytes, one rewritten in place through its inode, one that has disappeared (reported as a loss of its own), and a directory that cannot be enumerated are refused. Because the rename is a later step, that evidence is re-derived once more after it; a mismatch is refused too, as detection after the fact. If the evidence does not hold, the run refuses and stops.

**Exact-owned rollback.** On failure the creator unlinks only names whose identity it acquired, and removes the staging or published directory only while the name still resolves to the proved inode; anything replaced or unproven is preserved for manual cleanup. That check and the `rmdir` are separate steps: a swap between them is not prevented (below).

**Platform and boundary limits.** Darwin/Python create a directory by pathname and open it separately, so the create→open window is not authenticated by pathname: what excludes another principal is the trusted-parent precondition, not the identity proof, and a same-account actor that wins that race is not detected - an empty adopted directory passes every gate and is published, one holding a foreign entry is refused and preserved (both pinned by fixtures). Three windows are acknowledged, not closed: the create→open race above, which is undetected; the span between the last re-derivation and the `renameatx_np` call, where a boundary replaced beneath the rename, or an entry changed or injected, is refused only after the rename published it, with manual cleanup guidance, not automatic removal; and rollback's stat→act window, where a same-account actor parks an empty directory under this run's unpredictable staging name before the `rmdir`, so this run removes that empty directory, leaving its own behind. Darwin keeps an open descriptor's `st_nlink` at 2 after `rmdir`, so what was removed is re-examined by re-enumerating the parent afterwards: detection after the fact, never prevention, unconfirmed when the parent cannot be listed. The worst it yields is removing an empty directory the actor parked under a name this run predicted; the actor gains nothing, able to read the published `0700` output anyway. Exclusive publication uses Darwin `renameatx_np` with `RENAME_EXCL` and privacy checks use Darwin descriptor ACL APIs; where those are unavailable the creator fails closed, and Windows and other platforms stay unsupported until separately verified backends exist.
2. Set `CHOOGUARD_VOICE_DIR` to that absolute directory and run `docker compose -f services/livekit/compose.yaml up -d`. LiveKit listens on `0.0.0.0` **inside the Compose bridge** so published ports can reach it; Compose keeps every host-published port pinned to `127.0.0.1`.
3. Start the authenticated game server with `--cg-voice-config <private-directory>/server-voice.json`. Game clients receive room-scoped grants over their game connection; service API secrets never enter client builds.
4. Stop with the same Compose file and directory: `docker compose -f services/livekit/compose.yaml down`.

Room auto-creation is disabled. Only the game server creates epoch-specific team and command rooms. Participant grants allow microphone publication according to channel permission, disable data publishing and contain no room administration/create permission. A server restart retires old room names before issuing new grants. Self-hosted participant removal alone does not revoke old JWTs; test room retirement and reconnect races explicitly.

Internet deployment needs trusted WSS/TLS, reachable ICE/TURN and separately verified game transport certificates. A loopback run does not establish WAN or end-to-end voice latency acceptance. Never expose these unencrypted loopback settings by changing only the published address.

Sources: [LiveKit 1.13.6 configuration](https://github.com/livekit/livekit/blob/v1.13.6/config-sample.yaml), [self-hosting ports](https://docs.livekit.io/transport/self-hosting/ports-firewall/), [token permissions and revocation limits](https://docs.livekit.io/frontends/reference/tokens-grants/).
