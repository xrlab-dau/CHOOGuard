# FPS 랜덤 시드 시뮬레이터 설계안

대상 공간은 한국철도공사(코레일)의 부산역과 주변 지역이다. 맵 전체 오브젝트와 NPC의 상태·행동·상호작용에서 상황이 생기는 **완전 랜덤 오픈월드**가 개발 목표다. 완성 사건의 목록을 추첨하는 방식으로 제한하지 않는다. 생성 모델의 계획, JEV의 판단, 시드 기반 실행과 계획 재사용을 결합해 행동 범위를 넓히면서 반복 호출 비용을 줄인다. 이 문서는 개발안이며 구현·비용·현장 정합성의 측정 결과가 아니다.

## 1. 연구를 확인한 결론

| 연구·제품 | 적용할 내용 | 적용 범위 |
|---|---|---|
| SimWorld, NeurIPS2025 [R24] | 세계 상태·목표에서 행동을 만들고 실행 결과로 다시 판단 | Unreal 기반 연구. Unity 연결과 비상 대응의 정합성은 별도 구현·검증 |
| Virtual Community, ICLR2026 [R28] | 공간에 연결한 NPC 관측·목표·기억·사회 관계와 행동 계획 | Genesis 기반이며 선택한 행동과 물리 연결에 한계. 모든 객체의 임의 상호작용을 증명하지 않음 |
| TypeSafe JEV 공식 API [R29] | Choice·Score·Noul로 제안과 상황 평가 | 자유 형식 계획·새 조작 의미·물리 법칙의 생성 기능은 아님 |
| AgenticCache, MLSys2026 [R25] | 계획 전이 재사용과 비동기 검토 | 조건이 바뀐 캐시는 검사·갱신 필요. 연구 절감률을 이 게임에 적용하지 않음 |
| ADaPT, NAACL Findings2024 [R26] | 실행할 수 없을 때 계획 분해·수정 | Unity의 경로·물리 실행을 제공하지 않음 |
| AutoGPT+P, RSS2024 [R20] | 객체에 가능한 행동을 계획에 연결 | 원 연구도 모델을 사용. 새 조작을 자동으로 구현하지 않음 |
| RESCUE, ICCV2025 [R19] | 인지·판단·운동 분리 | 출구 입력과 학습 보행의 조건이 있어 전체 모델 이식을 필수로 삼지 않음 |

**적용 판단:** 모델이 상태와 목표를 읽고 행동을 조합하며 결과에 따라 수정하는 방향은 연구 근거가 있다. JEV 단독으로 새로운 실행 가능 행동을 생성한다고 보는 것은 API 기능과 맞지 않는다. 따라서 생성 모델은 계획 제안, JEV는 판단, Unity는 조건 검사와 실행을 맡기는 구조를 개발한다. 이 결합이 완전 랜덤 오픈월드의 목표를 얼마나 충족하는지는 객체 연결과 실제 전개를 측정해 판단한다.

## 2. 현재 구현과 변경할 부분

현재 JevClient는 Choice·Score 등의 응답 분포에서 난수로 선택한다. IncidentDirector는 세계 시드에서 사건 RNG를 분리하고, 코드에 있는 원인·전개 후보를 JEV로 평가한 뒤 적용 직전 재검사한다. NPC별 관측과 기억, 목적과 경로, 일부 로컬 복귀 동작도 있다. 따라서 난수나 캐시를 처음 도입한다고 설명하지 않는다. 현재의 사건 후보 목록을 전체 객체 상호작용의 완성으로 부르지도 않는다. 플레이어는 부품·도구를 직접 조작하고 현실 대응 조작99% 재현을 개발 목표로 둔다. 물리·조작은 입력과 실행기가 처리하며 모델은 세계·NPC 판단을 맡는다. 조작의 실제 상태 변화가 다음 계획으로 전달된다. 상세 범위는 [현실 조작 재현 계획](INTERACTION_FIDELITY.md)에 따른다.

개발할 부분은 **등록한 객체에서 가능한 행동의 조합을 제안하고 실제 세계 변화로 연결하는 과정**과 **상태가 바뀔 때 판단·계획을 갱신하는 비용 제어**다. 모델 호출 0은 목표에서 제외한다. 호출 없는 로컬 정책은 비교 조건으로만 둔다. 기존 세계와 FPS 기능을 활용하며 생성 모델과 Unity를 연결하는 어댑터·실행 계약은 구현 대상이다.

## 3. 모든 객체와 NPC의 상태를 유지한다

모든 맵 객체에 고정 ID, 상위 물리 객체 ID, 위치·층·구역, 종류·크기, 상태·관계와 가능한 행동을 등록한다. 부품 메시와 문·설비 같은 상위 객체를 함께 기록한다. 메시 분할 개수에 따라 고장·사고 기회가 늘어나지 않게 한다. 역할을 확인하지 못한 객체와 장식물도 위치·장애물 정보로 유지하며 이름만으로 원인을 부여하지 않는다.

세계 전체 상태와 NPC 개인 관측을 나눈다. NPC는 시야·거리·소리·경보·지시로 알게 된 정보, 기억과 목표를 사용한다. 숨은 위험을 세계 목록에서 바로 읽어 도망가지 않게 한다. 모델 요청에는 관련 상태 변화와 의존 객체를 검색해 전달한다. 나머지 객체도 세계에 유지하며 정보가 부족하면 추가 조회한다. 전체 객체를 등록한다는 요구를 매 호출에 모든 원시 메시를 전송한다는 요구로 바꾸지 않는다.

시각 자산 수, 등록된 물리 객체 수, 상태가 연결된 수, 실행 가능한 조작이 있는 수를 따로 센다. 전체 연결 목표의 진행 범위를 이 수와 미지원 객체 목록으로 확인한다.

## 4. 생성 → 판단 → 실행 → 결과 갱신

1. 세계 상태와 NPC의 관측·기억·목표에서 변화를 검토한다. 생성 모델은 실제 객체와 가능한 조작을 조합해 계획을 제안한다.
2. 제안을 객체 ID·행동·전제 조건·예상 결과·관찰할 종료 조건으로 구조화한다. 객체 연결이 없는 제안과 지원하지 않는 조작은 실행하지 않고 기록한다.
3. JEV는 후보의 상황 적합성과 선택·정도를 평가한다. 모델 분포는 실제 사고율로 해석하지 않는다. 물리·경로·상태 검사는 코드가 별도로 수행한다.
4. 유효한 계획을 시드 난수와 함께 선택하고 실행 직전 대상 존재·상태 버전·경로·상호 배제를 확인한다. Unity의 이동·물리·상호작용이 실제 상태를 바꾼다.
5. 결과와 실패를 기록하고 세계 상태·NPC 관측을 갱신한다. 플레이어와 다른 NPC의 개입이 전제 조건을 바꾸면 다음 계획도 바뀐다.

완성 사건 대본의 선택과, 실행 가능한 조작을 조합해 생기는 전개를 구분한다. 물리와 조작의 의미는 구현되어 있어야 한다. 모델이 제안했다는 이유로 지원하지 않는 효과를 세계의 사실로 만들지 않는다. 미지원 제안의 종류와 빈도를 행동 범위 확장의 근거로 남긴다. 새 조작의 구현은 별도 개발·검사를 거친다.

원자 상태 변화의 빈도·강도·반응 지연은 게임 설정이다. 조건별 발생률을 사용할 경우 단위·기회 수·상위 객체 단위를 고정한다. 발생 없음, 후보 없음, 재추출·폐기·실패도 기록한다. Scenic의 조건부 확률·공간 제약 [R18]은 검사 구조의 참고이며 완성 사건 목록이나 Unity 어댑터로 사용하지 않는다.

## 5. 계획 재사용과 호출 비용

캐시는 계획과 관련 객체 ID·상태 버전·전제 조건·경로·모델·프롬프트·실행기 버전을 함께 저장한다. 같은 조건에서는 재사용하고, 객체 이동·삭제·관계 변경·경로 차단·목표 변경·실행 실패가 의존 조건을 바꾸면 무효화한다. 단순히 문장이 비슷하다는 이유로 같은 계획을 적용하지 않는다.

호출은 새 목표, 미지원 상호작용, 행동 실패, 전제 조건의 변경 등으로 발생시킨다. 유사한 상태 변화는 묶고 NPC별 재판단 간격을 둔다. 요청·실제 토큰·동시 처리 상한과 기한은 파일럿에서 정해 본평가 전에 고정한다. 새 응답이 도착해도 대상·상태 버전이 바뀌면 폐기한다. 응답을 기다리는 동안 유효한 기존 이동·물리 실행을 계속하고, 즉각 위험 회피는 로컬 실행이 맡는다. API 중단과 예산 소진 때의 동작도 기록한다.

요청을 줄인 대가로 놓친 상태 변화, 잘못 재사용한 계획, 반복 행동과 도착 지연을 함께 측정한다. 공급사의 KV 캐시나 요금 할인을 가정하지 않는다. 계획 생성 모델과 JEV, 재시도·캐시 갱신·초기 계획 비용을 합산하고 로컬 CPU·메모리도 별도로 보고한다.

## 6. NPC 이동과 위험 반응

목표 선택, 경로 탐색, 국소 회피와 보행을 나눈다. NPC는 도달 가능한 목표와 개인 관측·기억에서 행동을 결정한다. 목표와 경로의 위험·혼잡·최근 방문을 반영하며 매 프레임 임의 좌표를 찍거나 고정 경로를 순환시키지 않는다.

위험을 인지한 NPC는 위치와 목표, 이용 가능한 경로에 맞게 회피·도주·안내 따르기 등에 반응한다. 모든 사건에서 모든 NPC가 도망가게 만들지 않는다. 사람의 반응 지연과 API 지연은 구분한다. 갈 수 있는 경로가 없으면 경로 없음으로 기록한다.

NavMesh를 경로 기반으로 두고 기존 국소 회피와 ORCA 또는 social force를 비교한다. 속도 결정자는 하나만 사용하며 NavMesh 기본 회피를 ORCA로 부르지 않는다. CalculatePath의 반환값뿐 아니라 완전 경로 여부를 검사한다. PeopleFlow의 주요 실험은 위험 가중치를 끈 조건이므로 본 게임의 위험 반응을 검증하는 근거로 사용하지 않는다. [R11–R14, R19]

## 7. 시드와 모델 응답의 기록

마스터 시드에서 사건·상태 변화·NPC 목표·반응의 난수 흐름을 고정 해시로 분리한다. 후보는 고정 ID 순으로 정렬하고 난수 알고리즘·버전, 틱, 설정과 공간·자산·경로 해시를 저장한다. 변동 가능한 런타임 문자열 해시를 영구 시드로 사용하지 않는다.

모델의 실제 요청·응답·해석된 버전, 계획과 캐시 상태, 적용·폐기 틱, 입력과 전이 순서를 저장한다. 재생할 때는 기록한 응답을 사용하고 새 모델 호출을 막는다. 시드만 같으면 같은 결과가 나온다고 약속하지 않는다. 다른 입력의 반복 플레이, 같은 입력의 재시뮬레이션, 기록 궤적 표시는 구분한다. [R15, R16]

## 8. 비교와 적용 일정

호출을 반복하는 모델 정책과 상태 변화 때 호출하며 계획을 재사용하는 정책을 비교한다. 로컬 정책은 기준선으로 둔다. JEV의 판단과 생성 모델 추가의 효과를 구분하기 위해 같은 후보를 주는 판단 시험과 후보 제안까지 포함한 통합 시험을 나눈다.

| 확인할 내용 | 측정 |
|---|---|
| 전체 객체 연결 | 시각 자산·물리 객체·상태·조작별 수와 미지원 범위 |
| 전개 | 객체·목표의 미사용 조합, 상태 변화 연쇄·행동 조합·위치의 다양성 |
| 타당성 | 독립 기준표의 적합성, 미지원 효과·조건 위반·실행 실패·발생 없음 |
| NPC | 목표 반복·도달 불가·접촉·정체, 위험 인지와 반응, 목표 완료 |
| 비용 | 생성 모델·JEV별 요청·실제 토큰·청구·p50/p95 지연·CPU·메모리 |
| 재생 | 첫 불일치 틱·상태·사건 순서·궤적, 빌드·장치·허용 오차 |

개발·튜닝용 자료와 본평가의 객체·목표 조합·시드·캐시를 분리한다. 동일 초기 상태의 시험과 행동에 따라 세계가 달라지는 통합 시험은 다른 질문으로 해석한다. 4주차 객체 연결, 5주차 생성·판단·계획 재사용·시드와 NPC·FPS·VR 통합, 6주차 평가·수정으로 진행한다. 연결한 객체와 기능, 미완료 범위를 주별로 확인한다.

참고문헌 R11–R29와 적용 범위는 [제안서](PROPOSAL.md), 시험 조건은 [평가 계획](EVALUATION_PROTOCOL.md), 원문 확인은 [출처 원장](SOURCE_LEDGER.md)에 정리했다.
