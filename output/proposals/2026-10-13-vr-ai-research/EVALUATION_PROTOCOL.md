# CHOOGuard 평가 계획

이 문서는 앞으로 수행할 시험의 조건과 판정 방법을 정한다. 실험 결과를 보고하는 문서는 아니다. 1주차에 입력 자료·객체·전이 검증 묶음과 장치를 정한 뒤 버전이 붙은 시험표를 고정한다. 파일럿과 본평가 자료를 나누고, 변경한 항목과 이유를 기록한다.

## 1. 평가 단위와 자료 분리

| 평가 | 독립 단위 | 반복 측정 | 분리 원칙 |
|---|---|---|---|
| 시점 보강·자산 제작 | 객체 또는 공간 구역 | 같은 대상의 시점·프레임·방법·실행 | 같은 영상·촬영 구간과 중복 사진은 같은 묶음에 둔다. |
| NPC 판단·사건 실행 | 객체·목표·초기 조건의 조합 | 같은 조건의 정책·시드·모델 호출 | 개발·평가 조합과 시드를 분리한다. 캐시와 프롬프트 조정에 평가 조합을 사용하지 않는다. |
| XR 사용성 | 참가자 | 과제·조건·재시도 | 같은 참가자의 여러 시도를 독립 참가자로 세지 않는다. 조건 순서를 교차 배정한다. |

자료 목록에는 출처 URL, 원본 식별자·해시, 장소·층, 촬영 시점, 영상 구간, 중복 묶음, 사용 조건, 학습·검증·평가 역할을 남긴다. 같은 건물의 비슷한 객체도 독립 장소 표본과 구분한다. 단일 구역 결과는 그 구역의 결과로 해석한다.

평가용 실제 사진과 치수는 카메라 정합, 생성모델의 조건 입력, 매개변수 조정, 결과 선택과 수동 보정에 사용하지 않는다. 정합은 제작 자료로만 수행한다. 평가 사진의 카메라는 제작 결과를 고정한 뒤 별도로 추정하며, 이를 다시 제작에 반영하지 않는다. 독립 형상·치수 기준이 없으면 형상 정확도 대신 미사용 뷰의 영상 품질만 보고한다.

## 2. 공간 제작 비교

| 시험 | 고정 조건 | 변경 조건 | 판정 |
|---|---|---|---|
| 시점 보강 효과 | 같은 객체, 실제 제작 사진·카메라, 평가 뷰, 후처리 기준 | 실제 입력만 / 3DGS 렌더 추가 / 생성 보강 추가 | 객체별 영상 오차와 독립 치수 오차의 차이. PSNR·SSIM·LPIPS는 영상 품질 지표이며 형상 정확도의 대용물이 아니다. |
| 정합 초기화 | 같은 사진·카메라 모델·기준점·후속 최적화 | COLMAP 기준선 / VGGT 초기화 | 등록 성공률·기준점 오차·실패와 시간. VGGT 출력을 정답으로 삼지 않는다. |
| 표면 복원 | 같은 정합 다중뷰·분할·대상·해상도 | NeuS / 2DGS 등 사전에 선택한 표면 방법 | 치수·표면·구멍·보정 시간. NeRF의 방사장 평가는 표면 평가와 분리한다. |
| 제작 경로 | 양쪽 경로가 처리할 수 있는 공통 객체와 평가 기준 | 다중뷰 복원 / Hunyuan3D 버전별 생성 | 입력 조건과 비용을 함께 공개한 제작 방식 비교. 입력이 다르면 알고리즘 우열을 주장하지 않는다. |

각 방법의 실제 입력 수·촬영 범위·해상도, 사전학습 모델·가중치·버전, GPU·메모리, 실행 시간, 출력 해상도·삼각형 수, 재질 크기, 실패·재시도, 수동 보정 시간과 담당자·도구 숙련도를 기록한다. 설치·최초 실행 시간과 대상별 실행 시간을 구분한다. 생성모델의 사전학습 비용을 이 프로젝트에서 측정한 비용으로 혼동하지 않는다.

방법별 입력·시간·수작업 상한과 결과 선택 규칙을 평가 전에 고정한다. 공통 예산 시험과 각 도구의 권장 설정 시험은 따로 보고한다. 기준을 넘긴 경우 중단·초과·실패로 남기며 성공 사례만 선택하지 않는다. 생성 뒷면과 가려진 접합부는 독립 자료가 없으면 미확인으로 표시한다. Hunyuan3D 2.1과 Omni의 입력·기능·가중치·라이선스는 버전별로 기록한다. [R4, R5, R7–R10]

파일럿은 1층의 유리 양개문 객체 한 개를 우선 후보로 삼는다. 1주차에 사진 중첩과 사용 조건을 확인해 대상 ID·촬영 구간·실제 입력·평가 자료 목록을 고정한다. 조건을 충족하지 못하면 다른 공통 객체로 바꾸고 이유를 남긴다. 이 한 객체의 결과로 역 전체의 성능을 추정하지 않는다.

생성·복원 외에 기존 자산 재사용과 Blender 수작업을 제작 대안으로 포함한다. 준비·추가 제약 제작·재시도·보정·충돌·LOD·검수까지 같은 시간 경계로 기록한다. 기존 자산은 원본 라이선스와 적용 범위를 남긴다. 도면을 배치에 썼다면 같은 도면과의 일치는 ‘도면 일치도’로 부르며, 독립 실측 정확도로 부르지 않는다.

## 3. 생성·판단 모델과 계획 재사용 비교

목표는 모든 오브젝트·NPC의 상호작용에서 전개를 만들면서 반복 호출 비용을 줄이는 것이다. 외부 모델 호출 0은 목표가 아니다. 현재 코드에도 모델 분포의 난수 추출과 캐시가 있으므로 새 난수 도입이나 캐시 유무만의 효과로 해석하지 않는다. 생성 모델의 계획 제안, JEV 판단, 호출 주기와 재사용의 효과를 나눠 비교한다.

| 시험 | 고정 조건 | 비교 조건·해석 |
|---|---|---|
| 판단 단독 | 같은 상태·관측·허용 후보·실행 계층 | 로컬 정책 / JEV. 같은 후보 안의 판단 차이 |
| 제안·판단 | 같은 상태·객체·목표·실행 기능·총 시간·토큰 예산 | 기존 후보+JEV / 생성 계획+JEV. 후보 범위를 포함한 전체 차이 |
| 비용 제어 | 같은 생성·판단 모델·프롬프트·세계·입력·실행 예산 | 고정 주기 호출 / 상태 변화 호출+계획 재사용. 같은 모델의 호출·재사용 정책 차이 |
| 통합 | 같은 빌드·초기 세계·플레이어 입력 절차·기한·비용 상한 | 로컬 / JEV / 생성+JEV / 생성+JEV+계획 재사용. 행동이 바꾸는 세계를 포함한 차이 |

현재 코드 정책을 기준선으로 보존하고 실제 호출·캐시 동작을 기록한다. 모델 추가와 캐시 변경을 동시에 바꾼 결과만으로 각 효과를 주장하지 않는다. 같은 후보 시험에서는 생성의 확장을 평가할 수 없으며, 생성 후보가 다른 시험은 판단 모델만의 우열로 부르지 않는다.

**자료와 캐시 분리.** 객체·목표·관계 조합을 기준으로 개발·파일럿·평가를 나눈다. 평가 조합·실행 결과는 프롬프트·규칙·검색·계획 선택·캐시 작성·결과 선별에 사용하지 않는다. 캐시의 초기 버전과 내용·해시를 저장한다. 대응 비교의 각 실행 시작 시 같은 초기 캐시를 복사해 초기화한다. 실행 중 새 계획 삽입·의존 조건 무효화는 허용하되 실행 사이로 전달하지 않는다. 실행 간 누적 학습은 별도 조건이며 평가 데이터로 다음 비교 실행의 초기 캐시를 개선하지 않는다. 기본 시험은 초기 캐시를 고정하고, 평가 중 학습·갱신을 허용하는 시험은 별도 조건으로 둔다. 새 조합을 일반화했다고 말하려면 그 조합을 개발에서 제외했는지 확인한다.

**동일 상태와 통합 실행.** 판단·제안 단독 시험은 같은 상태 스냅숏을 제공한다. NPC 단독 실행은 외부 사건 일정과 이동 실행을 고정한다. 통합 시험은 같은 초기 세계와 입력을 사용하되 정책 때문에 생긴 상태 차이를 결과로 남긴다. 서로 다른 정책에 같은 시드를 넣었다고 같은 사건이 발생했다고 보지 않는다. 사건·이동·NPC별 난수 흐름을 나눠 정책의 난수 소비가 외부 조건을 바꾸지 않게 한다.

**전개와 타당성.** 전개 다양성은 객체·행동·전제 상태·결과의 ID와 상태 변화 연쇄에서 계산한다. 문구만 다른 계획을 새 사건으로 세지 않는다. 유형·위치·행동 조합의 수와 빈도, 연쇄 길이·반복, 발생 없음·유효 기회 수를 보고한다. 고정 실행 시간과 같은 예산에서 비교하고 유효한 전개와 조건 위반 전개를 구분한다. 새 계획의 비율이 높다는 이유만으로 현실적이라고 판단하지 않는다.

대상 존재·관측·상태·경로·상호 배제·지원 조작을 코드 검사로 확인한다. 모델 이름을 가린 평가자2명이 독립 기준표로 상황과 행동을 판정한다. 복수 행동을 허용하고 정보가 부족하면 보류한다. 합의 전 판정·불일치·보류 비율과 해결 이유를 남긴다. JEV의 신뢰도·분포나 생성 모델의 자기 평가는 정답으로 사용하지 않는다. 현장 대응 적절성은 도메인 검토가 있어야 주장한다.

**전체 객체 범위.** 시각 메시·상위 물리 객체·상태 연결·행동 연결의 수와 미지원 객체 목록을 보고한다. 부품 분할, 삭제 대상, 조건 충돌, 관측 누락, 후보 없음, 재추출 상한을 검사한다. NPC에는 목표 반복·도달 불가·정체·접촉, 위험 인지·반응 시점과 경로 위험 구간 통과를 포함한다.

**비용과 실패.** 생성 모델과 JEV 각각의 요청·실제 입력/출력 토큰, 캐시 작성·검토·초기화·재시도, 청구 정보와 총 비용을 기록한다. 정보가 없으면 미제공으로 표시한다. 로컬 CPU·메모리와 상태 입력부터 선택·실행까지의 지연 p50/p95, 대기 시간·실패·폐기·예산 소진을 함께 보고한다. 호출 없는 정책의 API 지연은 해당 없음으로 표기한다. 연구나 공급사의 절감률을 이 게임의 결과로 쓰지 않는다.

요청·토큰·동시 처리·기한·재시도 상한, 오래된 응답의 폐기와 API 중단 때의 동작은 본평가 전에 고정한다. 모델 이름·실제 반환 버전·프롬프트·후보·계획·캐시 해시·응답·적용 틱을 저장한다. jev-latest만으로 버전 고정이라고 보지 않는다. 캐시가 오래되어 놓친 변화와 잘못 재사용한 계획, 유효성·완료의 저하를 비용 절감과 함께 비교한다. [R24–R29]

| 주 지표 | 계산·단위 | 판정·예외 |
|---|---|---|
| 공간 치수 오차 | 대상별 측정 차이 절댓값, cm | 제작에 쓰지 않은 실측·기준점. 기준이 없으면 미평가 |
| 행동 적합률 | 허용 행동 집합에 속한 선택 / 판정 가능한 결정 | 독립 평가자2명. 보류·불일치·응답 실패도 별도 보고 |
| 유효 전개율 | 적용 직전 검사와 독립 기준을 통과한 제안 / 전체 제안 | 미지원·기각·실패를 숨기지 않음. 기회 수·고정 시간당 수 동시 보고 |
| 과제 완료율 | 사전 목표를 완료한 참가자 / 전체 참가자 | 중단·시간 초과 포함 |

객체·목표 조합별 차이와 신뢰구간을 계산한다. 반복 시드·모델 호출·NPC·프레임은 같은 묶음 안의 반복이다. 비용 감소와 행동 적합성의 허용 차이, 실행 기한과 실용 차이 기준은 파일럿 후 본평가 전에 정한다. 표본이 작으면 탐색 결과로 보고한다.

## 4. 재생 검사

현재 코드의 시드·로그와 앞으로 만들 전체 재생 기능을 구분한다. 재생 묶음에는 빌드·자산·NavMesh·설정 해시, Unity·패키지·플랫폼 버전, 난수 생성기와 흐름별 시드, 초기 상태, 고정 시간 간격, 틱별 입력, 실제 모델 응답과 적용 틱, 사건·처리 순서가 필요하다. 재생 중에는 외부 모델을 다시 호출하지 않는다.

5주차의 구현 목표는 저장한 입력·응답을 틱에 맞춰 적용하는 재시뮬레이션이다. 관측 ID·요청 ID·응답 적용 틱·제한 시간 판정도 기록한다. 궤적을 그대로 표시하는 재생은 확인 도구로 구분하고 필수 목표의 성공으로 세지 않는다. 전체 재시뮬레이션이 완료되지 않으면 구현 범위와 첫 차이 지점을 결과로 보고한다.

같은 빌드·장치에서 같은 기록을 재생한다. 사건 식별자·순서·상태 전이는 정확히 일치해야 한다. 위치는 틱별 궤적으로 비교하며 허용 오차는 첫 구현 시험 전에 정한다. 수치 판정의 초기 기준은 위치 최대 오차 1 cm이며, 충돌·통행 판정이 달라지면 오차 크기와 관계없이 실패다. 기준 변경은 평가 전에 이유와 버전을 남긴다. 장치 간 재생은 별도 시험이며 동일 결과를 미리 보장하지 않는다.

처음 어긋난 틱과 상태·입력·응답을 보고한다. 통과한 빌드·장치·기록 수와 실패 수를 모두 적는다. 시드만 같고 사용자 입력이 다른 시험은 재생 일치 시험과 구분한다. [R15]

## 5. XR 사용성·성능

기본 장치 후보는 Meta Quest 3 독립 실행형이며 Android·OpenXR 빌드를 계획한다. 보유·대여 가능 여부는 아직 확인하지 않았다. 1주차에 개발 담당자가 장치 접근과 Android 빌드·머리 및 컨트롤러 추적을 확인한다. 접근 또는 빌드가 실패하면 시뮬레이터 검증과 기존 데스크톱 사건 실행을 제출 범위로 표시하고, HMD 조작·불편감·입체 표시 검증은 미완료로 남긴다. 장치 변경 시 실행 설정과 성능 예산을 다시 고정한다. [Unity의 Meta Quest 개발 안내](https://docs.unity3d.com/6000.0/Documentation/Manual/xr-meta-quest-develop.html)를 구현 경로의 근거로 사용한다.

1주차에 지원 HMD·컨트롤러·연결 방식·주사율을 정한다. 실제 주사율에 맞춰 CPU/GPU 프레임 시간 예산을 고정한다. 예를 들어 72 Hz는 13.9 ms, 90 Hz는 11.1 ms다. 예산 통과율과 상위 분위수, 재투영·프레임 손실, 추적 상실을 실제 장치에서 기록한다. 데스크톱 성능을 HMD 성능으로 대신하지 않는다.

대표 과제는 단서 찾기, 대상 선택, 무전·안내, 종료와 재시작이다. 완료·시간·오류·도움 요청과 UI를 놓친 횟수, 과제 전후 불편감을 참가자별로 기록한다. 조작 연습을 먼저 제공하고 조건 순서를 교차 배정한다. 앉기·서기, 이동·회전 옵션, 손 선택과 패널 거리·크기를 조절할 수 있게 한다. 입력 시뮬레이터와 실제 HMD 결과를 따로 보고한다.

| 현장 행동 과제 | 입력·대상 | 상태·피드백·기록 |
|---|---|---|
| 이동·관찰 | 머리/시야·이동 입력, 실제 대상 | 인지한 정보와 선택 대상, 도달·접촉 오류 |
| 도구 사용 | 집기·겨냥·사용·취소 | 도구와 대상의 실제 상태, 사용·취소 시점 |
| 설비 조작 | 등록된 설비의 현재 작동 조건 | 허용·거부 이유와 객체 상태 변화 |
| 무전·지원 | 관찰 정보·대상·요청 | 송수신·기관 행동·후속 전개 연결 |

과제는 현재 구현된 오브젝트와 행동에서 고정한 시험 묶음이며 게임 전체를 하나의 고정 사건 대본으로 바꾸지 않는다.

파일럿은 조작 연습 3분과 사전에 고정한 현장 행동 과제 5분 이내, 과제 후 사용성 응답 순으로 계획한다. 이는 평가 진행이며 별도 의무 복기 화면을 제품에 추가하는 요구가 아니다. 이동은 텔레포트와 단계 회전을 기본으로 고정하고 조건마다 기록한다. 과제 전·후 SSQ의 한국어 문항을 같은 방식으로 제시하며, 번역·응답 방식을 평가 전에 검토한다. 즉시 중단 요청, 추적 상실 또는 불편감 악화 시 종료하고 노출 시간·이유를 남긴다. 시간·오류·도움 요청은 실행 로그와 관찰표로 함께 기록한다. 수치는 노출 범위에 대한 설계값이며 문헌이 보장한 안전 한계가 아니다.

공간 UI 파일럿은 패널 거리 1 m·2 m와 선택 영역 너비 4 cm·8 cm의 2×2 조건을 계획한다. 조작자와 UI 높이·입력 장치·노출 문장은 고정한다. 실제 등록 객체·현재 상태를 설명하는 동일 길이의 한국어 문장의 읽기 정확도, 대상 선택 시간·실수·재시도·도움 요청을 각각 기록한다. 실제 HMD에서 가독성 또는 도달성이 맞지 않으면 파일럿 안에서 조정하고 본평가 전에 값을 고정한다. 거리·크기는 검토할 설계 조건이며 한국어 UI의 보편 기준이 아니다.

참가자가 중단을 요청하거나 불편감이 커지면 즉시 종료한다. 중단·추적 실패·미완료를 삭제하지 않는다. 화면의 글자 크기와 색 대비는 실제 HMD 거리에서 확인한다. 이 파일럿의 결론은 사용성·성능·실패 원인까지다. 실제 대응 역량의 향상을 주장하려면 사전·사후, 비교 조건, 새로운 사건으로의 전이와 유지 검사를 별도로 설계한다.

회고에서는 ‘어떤 단서를 보았는가’, ‘왜 그 대상을 선택했는가’, ‘다시 실행하면 무엇을 바꾸겠는가’를 묻는다. 정해진 단서·행동 기록과 맞는지 두 평가자가 확인하고 불일치를 보존한다. HMD가 데스크톱보다 유리하다는 비교 효과는 이번 VR 단독 파일럿의 결론에 포함하지 않는다. 그 효과를 시험하려면 같은 내용의 데스크톱·HMD 과제와 순서 교차 배정이 필요하다.

## 6. 표본·통계·공개

주 지표는 공간 제작의 독립 치수 오차, 모델 정책의 행동 적합률·유효 전개율, XR의 과제 완료율로 정한다. 독립 치수 기준이 없는 대상은 공간 정확도 분석에서 분리하고 영상 품질 분석에만 넣는다. 나머지 지표는 보조·탐색 지표로 표시한다. 사건·객체·참가자 수는 아직 정하지 않았으며 파일럿의 변동과 필요한 신뢰구간 폭으로 정한다. 표본이 작아 정밀도가 부족하면 탐색 결과로 보고한다.

같은 독립 단위 안에서 방법별 차이를 계산한다. 프레임·시도·NPC를 독립 표본처럼 늘리지 않고 객체·시나리오·참가자 단위의 묶음을 보존해 부트스트랩 신뢰구간을 계산한다. 반복 호출·시드 간 변동은 묶음 안에서 별도로 보고한다. 개별 차이, 효과 크기와 95% 신뢰구간, 표본 수·실패 수·분포를 함께 제시한다. 유의성 검정을 사용할 경우 검정과 가정을 먼저 정하고, 같은 결론을 위한 여러 비교에는 Holm 보정을 적용한다. 신뢰구간의 겹침만으로 유의성을 판정하지 않는다. 독립 단위가 너무 적으면 부트스트랩 구간도 안정적이지 않을 수 있으므로 사례별 차이를 기술하고 확정적 검정을 보류한다. [M1]

분석 전 제외 기준과 결측·실패 처리, 시험 횟수·중단 규칙을 고정한다. 연결 실패와 생성 실패는 성능 결과에 포함한다. 평균 하나나 성공한 장면만으로 결론을 내리지 않는다. 평가표·버전·분할 목록·비식별 실행 로그·분석 절차를 함께 남긴다. 공개할 수 없는 원본은 식별자와 사용 조건, 재현에 필요한 대체 절차를 제공한다.

### 평가 방법의 연구 근거

- **M1.** Agarwal et al. [Deep Reinforcement Learning at the Edge of the Statistical Precipice](https://proceedings.neurips.cc/paper/2021/hash/f514cec81cb148559cf475e7426eed5e-Abstract.html). NeurIPS, 2021. 적은 반복과 불확실성 해석의 근거로 사용한다. 강화학습 벤치마크의 결과를 본 게임의 효과로 옮기지 않는다.
- **M3.** Munje et al. [SocialNav-SUB](https://proceedings.mlr.press/v305/munje25a.html). CoRL, 2025. 공통 입력·사람의 판단 기준·규칙 비교를 설계할 때 참고한다. 로봇의 사회적 장면 이해 평가이며 JEV나 역무 대응의 검증 자료가 아니다.
- R1–R29의 서지와 적용 범위는 제안서 참고문헌에 따른다.

- **VR01.** Dylong & Nickel. [VR 이동 방식·작업부하 평가](https://doi.org/10.1007/s10055-025-01290-2). Virtual Reality 30:33, 2026 (온라인 2025-12-24). 완료·불편감·작업부하를 함께 측정하는 설계 근거이며 이동 방식의 보편 우열을 주장하지 않는다.
- **VR02.** Kim & Xiong. [TouchView](https://doi.org/10.3390/s24227202). Sensors 24(22):7202, 2024. 거리·선택 영역 시험을 설계할 때 참고한다. 자유손 평면 UI 연구를 컨트롤러·한국어 읽기의 검증으로 사용하지 않는다.
- **VR03.** Stefan et al. [VR 전기 안전 교육 평가](https://doi.org/10.1016/j.jsr.2024.06.002). Journal of Safety Research 90:48–61, 2024. 반응·사용성과 사전·사후·유지 측정을 구분하는 근거이며 본 게임의 학습 효과가 아니다.

## 7. 현실 대응 조작 재현

현실 대응 조작99% 재현은 개발 목표이며 측정 결과가 아니다. 평가 전에 장비·부품·도구·움직임·순서·작동 조건·결과의 필수 항목과 출처를 고정한다. 요구됐지만 확인하지 못한 항목도 미확인·미통과로 남긴다. 부품 수나 프레임 수로 분모를 늘리지 않는다. 항목 일치율과 연속 운동·시간·힘·감각의 오차를 분리한다. 필수 조작·조건의 실패를 외형 검사 수로 상쇄하지 않는다. 전체99% 판정의 범위와 결합 규칙이 고정되지 않았으면 달성으로 보고하지 않는다.

정상 조작, 순서 변경, 도구 호환 불일치, 잠금·접촉 실패·부분 완료에서 상태와 결과를 확인한다. 조작 재현과 실제 대응 전이는 별개다. [현실 조작 재현 계획](INTERACTION_FIDELITY.md)의 범위·분모·미확인 처리와 독립 자료 대조를 따른다. 조작 재현 지표는 별도 요구사항 검증 지표로 보고하며 원래의 공간·모델·XR 주 지표와 섞어 단일 성능 수치를 만들지 않는다.
