# 현실 대응 조작 재현 계획

대상 공간은 한국철도공사(코레일)의 부산역과 주변 지역이다. 요구사항은 마이 썸머 카처럼 오브젝트·부품·도구를 직접 다루는 FPS 시뮬레이터이며, **현실 대응 조작의99% 재현**을 목표로 한다. 부품의 구조와 움직임, 도구 사용, 조작 순서와 작동 조건, 실패 결과의 복잡성을 유지한다. 99%는 개발 요구사항이며 측정 결과가 아니다.

## 현실 자료와 객체 연결

현장 사진·영상과 장비 매뉴얼, 실제 조작 관찰을 장비 모델·위치·부품 ID에 연결한다. 자료가 없는 내부 구조·치수·작동 조건을 생성 모델의 추정만으로 확정하지 않는다. 같은 외형의 장비라도 모델과 작동 방식이 다른지 확인한다. 각 조작 항목에 출처·관측 시점·확인 범위·미확인 사항을 남긴다.

| 재현 항목 | 제작·연결 | 확인할 근거 |
|---|---|---|
| 부품 구조 | 몸체·덮개·손잡이·스위치·결합 부품을 구분한 객체 | 같은 장비의 사진·영상·도면·매뉴얼 |
| 움직임 | 회전축·이동 방향·범위·걸림·접촉·잠금 | 조작 영상·실측·제조사 사양 |
| 도구 | 호환 대상·접촉점·결합 방향과 도구 상태 | 같은 장비의 실제 사용과 매뉴얼 |
| 순서·조건 | 선행 조작·현재 상태·연결·잠금이 다음 동작에 미치는 영향 | 절차와 실제 작동의 대조 |
| 결과·실패 | 입력·상태 변화·작동/비작동·피드백 | 정상·실패 조건의 관측과 기록 |
| 감각·시간 | 조작 시간·소리·진동·저항·힘 | 측정 가능 항목과 장치가 재현하는 범위 |

## 제작과 FPS·VR 조작

복원·생성한 외형을 Blender에서 부품으로 나누고 원점·축·단위·결합 위치를 맞춘다. Unity에서 부품별 Collider·Rigidbody와 HingeJoint·ConfigurableJoint를 연결해 움직이는 축과 범위를 제한한다. 상태와 도구, 접촉과 조작 순서에 따라 결과가 바뀌게 한다. 단일 성공 버튼으로 복잡한 조작을 완료시키는 방식으로 대체하지 않는다.

데스크톱에서는1인칭 시야와 입력으로 대상 부품을 잡고 움직이며, VR에서는 머리·양손 추적과 잡기를 같은 조작 상태에 연결한다. 자동 보정·결합 허용 범위와 보조 입력은 명시하고 실제 조건과 차이를 기록한다. XR Interaction Toolkit은 잡기와 입력의 기반이며 장비의 조작·관절·실패를 자동으로 제공하지 않는다.

플레이어의 움직임과 접촉은 입력·물리 실행이 처리한다. 생성 모델과 JEV는 상황과NPC의 목표·행동 판단에 사용한다. 입력 한 번이나 물리 프레임마다 모델 호출을 요구하지 않는다. 조작이 바꾼 객체 상태는 세계 목록과 다음 상황 판단으로 전달한다.

## 99%의 확인 방법

평가 전에 대상 장비·부품·도구·조작·조건·결과의 **전체 필수 항목과 독립 출처**를 고정한다. 메시 수·영상 프레임 수·쉬운 외형 검사 수로 분모를 늘리지 않는다. 요구됐지만 자료가 없거나 구현하지 못한 항목은 미확인·미통과로 남긴다. 평가 후 항목을 빼거나 바꿔서 비율을 높이지 않는다.

외형·치수, 조작 움직임·도구, 순서·조건·결과, 시간·힘·피드백은 **각각** 보고한다. 정해진 항목의 일치율은 `통과한 필수 항목 / 사전에 고정한 전체 필수 항목`으로 계산하되 이것만으로 연속 운동·힘·체감 전체가99% 같다고 부르지 않는다. 실제 측정의 오차·단위·허용 범위를 항목마다 정하고 원자료와 차이를 제시한다. 장비 작동을 좌우하는 필수 조건과 조작은 모두 통과해야 하며 다수의 외형 항목으로 실패를 상쇄하지 않는다.

99%라는 전체 재현 판정을 사용할 수 있는 범위와 결합 규칙은 실제 자료와 담당자의 검토로 평가 전에 정한다. 고정되지 않은 상태에서는 개발 목표로만 표시한다. 힘·저항을 재현하지 못하는 입력 장치와 미확인 구조는 한계로 남긴다. 조작 재현율과 사용성, 교육·현실 대응 전이는 서로 다른 결과다.

개발자가 만들 때 사용한 사진·영상·매뉴얼과, 완성 후 대조하는 독립 자료·조작 관찰을 구분한다. 평가자2명이 장비·부품별로 판정하고 불일치와 근거를 보존한다. 정상 조작, 순서 변경, 맞지 않는 도구, 잠긴 부품, 접촉 실패와 부분 완료를 포함한다. 시도·프레임을 독립 장비 표본으로 세지 않는다.

## 근거와 범위

- 사용자 지정 참고게임 [My Summer Car 공식 제품 페이지](https://store.steampowered.com/app/516750/My_Summer_Car/): 부품 조립과 운전·엔진 시뮬레이션을 제품 특징으로 제시한다. 조작 수준의 방향이며 이 프로젝트의 교육 효과·현장 조작99%를 증명하는 학술자료가 아니다.
- [Unity HingeJoint](https://docs.unity3d.com/6000.0/Documentation/Manual/class-HingeJoint.html), [ConfigurableJoint](https://docs.unity3d.com/6000.0/Documentation/Manual/class-ConfigurableJoint.html): 관절 축·범위·구동의 구현 근거. 현실 장비의 수치를 제공하지 않는다.
- [XR Interaction Toolkit3.3](https://docs.unity3d.com/Packages/com.unity.xr.interaction.toolkit@3.3/manual/index.html), [XR Grab Interactable](https://docs.unity3d.com/Packages/com.unity.xr.interaction.toolkit@3.3/manual/xr-grab-interactable.html): Unity6 입력·잡기·피드백의 기반. 실제 HMD 구현과 촉각 재현은 별도 확인한다.
- [OpenHOI, NeurIPS2025](https://proceedings.neurips.cc/paper_files/paper/2025/hash/f376f5dff6f6ec6364aea7a46ab49574-Abstract-Conference.html): 객체 부위와 손의 상호작용을 연결하는 연구 참고. NPC 손동작 합성 후보이며 플레이어의 직접 조작이나 장비 절차·현실99%의 검증을 대신하지 않는다. 전체 모델 이식은 필수로 두지 않는다.
