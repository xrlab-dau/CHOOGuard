# Product Brief: choo guard AI-native 개발 파이프라인

- 작성일: 2026-09-06.
- 방법: BMAD Method의 product brief 구조를 수동 적용한 에이전트 보조 초안. BMAD CLI·스킬 런타임의 headless 실행 완료 영수증은 없다.
- 권위: 요구사항 기준선 v1.1, 파이프라인 v1.2, 백로그 v1.3. 본 문서는 승인 기준선을 변경하지 않는다.
- 자료 등급: PUBLIC_SYNTHETIC. 개인 계정·실제 촬영·회신·호스트 정보를 담지 않는다.
- 상태: 1차 검토 changes_required 반영 중. 독립 재검토·실행 승인 미완료.

## 목표와 사용자

팀의 분리된 Pi 세션에서 변경 단위 명세를 구현하고, 다른 제공자의 읽기 전용 검토와 사람 승인 뒤에만 develop에 병합하는 개발 제어면을 준비한다.

| 역할 | 필요한 것 | 실패 비용 |
|---|---|---|
| PM·Core | 요구·명세·구현·검증·승인 사이 ID와 hash 추적 | 범위 변경·미승인 병합·잘못된 완료 판정 |
| XR·Capture | 학교 PC·HMD 검증과 촬영 승인 조건 분리 | 승인 전 촬영·실물 검증 지연 |
| Map Pipeline | 합성 맵부터 시작하는 내부 변환과 가중치 고지 | 외부 유출·제한 라이선스 도입 |
| Flat Art·UI | Desktop·VR의 동일 훈련 상태 | 모드별 기능 불일치 |
| Scenario·Verification | 임시 직무 데이터와 설명형 피드백 검증 | 미검수 절차의 권위화 |

## 문제와 접근

- 승인 기준선은 있으나 실제 제공자·실행 경계·불변 검토 대상·정제 판정을 연결하는 구현은 미완료다.
- 저장소에는 v3 문서가 확인되지 않았다. 외부 v3 내용이나 OpenSpec 설치 이력을 현재 파일만으로 증명하지 않는다.
- 발견은 BMAD 방법, 명세 품질은 Spec Kit의 명확성·완전성·일관성 기준, 기술 조사는 주장·근거·한계 구조를 따른다. 수동 적용과 도구 실행 영수증은 구분한다.
- Pi 선언 그래프·프로파일은 후보 설정이다. reviewer가 읽기 도구만 선언해도 OS 파일·네트워크 경계가 생기지 않으므로 M1-02·M1-07 시험이 필요하다.
- 게이트를 JSON 스키마·고정 test ID·실제 diff·manifest·승인 기록으로 연결한다. 현 YAML의 오류 후 나머지 승인과 자유 셸 입력은 수정·시험 전 운영 금지다.

## M0·M1 완료 목표

1. 작성과 다른 제공자의 명세·적대적·보안 필수 관점을 모두 검증하고, 미수신·오류·대상 변경은 cannot_proceed로 유지한다.
2. 순수 리뷰어는 불변 입력만 읽고 verifier는 별도 생성·빌드·임시 로그만 쓴다. 보호·자격·자료·네트워크 경계를 합성 fixture로 시험한다.
3. 수정·반박 뒤에는 새 독립 검토가 필요하다. 총 3라운드 목표와 현재 초기 리뷰+최대 3회 재검토 구현의 불일치를 승인된 수정으로 해결한다.
4. 모든 실행 주체의 승인 목적지·포트·프로토콜·프록시·목적·자료등급을 고정한다. 학교 PC 모델·Exa·로그인은 기본 비허용이다.
5. 정책·명세·검사 결과·판정의 불변 hash와 정제된 append-only 증거가 연결된다. PM과 팀의 별도 승인 없이 완료 판정을 생성하지 않는다.

## 대안·위험·비목표

도구별 대안·위협·비용은 ADR 0002, 독립 검토는 ADR 0003, 조사는 ADR 0004, 학교 PC는 ADR 0005에 둔다. 리뷰 제공자 장애 시 임의 모델로 fallback하지 않고 미완료로 남긴다. 조사 하네스 장애 시 직접 curl을 실행 통제 우회 대안으로 제공하지 않는다.

Unity 프로젝트·XR 구현·실제 촬영·KORAIL 회신 처리는 이번 계획 초안의 완료 범위가 아니다. 실제 Researcher 조사, 공급망·라이선스 승인, 학교 PC 실행과 독립 재검토는 아직 완료되지 않았다.
