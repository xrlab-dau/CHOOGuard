# choo guard 요구사항 발견 v1 (BMAD Method)

- 작성일: 2026-09-06
- 작성: PM 요청에 따른 Claude Code 보조 초안. 사람 검토·승인 완료 기록이 아니다.
- 방법: BMAD Method 6.12.0의 발견·계획 구조를 수동 적용했다. 별도 headless 런타임 실행 영수증은 없다. 대화형 인터뷰 대신 요구사항 기준선 §1의 사용자 역질의 답변을 근거로 소크라테스식 재검증을 수행했다.
- 입력: 요구사항 기준선 v1.1, 플랫폼 아키텍처 v4.2, AI-native 파이프라인 v1.2, 실행 백로그 v1.3, `product-brief-agentic-pipeline-v1.md`
- 산출: 확정 요구 재확인, 가정(A-nn), 개발 환경 미결정(D-01~D-09), 비목표, 용어, Spec Kit 인계 목록
- 권위: 요구사항 권위는 기준선 v1.1이다. 본 문서는 발견 기록이며 기준선을 바꾸지 않는다. 충돌을 발견하면 기준선 §8 변경 규칙에 따라 별도 PR로 제안한다.
- 자료 등급: PUBLIC_SYNTHETIC. 실제 역사·촬영·KORAIL 회신 내용을 담지 않는다.

## 6. 비목표

기준선 §4 비목표 전부를 유지하며, 개발 환경 비목표를 추가한다.

- 로컬(계획 머신)에 Unity·unity-mcp를 설치하지 않는다.
- 에이전트가 GitHub 이슈·PR을 자동 생성하지 않는다.
- 에이전트가 main·develop에 직접 push하지 않는다.
- 사람 승인 없는 병합·삭제·권한 변경을 자동화하지 않는다.
- 실제 역사 촬영물·KORAIL 자료를 외부 모델·MCP·검색 API에 보내지 않는다.

## 7. 용어

| 용어 | 정의 |
|---|---|
| PUBLIC_SYNTHETIC / TEAM_INTERNAL / KORAIL_RESTRICTED | 파이프라인 §6 자료 등급. 외부 모델 전송은 PUBLIC_SYNTHETIC만 허용 |
| 변경 단위(Work Unit) | 백로그 항목 1개(M0-00 등)에 대응하는 Spec Kit 명세와 브랜치·PR의 단위 |
| 독립 검토 | 작성 에이전트와 다른 제공자·모델이 읽기 전용 도구로 수행하는 검토 |
| 그래프 워크플로 | `.pi/workflows/*.yaml`로 정의한 병렬 검토·수정 루프 (pi-agents) |
