# 컨텍스트 그래프의 결정 출처

이 문서는 대화에서 사용자가 명시한 프로젝트 방향을 팀이 재사용할 수 있도록 요약한다. 명령 실행 결과나 현장 수용 증거가 아니며, 최신 사용자 지시와 프로젝트 AGENTS.md가 우선한다. 그래프의 상태만 바꿔 구현 또는 검증을 완료 처리하지 않는다.

## 2026-09-07 · 현재 외형 방향

사용자는 flat 스타일을 제거하고 공개된 역사 레퍼런스를 참고하여 Blender에서 사실적인 역사 모델을 제작하도록 요청했다. 사실적인 재질·형상 방향은 승인된 목표이며, 새 모델의 제작·통합·검증 완료를 의미하지 않는다. 기존 flat 규칙은 이 외형 범위에서 폐기되었다. 실제 시설 자료가 없는 부분은 합성·미검증으로 유지한다.

## 2026-09-07 · 지속되는 시뮬레이션 방향

평상시 NPC와 설비가 운영되는 공간에서 예상하지 못한 사건을 발견하고, 조건에 맞게 대응한 뒤 같은 세계가 복구되어 다음 사건으로 이어진다. 사건 선택 메뉴나 정답 순서가 기본 경험이 아니다. Desktop을 먼저 구현하고 VR은 같은 공간 Anchor와 행동 의미를 사용한다. 동일한 대피자에게 감정·표정·직무 대행을 추가하지 않는다.

## 2026-09-07 · 프로젝트 컨텍스트의 범위

사용자는 로컬·학교 PC·팀원·서브에이전트 사이에서 사용할 수 있는 Git 기반 프로젝트 컨텍스트 그래프를 요청했다. 이 그래프는 출처·현재성·폐기된 결정을 구분하는 탐색 자료다. 개인 전역 메모리, 계정 정보, 원문 기밀 자료, 재사용 가능한 게시 승인이나 실행 권한을 저장하지 않는다.

## 폐기된 외형 결정

앞선 2026-09-07 지시는 단색·무광·면 단위 음영의 flat 스타일이었다. 당시 코드와 시험 기록은 그 범위의 역사적 자료로 남는다. 현재 작업 지시로 재사용하지 않는다. 상시 운영·직접 인솔·공통 역할 계약 등의 별도 결정은 flat 스타일 변경만으로 폐기되지 않는다.

## 2026-09-07 · 오브젝트별 재현 기준

사용자는 실제 시설 재현이 제대로 진행되는지 점검하고, 시뮬레이션에 사용하는 모든 오브젝트를 Pinterest 또는 웹에서 찾은 개별 원본 이미지에 근거해 Blender로 상세 제작하도록 요구했다. 전체 역사 사진 몇 장이나 FBX 개수만으로 충족을 선언하지 않는다. 원본에서 관찰한 형태, 제조사 대체 모델, 합성 배치·치수, 가상 UI와 실제 출력 검수의 근거를 분리해 기록한다. 이미지 참고와 자동 시험은 실제 시설 일치의 수용 증거가 아니다.

## 2026-09-07 · 사진 복원과 연결된 전체 시설

사용자는 DA3 등 실제 컴퓨터비전 엔진으로 참고 사진의 깊이·카메라·기하를 복원하고 PLY/GLB 또는 3DGS로 전처리한 뒤 Blender 편집과 Unity 통합으로 이어지는 개발을 요청했다. 사진을 눈으로 참고한 합성 배치만으로 디지털 트윈이라고 부르지 않는다. 사용할 수 있는 오픈소스를 먼저 실행·비교하고, 부족하면 현재 공개된 논문·공식 코드를 같은 입력과 지표로 평가한다. 가장 최근 논문이라는 이유만으로 현장 정확도나 배포 가능성을 확정하지 않는다.

오픈월드의 최종 범위에는 열차·선로·승강장·터미널·매표소·역사 건물·연결 지하철역이 모두 포함된다. 구역별 입력 자료, 운영 주체, 관측 범위, 배치/축척 상태와 연결 통로를 기록한다. 공개 도면을 조사하되 치수가 있는 설계도·구내 안내도·장래 계획안을 구분한다. 한 맞이방의 사진 두 장이 사진 밖의 전체 세계를 복원하지는 않는다. 현재 합성 게임을 그대로 실제 부산역 평면으로 재분류하지 않는다.

VR 기기는 미정이다. 기기별 SDK·컨트롤러·PC/단독형 성능 목표는 확정하지 않고 같은 공간·상호작용 의미를 유지하는 이식 경로를 준비한다. Mac의 개발 실행 성공은 HMD 실행이나 학교 PC의 선택 기기 검증을 대신하지 않는다.

## 2026-09-08 · 외부 3D 생성 자료 정책 변경

사용자는 철도 사진·복원 기하를 외부 생성 서비스에 보내도 된다고 명시했고, 이어 자신이 정한 기존 프로젝트의 일괄 금지 규칙을 폐기하라고 지시했다. 따라서 **저장소의 외부 3D 생성 서비스 전송 일괄 금지 정책은 폐기**한다. 이를 단순한 논의나 허가 대기 상태로 다시 해석하지 않는다.

이 변경은 외부 3D 생성 서비스에 자료를 입력해 에셋을 제작하는 방향에 관한 것이다. 코딩 LLM에 이미지 첨부 없이 진행하라는 별도 지시는 유지한다. 원본·얼굴·민감자료·자격증명의 공개 Git 게시 금지, 제3자 권리·개인정보·서비스 약관, 과금 조건은 별도다. 이 문서는 계정 키나 미래의 게시·지출 권한을 저장하지 않으며, 실행 환경에서 별도로 적용하는 상위 지침을 변경하지 않는다.

이전 정책하에서 발생한 이미지 첨부 기록과 사후 감사는 당시 이력으로 보존한다. 새로운 정책을 소급 적용해 과거 위반이나 미검증 상태를 PASS로 바꾸지 않는다.

## 2026-09-08 · 전문 3D 생성 모델과 Astra의 역할

사용자는 전문 3D 생성 모델이 에셋 초안을 만들고 Astra가 환경 설정·Unity 연결 또는 Blender 디테일 작업을 맡는 방식을 제안했으며, Tencent의 최신 모델을 사용해 보라고 요청했다. 모델 발표·공개 가중치·실제 서비스 API를 구분하고, 계정/라이선스/하드웨어에 의해 실행되지 않은 모델을 사용 완료로 표시하지 않는다.

사용자는 Blender 디테일 작업에서 **GPT-6 Astra max reasoning**의 성능을 활용하는 방향을 제시했다. 이어 이러한 지시를 새로운 하드게이트로 고정하지 말고 목적을 추론하여 오케스트레이터가 모델 선택·작업 분할·연결을 직접 판단하라고 명확히 했다. 따라서 이는 품질을 위한 선호와 작업 방향이지 다른 모델의 활용이나 작업 진행을 일괄 차단하는 규칙이 아니다. 생성된 외형은 관측 복원이나 실측 평면으로 재분류하지 않으며 기존 오브젝트별 출처·기하·임포트 검증을 유지한다.

## 2026-09-08 · 최신 CV 기반의 재사용 가능한 Foundation 파이프라인 — 이후 폐기

사용자는 수천 개의 오브젝트마다 생성 비용을 지불하는 방식 대신 Astra와 재사용 가능한 제작 파이프라인을 원한다. 이어 단순한 벤치 변형·카탈로그 작업에 그치지 말고 **현재 날짜의 컴퓨터비전 논문과 연구자료를 확인해 SOTA 접근을 적용하고 Blender·Unity에 연결**하라고 명시했다. 실제 영상의 관측 복원, 객체/공간 분리와 동일 자산의 반복 사용을 함께 다루는 방향이다.

최신 발표일이나 논문의 성능표만으로 도입·현장 수용을 선언하지 않는다. 현재 공개 코드·가중치·라이선스·실행 자원과 원문의 한계를 확인하고, 이미 실행한 DA3/MapAnything 결과를 버리지 않고 적용 가능한 부분을 검증한다. 연구 확인과 실제 구현·실행은 구분하며, 아직 실행되지 않은 자동 객체 추적·장거리 정합·VR 단계는 남은 작업으로 표시한다. 이 결정은 조사 방향이며 새 유료 서비스 지출·계정 승인이나 현장 검증을 대체하지 않는다.

## 2026-09-08 · VARCO 제작 전환 — 이후 비용으로 폐기

사용자는 ‘3d 모델, asset, 사운드는 VARCO로 진행해, 파이프라인작업폐기하고’라고 명시했다. 위 자체 CV/재사용 제작 파이프라인의 추가 개발 계획을 폐기하고, **3D 모델·에셋은 VARCO 3D, 효과음·배경음은 VARCO Sound**를 사용한다. Astra는 제작 요청·선별과 기존 Unity 통합을 지원하며 자체 복원·생성 파이프라인 고도화를 계속하지 않는다.

이는 Foundation 개발의 취소나 기존 코드·원본·산출물의 일괄 삭제 요청이 아니었다. 이전 복원 결과와 실패 증거는 보존했다. 전환 당시에는 계정 접근·생성 전이었고, 이후 진행한 단일 시제품과 미완료 항목은 [VARCO 실험 기록](../art/varco-production.md)에 남긴다. 서비스 선택은 구독 결제·공개 게시·실제 시설/안전절차 수용을 뜻하지 않는다.

## 2026-09-08 · 현재 방향: CV 파이프라인 재개와 학교 PC 전달

사용자는 VARCO의 크레딧 비용 때문에 해당 제작 방향을 폐기하고, 이전 컴퓨터비전 SOTA 논문·연구에 근거한 재사용 파이프라인으로 돌아가도록 명시했다. 지금까지의 진행과 변경된 결정을 context graph로 공유하고 작업 단위별 소스를 기존 열린 Foundation PR에 전달하도록 요청했다. 이번 커밋/푸시 지시는 이 작업에 관한 것이며 미래 세션의 재사용 가능한 게시 권한으로 저장하지 않는다.

학교 PC에서 Foundation의 무거운 모델링·복원·렌더/베이크·Windows/HMD 작업을 수행하는 방향을 재확인했다. 학교 PC의 Unity 개발 적합성은 이미 사용자 경험으로 확정된 결정이며, 추가 사양 제출을 작업 장소 재승인의 선행조건으로 요구하지 않는다. 실제 실행 세션에 접근한 뒤 호환성·GPU 메모리·입력 상태를 확인하여 실행 크기와 예산을 정한다. Mac에서 실행한 결과를 학교 PC나 HMD 수용으로 옮기지 않는다.

사용자는 추가로 **CV/SOTA 파이프라인 재개는 현재 로컬 세션의 작업**이라고 명확히 했다. 학교에는 기존 자산의 고해상도 베이크/렌더, 대용량 데이터·모델 준비와 upstream GPU benchmark, Windows 빌드/성능 검증처럼 독립적인 고부하 작업을 배정한다. 공통 불변 기준과 별도 브랜치/출력을 사용하며 로컬 구현이 학교 결과를 기다리지 않게 한다. 학교 세션에 실제 연결되지 않았다면 준비된 작업 계약을 실행 중으로 표시하지 않는다.

기존 DA3/MapAnything 연속4장 결과·SfM 미등록·실패와 자료 복구 기록을 재사용한다. CV 기법 조사와 CV-01~06의 실제 적용·Blender/Unity 전달 완료를 구분하며, VARCO 시제품은 채택 자산으로 바꾸지 않는다. 학교 시작점은 [학교 PC 인계](school-pc-handoff-2026-09-08.md)와 기존 sequence spec이다. 원본 영상·가중치·계정·원시 실행 로그는 공개 Git에 넣지 않는다.

## 2026-09-08 · 공식 Unity Editor MCP 선택

PM 사용자는 학교 PC 사양·SPEC/계획/작업 파이프라인·GitHub 보드를 확인하고, CoplayDev/unity-mcp 대신 공식 Unity CLI에 포함된 Editor MCP를 사용하도록 지시했다. `unity mcp`와 공식 `com.unity.pipeline`을 기준으로 전환하며 native MCP 클라이언트에 Pi adapter를 필수화하지 않는다. 자세한 범위는 [ADR 0006](../adr/0006-official-unity-editor-mcp.md)을 따른다.

이 기록은 도구 선택에 관한 결정이다. 실제 연결·테스트·보드 Done·PR 검토 결과는 각각 확인하며, 과거 Coplay 연구/시험을 새 공식 서버의 증거로 바꾸지 않는다. 학교 PC의 실행 크기는 실제 자원에 맞춰 정하고 이전 기기의 무거운 작업 가능성을 그대로 가정하지 않는다.
