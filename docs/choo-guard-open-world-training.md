# 상시 현장 운영과 불시 비상대응 훈련

2026-09-07 사용자 확정: 실제 환경과 매뉴얼에 최대한 충실한 flat 스타일의 3D 시뮬레이션이다. 일반적인 현장 운영 중 예상하지 못한 변화를 인지하고 대응하는 능력을 연습한다. Desktop을 먼저 개발하고 같은 공간·설비·행동 모델을 VR 입력으로 확장한다.

## 현재 실행 흐름

현장 입장 → 이용객 순회와 설비 확인 → 조건을 만족하는 위치에서 불시 사건 발생 → 현장 신호/상황 패널로 관측 → 보고·사용 가능한 경로 판단·필요한 안내 전파 → 가까운 이용객 직접 인솔 → 집결 확인 → 현장 복구와 순회 재개 → 다음 불시 사건.

기본 플레이에는 훈련 종류 선택과 사건 시작 버튼이 없다. 입장 때 임시 직무와 일반 조작 안내만 선택한다. 사건 발생까지의 남은 시간·유형·위치·정답 행동 순서는 미리 표시하지 않는다. 평상시에는 다음 목표 내비게이션이 없으며, 사건을 관측한 후 플레이어가 직접 선택한 경로만 맵 위에 표시한다. 장치와 사람의 사용 표시는 맵 안에서 제공한다.

- 동일한 NPC 6명이 대합실·대기실·우회 통로 등의 지점 사이를 이동하고 잠시 대기한다.
- 사건 유형은 통행 제한, 안내·통신 이상이다. 중앙·서측·동측 중 하나에서 발생하며, 해당 위치에 실제로 접근 중인 이용객 중 2~6명을 대상으로 삼는다. 영향받지 않은 이용객은 일상 이동을 계속한다.
- 통행 제한은 물리 차단과 경로 그래프에 반영한다. 안내 이상은 표지/장치 상태와 NPC의 이용 가능한 경로에 반영한다. 차단 예정 영역에 사람이 있거나 대응 가능한 대상이 부족하면 발생을 보류한다.
- 보고가 오래 이루어지지 않으면 보조 통신 경로가 필요한 추가 상태 변화가 생길 수 있다. 이는 게임의 사건 변형이며 실제 고장 확률·위험 확산 법칙이 아니다.
- 관측 후 보고와 경로 선택은 서로 순서를 바꿀 수 있다. 인솔은 해당 사건의 보고/안내/경로 조건을 만족해야 한다. 선택한 경로가 고장 구역이면 사용할 수 없고, 통신 장치가 불가 상태이면 보조 단말을 사용한다.
- NPC에게 가까이 다가가 조준하고 E로 직접 인솔한다. 다른 물체·NPC에 가려진 대상과 미등록 복제 객체는 사용할 수 없다. 원격 인솔 버튼은 기본 모드에서 사용하지 않는다.
- 선택 통로 통과는 통로 앞에 접근한 것만으로 인정하지 않고 양쪽 면을 실제로 통과했는지 확인한다. 대상 NPC의 실제 도착과 집결 단말 확인이 필요하다.
- 대응이 끝나도 플레이어를 이동시키거나 시나리오 선택으로 돌아가지 않는다. 짧은 복구 후 NPC가 현재 위치에서 일상 이동을 재개한다.

## 구현과 재현

- `foundation/world/station-twin-profile.json`: 좌표계·단위, 세 통로, 센서 위치, 설비 식별자/Anchor/위치, 순회 목적지, 훈련 변형용 시간 범위와 출처 상태.
- `StationWorldSession.cs`: 독립된 seeded PRNG, 조건부 발생, 관측 여부와 세계 상태의 분리, 대응 선행 조건, 사건 이력.
- `StationWorldController.cs`: 실제 관측/거리/가림 검증, 상태의 장치·NPC·경로 반영, 연속 근무와 복기.
- `StationPortal.cs`, `DemoWalkGraph.cs`: 물리/논리 통행 상태, 공간 점유 확인, 그래프 버전과 경로 갱신.
- `DemoEvacuee.cs`: 순회·대기·인솔·실제 경로 통과·집결·복구. 감정/표정/직무 대행 없음.
- `StationWorldBuilder.cs`: Unity Editor API로 반복 가능한 생성. 시각 자산은 기존 Blender flat 모델을 공유한다.

기존 `DemoFlow`/선택형 훈련은 계약·기존 기능의 회귀 시험에만 남긴다. 기본 생성 장면은 하나의 상시 현장 컨트롤러를 사용한다. 기존 5직무 코어는 선택한 직무의 해당 행동을 관측했을 때 사건당 한 번만 기록한다. 무관한 직무의 행동을 수행 완료로 바꾸지 않으며, 해당 행동을 관측하지 않았다면 복기에 그대로 남긴다.

발생 난수는 NPC 애니메이션과 분리된다. 시드·프로필 사본·엔진 버전·발생 당시 인원 위치·관측/보고/경로/인솔/도착 이력으로 재현 조건을 남긴다. 같은 시드를 다시 실행해도 새 근무 ID를 사용해 이전 기록을 덮어쓰지 않는다. 완료·새 근무·앱 종료 시 이 기기의 `Application.persistentDataPath/StationSessions/`에 저장한다. 외부 전송이나 실명/직원번호 기록은 없다.

Esc → 대응 기록에서 완료한 사건의 요약과 시간순 기록을 볼 수 있다. 발생 후 관측 시간, 관측 후 보고 시간, 선택 경로, 대상/도착 인원을 설명한다. 점수·합격·이수·실제 매뉴얼 준수 판정은 제공하지 않는다.

## 디지털 트윈과 현장 효용의 검증 범위

현재 자료는 `synthetic-unverified`다. 실제 도면/촬영·직원 매뉴얼·운영 관측·실시간 설비 데이터가 연결된 검증된 디지털 트윈이 아니다. 설비 위치의 2cm 비교는 생성 장면과 프로필의 내부 일치 검사이며 실제 시설 측량 정확도를 뜻하지 않는다. 가시 모델을 flat으로 단순화해도 실제 통로 폭·설비 위치·동선과 절차 조건은 근거 자료에 따라 유지해야 한다.

| 실제 자료 연결 항목 | 필요한 근거와 검증 |
|---|---|
| 공간·좌표 | 승인 도면/측량/촬영, 기준 좌표와 단위, 구역/출입구/설비 식별자, 용도별 허용 오차와 누락 검토 |
| 설비 운영 상태 | 실제 장치 목록과 허용 상태 전이, 관측 시각·출처·지연·신뢰도, 정상/고장 상태 대조 |
| 직원 대응 과업 | 매뉴얼 명칭·개정일·절/쪽, 직무 책임·보고·인계·전후 조건, 현업 담당자의 검토 |
| NPC와 사건 변형 | 비식별 현장 관측을 이용한 이동/대기/반응 모델 보정. 현재 속도·시간·발생 분포는 합성 값 |
| 현장 전이 | 검토된 과업으로 사전/사후 수행 비교, 연습하지 않은 변형에서 평가, 승인된 현장 모의훈련에서 유지·전이 확인 |

디지털 트윈의 신뢰성은 사용 목적에 맞춘 검증·타당성 확인·불확실성 평가가 필요하다. 제조 분야의 일반적인 모델 신뢰성 원칙을 참고하며 철도 인증 기준으로 사용하지 않는다. [NIST, Digital Twin Credibility](https://www.nist.gov/publications/credibility-consideration-digital-twins-manufacturing).

돌발 상황은 훈련 목표·핵심 과업과 연결하고, 당시 이용 가능했던 정보·행동·누락을 복기하는 사건 기록을 남긴다. 미국 HSEEP의 훈련 설계/평가 방법론을 참고하며 코레일 절차를 대신하지 않는다. [FEMA HSEEP 교범](https://www.fema.gov/sites/default/files/2020-04/Homeland-Security-Exercise-and-Evaluation-Program-Doctrine-2020-Revision-2-2-25.pdf).

게임 내 완료나 자동 테스트 통과는 현장 대응 역량 향상의 증거가 아니다. 훈련 중 습득 평가와 현장 적용 평가는 구분해야 한다. [FEMA NTED 훈련개발·평가 안내](https://www.firstrespondertraining.gov/frts/trdc/state/development).

## 현재 검증 기록

EditMode 99개, PlayMode 16개 통과. 실제 생성 장면에서 통행 제한/안내 이상 × 중앙/서측/동측의 여섯 조합과 연속 두 사건을 자동 완주했다. 기존 15개 선택형 드릴/직무 조합은 회귀 시험으로 유지한다. 표지 배경 상태색 변경 후 흰 화살표 가독성을 검사하는 마지막 장면 검사 2개도 통과했다.

Mac universal 실행본을 생성하고, 실제 실행에서 평상시 NPC 이동과 불시 중앙 통로 제한을 관측했다. 사람의 수동 대응 전체 완주나 실제 현장 효용을 검증한 기록은 아니다. [정제 검증 기록](evidence/foundation/2026-09-07-open-world.json), [GitHub 작업 #60](https://github.com/xrlab-dau/CHOOGuard/issues/60).
