# choo guard 학교 PC 부트스트랩 v1.2

- 2026-09-06 사용자 지시로 local Unity Hub·Apple Silicon용 안정 LTS Editor 설치와 가벼운 합성 장면·Desktop 개발·Editor 테스트를 허용한다. 설치 대상은 Hub 3.21.1 ARM64와 Editor 6000.3.23f1 LTS다. 선정과 실제 설치 성공은 별도로 기록한다. 무거운 모델링·렌더·베이크, Windows 실행본·HMD 검증은 school-pc에서 수행한다.
- 저장소는 공개 설정과 절차를 전달하는 유일한 수단이다. OS 설정·승인 기록·자격까지 Git에 넣는다는 뜻이 아니다.
- 공개 기록은 `local`, `school-pc` 라벨과 역할만 사용한다. 호스트명·개인 계정·민감 저장 위치는 공개하지 않는다.
- **학교 bootstrap·Pi/MCP 운영 실행 상태: 보류.** 스크립트와 Pi 설정은 검토 초안이다. 학교 도구 설치, 프로젝트 신뢰, 로그인, 외부 호출을 이 문서로 승인하지 않는다. 사용자 지시로 승인한 local Unity 설치·가벼운 합성 게임 개발에는 이 학교 bootstrap 보류를 전역 선행조건으로 적용하지 않는다.
- 검토 상태는 [워크플로 기록](reviews/2026-09-06-workflow-status.json)을 따른다. 이전 local 영수증의 `required_ok=true`는 M0-00 완료나 학교 PC 재현 증거가 아니다.

## 1. 학교 PC에 전달하기 전

1. local에서 변경 파일과 미추적 산출물을 모두 검토한다. 비밀·자격·캐시·민감자료를 제외한다. vendored 라이선스·고지와 공급망 자료가 미검토이면 배포를 보류한다.
2. 승인된 작업 브랜치에 커밋·푸시한다. 원격에 실제 파일이 존재하는지 확인한다. 로컬 파일만으로 학교 PC 재현을 주장하지 않는다.
3. 사람은 PR을 만들고 팀 검토·CODEOWNER·필수 검사를 확인한다. 자동 PR 생성이나 main/develop 직접 푸시는 하지 않는다.
4. 학교 PC는 승인된 불변 커밋을 사용한다. 작업 브랜치를 미리 받아도 문서 검토만 가능하며 실행 승인을 대신하지 않는다.

검토용 clone 예시다. 아래 명령은 설치나 에이전트를 실행하지 않는다. 네트워크·Git 사용이 승인된 학교 PC에서만 사람이 수행한다.

```bash
git clone --branch chore/pi-agentic-toolchain https://github.com/xrlab-dau/CHOOGuard.git
git -C CHOOGuard status --short
git -C CHOOGuard rev-parse HEAD
```

원격 브랜치가 없으면 전달 미완료다. 다른 파일 공유 경로로 우회하지 않는다. 실행 대상의 전체 커밋 SHA는 PM의 별도 승인 기록과 대조한다.

## 2. M0-00 사람 정적 검사

M0-00에서는 Pi·MCP 실행과 패키지 설치를 하지 않는다. 사람이 명세 001을 기준으로 아래를 검사한다. 에이전트가 작성한 이 문서는 초안이며 사람 검사 결과가 아니다.

| 범위 | 확인 내용 | 실패·미확인 처리 |
|---|---|---|
| 자료 분류 | 추적 파일과 에이전트 가시 입력을 분류 manifest와 대조. PUBLIC_SYNTHETIC 또는 승인된 공개 코드·문서만 허용 | 미분류 입력이 하나라도 있으면 연결 금지 |
| 저장소 위생 | 검토된 Python 실행기로 `scripts/ci/repository_policy.py` 실행. Windows는 관리자가 확인한 `python` 또는 `py -3` 사용 | 종료 코드와 실제 검사 범위 기록. 미실행은 PASS 아님 |
| 파일명 | 대소문자 무관 자격·가중치·geometry·촬영 원본 확장자, 중첩 `.env` 변형 검사 | 값을 읽거나 자동 이동·삭제하지 않음 |
| 링크·마운트 | tracked/untracked/ignored 입력, `.pi/npm`·가상환경 루트 링크, Windows reparse point·junction, 저장소 아래 mount | 접근 거부·해석 실패는 미검증. OS 도구 출력은 사람이 대조하고 수·결과만 공개 |
| 보호 소유권 | 명시적 CODEOWNERS 패턴의 마지막 일치 소유자가 PM 승인 역할인지 확인 | 전역 팀 규칙만으로 통과 불가. 변경은 PM 승인 뒤 사람 수행 |
| 정책 기준선 | 명세 001 FR-006 전체 해시 범위, 필수 파일 존재, clean 대상과 manifest 귀속 | 현 생성기의 누락을 보완·시험하기 전 불완전 관측으로 분류 |

현재 `verify_toolchain.py`의 `--write`는 경로 이탈과 덮어쓰기 방지가 검증되지 않았다. 확정 영수증 생성에 사용하지 않는다. 기존 영수증도 수정하지 않는다. 보완 검증기에는 append-only 생성, 실패 종료, 허용 라벨, 정책 검사 결과, 대상 해시 연결이 필요하다.

## 3. 환경·공급망·실행 승인 순서

| 게이트 | 결정·시험 | 그전 금지 |
|---|---|---|
| D-01·D-02 | OS·셸·Python·설치 권한을 관리자 확인. sh/ps1 제공만으로 실행 정책을 해결하지 않음 | 실행 정책 Bypass, 관리자 권한 우회 |
| D-03 | 실행 주체별 목적지·포트·프로토콜·방향·프록시·목적·등급을 비공개 승인 프로파일로 확정 | 미승인 네트워크 목적지 |
| M0-03 | Pi와 의존성의 버전·소스·배포물 해시·전체 lock·설치 스크립트·라이선스·고지 검토 | 설정에 선언됐다는 이유로 자동 설치·trust |
| M1-02 | 모델 밖 파일·프로세스·네트워크 경계의 합성 부정 시험 | 실제 자료 연결, 미검증 Pi 실행 |
| D-08 | 별도 사용자 프로파일, OAuth 토큰 저장·로그아웃 잔류·정리·철회 절차 확인 | 공유 PC 로그인, 키 복사, 기본 모델·Exa 호출 |
| M1-01·M1-06·M1-07 | 세션 계약·Writer Lease·실제 제공자·검토 대상·실패 차단 확인 | 운영 개발 그래프 실행 |
| M2-01 | local/school-pc의 정확 Unity 에디터 버전·UPM 의존성·프로젝트 기준선 고정 | 버전·의존성이 미기록된 상태에서 재현 완료 주장 |
| M1-03 및 M2-01 완료 후 M1-04 | [공식 CLI Editor MCP](adr/0006-official-unity-editor-mcp.md)·Pipeline 검토와 정확 프로젝트 연결 시험 | 미검토 패키지 설치·미검증 연결의 완료 처리. Pi adapter는 선택 사항 |

Node 22 이상은 호환 조건이다. 머신별 정확한 Node·uv 버전은 별도 결정한다. ignored npm lock만으로 재현성을 주장하지 않는다. 승인된 추적 manifest·전체 lock·integrity와 검토된 설치 절차가 필요하다.

기존 bootstrap은 기본 의존성 동기화·자동 설치 안내·실패 종료 문제가 남아 있다. 수정·회귀 시험과 독립 검토가 끝날 때까지 실행하지 않는다. 문서의 경고가 실행 경계를 구현한 것은 아니다.

2026-09-09 보강에서는 Bash·PowerShell 진입점에 `--policy-preflight`를 연결했다. 승인 manifest와 별도 핀 및 정적 입력 검사가 통과하기 전에는 Node/Pi/uv/npm을 호출하지 않는다. 이 정적 단계는 영수증을 쓰지 않으며 전체 도구 검증 성공이나 학교 운영 승인을 뜻하지 않는다. `AUTO_INSTALL=1`/`-AutoInstall`은 별도 설치 허용이며 정책 게이트를 대신하지 않는다. wrapper는 `--strict`, `--write`, `--policy-manifest`, `--policy-manifest-sha256`만 전달한다. 후보 생성과 preflight 단독 관측은 Python 검증기를 직접 호출한다. 실행별 검증과 남은 조건은 [R-07 증거](evidence/R-07/README.md)를 따른다.

## 4. Unity·조사·자료의 분리

- Unity 버전과 프로젝트 파일은 M2-01에서 기록한다. M1-01은 Pi 세션 계약 단위다. HMD 실기 검증의 시점은 해당 XR 변경 단위에서 정하고 M1-05 실행 기록 단위와 혼동하지 않는다.
- 라이선스 유형은 D-05에서 확인한다. 라이선스 파일·계정은 저장소 밖으로 분리한다. 설치 권한이 없으면 관리자에게 요청하며 사용자 경로 설치를 우회 승인으로 취급하지 않는다.
- Spec Kit·BMAD 파일의 존재는 공급망·재배포 승인 또는 워크플로 실행 증거가 아니다. 스킬과 프롬프트는 실행 전에 검토한다.
- 조사 하네스는 local 후보다. 현재 자유 주제·모델·출력 경로와 미정제 게시 문제가 있어 실행 보류다. 학교 PC에서 `.env`를 만들거나 키를 주입하지 않는다. `--dry-run`도 외부 전송 통제의 검증은 아니다.
- D-07 확정 전 학교 PC는 PUBLIC_SYNTHETIC만 허용한다. 실제 회신·촬영물·재구성·정제 결과는 각각 별도 승인 대상이다. 저장소 밖이라는 사실이나 gitignore는 취급 허가가 아니다.

## 5. 실패 대응과 증거

| 증상 | 처리 |
|---|---|
| 설치·로그인·네트워크가 막힘 | 승인 상태를 확인하고 중단한다. trust 재승인·방화벽 변경·다른 API로 우회하지 않는다. |
| 제한 파일이나 외부 링크 발견 | 읽기·전송·자동 삭제·이동을 중지한다. PM이 등급과 보존 절차를 확인한다. 공개 보고에는 원문·민감 경로를 제외한다. |
| PowerShell native 명령 실패 | `$LASTEXITCODE`를 명시적으로 검사하는 수정본과 회귀 시험 전 성공으로 처리하지 않는다. |
| 필수 리뷰 실패·대상 변경 | cannot_proceed를 유지한다. 새 불변 대상에 대해 독립 재검토한다. |
| 비밀이 이미 전송됨 | 세션 삭제로 미전송을 주장하지 않는다. 원문을 재전송하지 않고 정제된 사고 기록과 자격 철회 절차를 사람이 수행한다. |

사람이 승인된 증거 위치에 새 파일로 기록한다. 기록에는 machine-label, 날짜, 명령·종료 코드, 대상 커밋·manifest 해시, 범위·누락·분류 결과, 검토·승인 역할이 필요하다. 실명·연락처·호스트·계정 매핑은 공개 파일에 두지 않는다. 이 문서를 따른다는 이유만으로 서명이나 PASS를 자동 생성하지 않는다.
