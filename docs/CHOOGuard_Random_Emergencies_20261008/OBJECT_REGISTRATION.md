2026-10-08 현재 코드와 배치 자료를 확인한 설계·구현 기록이다. [OBJECT_CAPABILITIES.json](OBJECT_CAPABILITIES.json)의 76개 정의는 객체가 가진 능력, 상태, 연결 관계와 구현할 원자 전이를 정리한 입력 설계 자료다. 이 JSON은 런타임에서 읽지 않으며 객체를 배치하거나 사건을 실행하지 않는다.

## 어떤 객체를 먼저 늘릴 것인가

Meshy가 제공하는 메시와 실제 상호작용 구현은 별도 작업이다. 처음에는 기존 프리팹·컴포넌트를 실제 실내 위치에 근거를 남겨 연결하는 편이 새 모델만 많이 추가하는 것보다 다양한 전이를 빨리 활성화한다.

| 순서 | 등록할 객체 묶음 | 가능한 조합의 증가 |
| --- | --- | --- |
| 1 | 분전반·자동판매기·충전함 + 실제 차단기 연결 | 같은 불이라도 전원 공급, 차단 방법, 주변 승객과 연기 전개가 달라짐 |
| 2 | 배관·헤드·구역 밸브 + 물이 닿는 실제 전기 장치 | 누수, 젖은 바닥, 미끄러짐, 전원 고장과 통행 방해가 연결됨 |
| 3 | 방화셔터·제어함·방화문 + 실제 통행 링크 | 독립 고장 또는 경보 이후 경로 제한과 군중 반응이 연결됨 |
| 4 | 튀김기·레인지·오븐·호스·밸브·감지기 + 점포 관계 | 화재 원인, 가스 누출, 공급 차단, 감지와 재발의 차이가 생김 |
| 5 | 환기 팬·댐퍼·천장 패널·배수 펌프·실내 우수 배관 | 같은 최초 원인이 다른 실내 연기·침수·낙하물 전개로 이어짐 |
| 6 | 방송 제어기·재난 경보 수신기·통신 장비·실내 보호 구역 표지 | 전시·재난 경보를 받았을 때 전달 실패, 보호 안내, 혼잡, 고립 등의 실내 대응을 훈련 |
| 7 | 보관함·등록 소포·미확인 물질 용기·보안 상황 행위자·현장 신고 단말 | 단일 관찰부터 서로 다른 복수 원인의 확인·통제·기관 인계까지 확장 |
| 8 | 휠체어·응급 물품·AED 보관함·안내등·이동식 통제 펜스 | 같은 위험에서도 접근성, 응급 자원과 실내 이동 여건이 달라짐 |

## 전시·재해·보안·응급 상황을 합성하는 방식

다음은 완성된 사건 목록이 아니라 여러 객체가 연결될 수 있는 전이 예시다. 각각의 화살표는 실제 원인 객체와 필요한 상태가 있을 때에만 후보가 되고, JEV가 그 순간의 발생 정도를 판단한다. 화살표가 모두 실행되는 대본은 없다.

| 검토 영역 | 실제 입력과 가능한 연쇄 | 먼저 필요한 행동 구현 |
| --- | --- | --- |
| 전시 상황 | 등록 경보 수신기가 훈련 경보를 받음 → 방송 전달/중단 → 실내 보호 안내 → 실제 통행 여건에 따른 혼잡·이동 보조 | 경보 출처·수신 상태, 방송 범위, 검토된 실내 보호 장소와 수용 상태. 아무 방을 실제 대피소라고 단정하지 않음 |
| 자연재해 | 현재 지진 → 실재 천장 물체의 고정 실패·낙하; 명시된 환경 입력 → 실내 우수 배관 누수 → 바닥 물 → 실제 보행자의 미끄러짐 | 객체별 고정/젖음, 물 유입·배수, 같은 대상 재검사, 실내 영향 범위 |
| 단순 보안·테러 의심 | 실제 소유자가 등록 소포·가방에서 멀어짐 → 목격/신고 → 확인·통제·경찰 인계 | 소유 관계, 신고 근거, 관찰과 실체 구분. 외형만으로 폭발물이나 범인을 확정하지 않음 |
| 복잡한 보안 상황 | 서로 다른 등록 원인이 겹침 → 훈련용 위험 효과·연무와 방송·통신 장애 또는 실제 통행 제한이 상호작용 → 증거별 우선 확인·복수 기관 인계 | 등록된 비작동 훈련 소품의 명시된 활성 상태와 고수준 효과, 원인별 고유 ID, 인과 링크, 복수 현장·자원 부하. 공격 방법·폭발물 제조·실제 물질 살포 구현은 필요하지 않음 |
| 응급 상황 | 실제 승객 증상 → 도움 요청/직접 확인 → 응급 자원 접근; 다른 실제 위험이 통행을 막으면 이동과 인계가 달라짐 | 증상과 관찰 단계, 보조 이동, 자원 상태와 전문가 인계 |

기존 역 전체 원인 예외는 지진·전력망 정전·협박 전화다. 향후 전시·기상 입력도 현재 등록된 수신기·배관 등 실제 입력 객체의 상태로 먼저 받아야 한다. 맵 밖의 공격, 무기, 군인, 폭발을 갑자기 만들어 실내로 옮기는 구현은 이 설계에 포함하지 않는다.

## JEV가 매번 다르게 만들려면

1. **객체를 등록한다.** 메시뿐 아니라 고유 ID, 실제 참조, 실내 바닥 위치와 현재 상태가 필요하다. 사람의 휴대물 특성처럼 기존 프록시로 표현되는 경우에는 그 연결을 명시한다.
2. **상호작용을 연결한다.** `fed_by`, `owned_by`, `drains_to`, `ventilates`, `blocks_route`, `detects` 등의 관계는 실제 등록 ID를 가리켜야 한다. 거리만 가까운 다른 층의 물체를 연결하지 않는다.
3. **원자 전이를 구현한다.** 예를 들어 배관 이음에서 물이 새는 전이와 실제 전기 장치에 물이 닿는 전이는 별개다. `Apply`가 상태·시각/청각 효과·위험 범위·후속 가능한 전이를 실제로 변경해야 한다.
4. **지금 가능한 전이를 전부 판단한다.** 사건군을 먼저 고르거나 질문 수 때문에 원인을 제거하지 않는다. 요청당 100질문 제한은 판단 큐의 배치 크기이며 후보 집합의 상한이 아니다.
5. **시간과 크기를 JEV의 판단으로 추첨한다.** 임박도를 경쟁 위험률로 변환하고 크기도 수준별 확률로 추첨한다. 현재 진행 상황과 대응 부하를 함께 제공한다. 원인 객체가 늘었다고 사건 빈도가 폭증하지 않도록 기존 역 단위 신규 원인 위험률 배분을 유지한다.
6. **같은 종류라도 다른 실제 원인을 허용한다.** 이번 디렉터 변경은 이미 발생한 `Kind` 전체를 금지하던 제약을 원인 `Transition.Key`별 기록으로 바꾼다. 서로 다른 객체에서 같은 종류가 시작될 수 있지만 같은 원인 키를 무제한 반복하지 않는다. 이후 다시 정상으로 복구되어 별개 발생을 허용하려면 객체 상태 버전과 복구 시점을 포함하는 수명 규칙이 추가로 필요하다.
7. **인과 전개와 별개 동시 원인을 구분한다.** 같은 누수가 만드는 미끄러짐은 후속 전이이고, 독립 승객의 응급 증상은 별개 원인이다. JEV가 현재 객체와 연쇄를 보고 판단하게 하며 정해진 두 사건 조합으로 고정하지 않는다.
8. **실행 직전에 같은 원인을 다시 확인한다.** JEV의 응답을 기다리는 동안 객체가 이동·파괴·차단되거나 실외로 나갔다면 실행하지 않는다. 다른 객체로 바꾸어 실행하지 않는다.

## 등록 완료의 검증 기준

- 미등록 원인은 inventory에 `unavailable_no_registered_source`로 나오며 후보와 위험을 만들지 않는다.
- 새 종류의 객체를 등록하면 종류·상태 집계에는 나오되 어댑터가 없으면 가상의 원인이 생기지 않는다.
- 실외 객체·승객·열차 내부는 사건 원인으로 제외한다. 높은 실내 설비는 바닥 위치 메타데이터로 실내 여부를 확인한다.
- 같은 종류의 두 실내 객체는 서로 다른 후보 키를 가진다. 한 객체를 제거·차단하면 해당 객체의 후보만 무효가 된다.
- 스냅샷 반복·등록 자료·안내 설정이 디렉터나 세계의 난수열을 소비하지 않는다.
- 1초 캐시 이후 집계 갱신과 게임 시간 되감기 시 초기화가 맞게 동작한다. 캐시가 살아 있어도 실행 전 실제 대상 재검사는 유지한다.
- 한 근무·한 시드에서 특정 사건을 기대하지 않는다. 여러 합성 근무에서 실내 범위, 원인 실재성, 알려진 위험만 안내, 다른 객체 동일 종류 허용, 판단 큐 대기 시간과 프레임 비용을 검사한다.
- Meshy 결과물은 모델 품질 외에 collider, 회전/문짝 같은 동작 부분, 규모, ID·위치·출처, adapter, registry, 실내 경계, 관찰·기관 인계까지 확인해야 등록 완료다.

이 문서의 객체 수는 입력 정의 수다. 추가 물체 76개를 맵에 배치했다거나 40개 신규 동작 어댑터가 이미 구현되었다는 뜻이 아니다.
