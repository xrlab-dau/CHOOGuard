# 부산역 내부 비상상황과 JEV 랜덤 합성 보고

후속 승인 구현의 현행 정책은 **근무당 독립 발단 하나와 그에 연관된 실내 전개**다. 아래 초기 다양성 제안은 후보 풀의 다양성으로 해석한다. 측정 트윈·부품 분리·대응 흐름의 실제 완료 범위와 공백은 [후속 실행 보고](../CHOOGuard_Measured_Twin_20261008/IMPLEMENTATION_REPORT.md)를 따른다.

2026-10-08. 현재 코드/배치 파일/열린 Unity 에디터를 확인하고 작성했다. ‘전시상황’은 전시(戰時)로 해석했다.

## 이번에 반영한 동작

1. **발생은 부산역 건물 내부로 제한했다.** 실제 실내 구역에 속하고 역사 구조물 아래인 승객·지점·설비만 새 원인 후보가 된다. 광장·옥외 공간·승강장·선로·KTX 객실은 제외한다. 후보를 만들 때와 JEV 응답 적용 직전에 같은 대상을 검사한다. 가방·미확인 물질·협박 수색 지점도 내부 위치를 검사한다. 대피와 외부 지원기관 진입 동선은 유지한다.
2. **길 안내를 복원했다.** 기능이 삭제된 것이 아니라 표준 프로필과 저장값 `chooguard.showRoute.v2=0` 때문에 꺼져 있었다. 이번 사용자 환경의 값을 켰고, 견학·표준 기본값도 켜짐으로 바꿨다. 실전 기본값은 꺼짐이며 개별 설정은 가능하다. 바닥 점선·지도 경로·나침반은 플레이어가 인지한 현장만 안내한다. 수동 조작 수준은 그대로다.
3. **JEV에 현재 객체 입력을 추가했다.** `Focus.world_objects`에 실내 승객의 행동·소지품·부상 상태, 실제 지점 종류, 실제 등록 설비의 종류·상태, 에스컬레이터·승강기·남아 있는 안내판, 원인별 설비 등록 여부를 전달한다. 1게임초 단위로 집계하며 난수를 소비하거나 객체를 생성하지 않는다. 이 집계와 별도로 각 원자 후보는 정확한 객체를 지칭하고 자체 전제조건을 검사한다.
4. **독립된 같은 종류 원인도 허용했다.** 과거에는 한 번 발생한 종류 전체가 다음 원인에서 제외됐다. 이제 이미 실행한 정확한 원인 전이 key만 제외하므로 다른 배터리·다른 승객·다른 안내판에서 같은 종류의 변화가 가능하다. 진행 중 사건에 새 지진을 겹치지 않는 기존 제약은 유지한다. 안내판 낙하도 역 전체 후보 하나에서 실제 실내 안내판별 후보로 바꿨다.

## 현행 다양성이 작은 이유

설비 관련 코드가 있다고 실제 설비가 배치된 것은 아니다. `Assets/ChooGuard/Art/Emergency/Equipment/`의 FireSafety·Alarm·ElectricPlaza·Sprinklers·Compartments·Surveillance·KitchenGas **7개 JSON의 items가 모두 빈 배열**이다. 실제 배치 위치 근거가 없는 이전 객체가 제거돼 있었고, 현재 spawner도 위치 근거 없는 항목을 보류한다. 그래서 프리팹과 화재/누수 코드가 남아 있어도 그 설비에서 출발하는 후보는 생기지 않는다.

이번 작업은 빈 배치에 임의 위치를 넣어 실제 부산역 설치 사실로 꾸미지 않았다. 현재 존재하는 객체의 입력 집계는 런타임에 연결했고, 추가할 객체는 별도 능력 카탈로그에 등록 설계했다. 카탈로그 항목 전체가 이미 씬에 배치되거나 실행 가능한 것은 아니다.

## 추천 생성 구조

**실재 객체와 상태 → 물리적으로 가능한 원자 전이 → JEV 임박도/크기 판단 → 코드가 시간에 따라 발생 적용 → 바뀐 세계에서 새 전이 생성 → 발견·대응·피해·해소**를 반복한다.

JEV는 자유 문장으로 새 모델이나 임의 행동을 작성하는 생성기가 아니다. 상태에 대한 typed 질문을 평가하며 Score는 단계별 확률을 돌려준다. 공식 지침도 작은 원자 질문을 나누고 코드에서 합성하는 방식을 설명한다. 이 프로젝트의 다양성은 **원인 객체·물리 상태·연결 관계·관측·실행 능력**을 넓혀야 늘어난다. [TypeSafe Introduction](https://docs.typesafe.ai/introduction), [API reference](https://docs.typesafe.ai/api)

예를 들어 가상의 등록된 실내 배관에서 `누수 시작`이 평가·적용되면, 물이 닿는 바닥의 `미끄러짐`, 연결된 전기설비의 `이상`, 감지기와 셔터의 `상태 변화`, 승객의 `목격·신고·우회`가 각각 현재 전제조건에 따라 후보가 될 수 있다. 물리/행동 어댑터가 없는 변화는 발생시키지 않는다. 이 연쇄의 결과에 나중에 ‘정전과 환자가 겹친 대피 상황’이라는 이름을 붙인다. 같은 대본을 재생하거나 완성 사건을 추첨하지 않는다.

‘완전 랜덤’의 목표는 균등하게 아무 사건이나 발생시키는 것이 아니라, 허용된 내부 세계에서 **시점·원인 객체·크기·연쇄·발견 순서·대응 결과가 매번 달라지는 것**이다. 코드가 구현하지 않은 물리 변화까지 자동으로 무한히 만들어지는 것은 아니다. 여러 JEV 질문은 같은 세계 snapshot으로 평가하고, 적용 과정에서 전제조건이 달라진 후보는 폐기한다. 후보 수 증가가 사건 빈도를 무조건 올리지 않도록 기존 공통 위험률 예산을 유지한다.

## 어떤 객체를 늘릴 것인가

상세 등록 계약은 [OBJECT_REGISTRATION.md](OBJECT_REGISTRATION.md), 기계 판독 카탈로그는 [OBJECT_CAPABILITIES.json](OBJECT_CAPABILITIES.json)에 있다. 객체 정의는 76개이며 새 어댑터가 필요한 제안은 40개다. [44개 결과 예시](SCENARIO_PROPOSALS.md)는 전시 6·자연재해 8·단순 보안 6·복합 보안 6·의료/생활 8·설비 10개다.

| 분야 | 우선 등록할 객체·상태 | 만들어질 수 있는 결과 예시 |
|---|---|---|
| 전시(戰時) | 검증된 경보 수신기, 방송설비, 비상조명, 안내 표지, 대피/보호가 필요한 승객, 구호물자 | 경보와 정보 지연, 어둠 속 이동, 가족 분리, 의료 지원과 안내의 충돌 |
| 자연재해 | 유리/천장/안내판, 배수구·문·누수 지점, 배관·전원 연결, 군중 | 지진 뒤 낙하물·갇힘, 실내 유입수와 정전, 젖은 통로와 넘어짐 |
| 단순 보안 사건 | 가방·소포·봉투, 승객·목격자, 실제 CCTV/신고 지점 | 방치 물건과 주인 확인, 협박 신고, 미확인 물질과 주변 접근 통제 |
| 복합 보안 사건 | 여러 독립 물건, 안내/관측 설비 상태, 통로와 문, 취약 승객 | 여러 위치의 미확인 신고, 관측 공백과 상충 정보, 통제 동선과 환자 이동의 충돌 |
| 의료·생활 | 승객의 건강/이동/언어/동행 상태, AED·구급함·휠체어·들것 | 쓰러짐과 혼잡, 도움 요청 지연, 보호자 분리, 이동 지원과 대피 |
| 설비 | 분전반·자판기·충전기·주방·가스·감지기·셔터·승강기 | 서로 연결된 누수·전기 이상·연기·경보·이동 장애 |

Meshy로 만들 모델은 외형이다. 각 객체에는 `id`, 실내 위치와 배치 출처, `capabilities`, 현재 `state`, 연결 객체, 관측 신호, 전제조건, 적용 함수, 대응 상호작용을 함께 붙여야 한다. 단순히 모델 이름을 JEV 프롬프트에 적으면 그 객체의 화재·누수·상태 변화가 실행되지는 않는다. 시민 보호 훈련에 필요한 객체와 결과만 다룬다.

## 추가 구현 순서

1. **배치/등록부터 복구:** 기존 지원 코드가 있는 설비 중 실제 위치를 확인한 것부터 활성 등록한다. 새 훈련용 배치는 실제 트윈과 구분한 출처/모드 계약을 먼저 둔다. 원인·영향·대응 객체를 함께 넣고 단일 미확인 물건만 늘리지 않는다.
2. **재사용 가능한 능력:** 열·연기·물·전원·문/통로·군중·소지품·건강·신호/관측의 상태와 연결 어댑터를 둔다. 새 모델은 이 어댑터를 재사용한다. 최근 변한 주변 객체의 상태를 해당 후보 질문에 전달한다.
3. **환경 조건:** 전시 경보·강우·외부 재난은 명시적인 훈련 외부조건 입력으로 등록한다. 기존 예외(지진·계통 정전·협박 전화) 밖의 외부 사건을 프롬프트만으로 추가하지 않는다. 실제 플레이 사건/피해 위치는 실내 객체에 귀속한다.
4. **다양성 검증:** 종류별 기대 대본 대신 실내 경계, 실재 원인, 상태 재검사, 미인지 정보 비노출, 인과 링크, 대응 가능성, 호출 지연/예산과 프레임 비용을 검사한다. 다양한 seed와 실제 JEV 응답으로 범위·연쇄·발견 순서를 기록한다.

## 검증 상태

- Unity 6000.3.23f1에서 컴파일 후 설정 PlayMode 시험 12개 통과.
- 실재 씬을 로드한 내부 합성 계약 시험 통과: 실내 spawn 허용, 광장·승강장 제외, 열차/선로 원인 미등록, 밖으로 이동한 승객의 옛 후보 폐기, exact key 재발 방지와 다른 같은 종류 객체 허용, 현재 설비 집계와 캐시 갱신 확인. 추가 리뷰 후 외부 후속 부상자 선택/적용 거부와 보조배터리 화재의 최종 내부 위치도 검사했다. 해당 씬의 원인 후보는 1,345개, 실내 등록 설비는 0개였다(판단 결과나 실제 발생 사건 수가 아니다).
- 실제 씬의 길 안내 계약 시험 통과: 미인지 사건 경로 비표시, 인지된 현장의 바닥 점선 표시, 미인지 장애물에 경로 불변, 설정 전환과 세계 난수 독립, 역 전체 위험은 위치 안내 대상에서 제외. 설정 12개 + 내부 합성 1개 + 길 안내 1개, 총 14개 검사를 통과했다.
- 이 시험은 JEV를 꺼서 실제 API 비용과 우연한 사건에 의존하지 않고 후보/안내 불변조건을 검사한다. 전시·강우 등 새 제안의 실제 합성 및 Meshy 모델 제작/배치를 완료했다고 주장하지 않는다. 라이브 JEV 다양성/장시간 성능은 별도 실측 대상이다.
