# PRD v11 개정·검수 기록

## 변경 목적
운영 시뮬레이션 중심과 지원 범위의 정밀 모델 목표를 유지하면서 C01–C12 비평을 실제 기능·효용 평가·단계 계약에 반영했다. 핵심 변경은 반복 작성팀, 초기/반복 총인시, 재사용·변경 영향·부분 재실행·다음 판단 지점, 고객 양식, 동일 코어 A/B/C 비교, 별도의 사용자·모델·기관·도입 판정이다.

## 실제 확인한 범위
- 제공된 v10 PRD/계약, 비평/사용자 검증 계획, 결정서, 무료 에셋 등록부를 로컬 원문으로 읽었다. 입력 해시는 input-manifest.json에 있다.
- 기존 요구 REQ-001–076 식별자를 유지하고 15개를 추가했다. 기존 요구 중 관련 내용과 인수조건도 개정했다. 총 91개 요구 및 91개 미래 인수시험이다.
- EP00–EP11, 13개 구역 식별자, 22개 운영 원인, 기존 출처 URL, 무료 후보 25개를 보존했다.
- 전체 고정밀 모델 완료를 사용자 연구의 공통 선행으로 두지 않도록 단계 입력을 분리했다. 사용성을 물리 승인으로 승격시키지 않는다.
- 구조 검사와 문서 mutation 검사 32개를 실제 실행했고 모두 통과했다. 상세 출력은 document-tests.txt 및 contract-validation.json에 있다.
- ontology.jsonld는 RDF로 파싱했다. 실제 도메인 데이터에 대한 SHACL 검증이나 의미적 완전성 검증은 아니다.
- Word를 렌더링하고 총 35쪽의 한글·표·기호·본문 흐름·머리말/꼬리말을 시각 확인했다. 페이지 1–23은 최종 렌더와 기존 확인본의 PNG 바이트 일치도 확인했다. 시각 검수는 동일 작성자가 수행했다.
- 문서 접근성 자동 검사의 보고 항목은 high=0, medium=0, low=0이었다. 이것이 모든 보조기술에서의 완전한 접근성을 보증하지는 않는다.

## 초기 실패 기록의 의미
`document-tests-before-validator.txt`는 검사 도구 구현 전 모듈이 없어서 실패한 준비 단계 기록이다. 제품 오류나 Unity 버그를 재현한 기록이 아니다. 이후 구현한 검사는 손상된 계약을 명시적으로 주입하여 누락/중복 ID, 잘못된 참조, 가짜 PASS, 두 모드 불변조건, 연구 분모/시간 경계, 과도한 선행 및 순환 등의 탐지 여부를 확인한다. 첫 통과와 최종 재실행 로그를 별도로 보존했다.

## 절대 승격하지 않는 상태
사용자 인터뷰·시간 연구·실제 고객 A/B/C·Unity·물리 계산·현장 시험·기관 검수는 이번 작업에서 미실행이다. 미래 제품 인수시험 91개는 모두 NOT_RUN이다. C01–C12는 설계 반영 SPECIFIED, 현실에서 해결됨은 NOT_TESTED다. 문서 검사 횟수로 시장성·현실 정확도·기관 승인·AAA를 발급하지 않는다.

## 원문·원격 경계
외부 웹·매뉴얼·소프트웨어 버전·에셋 무료판을 이번에 다시 검증하지 않았다. 이전 확인 시점과 미확인을 유지했고 새 수집 완료로 표시하지 않았다. GitHub #222·코드·담당자·보드는 조회·수정하지 않았다. 이 전달 패키지는 실제 프로젝트 코드 커밋이나 구현 산출물이 아니다.
