## 0. 조사 방법과 증거의 경계

사용자가 제공한 클라이언트 요구와 기존 제품 결정서를 읽고, 국내 훈련 운영기관·행정안전부·FEMA의 공개자료, 제품 공급자·실제 도입기관 설명, 연구 초록·출판사 제공 본문, 공식 기술문서를 대조했다. 원문 23개는 `SOURCES.md`와 `sources.json`에 연결했다. “시간”은 준비·작성·검토의 시간으로 해석했으며, 사업 판단을 위해 시장·대체재도 조사했다.

증거를 다섯 층으로 구분한다. ① 사용자 전달 요구 ② 공개된 기관 업무·사례 ③ 연구 결과 ④ 공급자 주장 ⑤ 본 보고서의 제품 가설·실험 제안. 공급자 페이지의 “수분 생성”은 검수까지 포함한 독립 생산성 결과가 아니다. 연구 초록을 읽었다고 전체 실험을 재현했다고 표현하지 않는다.

**이번에 하지 않은 일:** 실제 작성 담당자 인터뷰, 현장 업무 관찰, 작성시간 계측, 경쟁제품 체험, Unity 빌드, 에셋 입고, 물리·군중모델 실행, 실제 철도 현장 정확도 검증, 고객 구매·예산 확인. 아래 실험은 모두 계획이며 결과가 아니다.

## 2. 문제 정의

### 2.1 해결할 핵심 문제

**철도 합동훈련 작성 담당자가 기관별 업무·자원·보고·시설 조건을 바꿀 때, 그 변경이 후속 업무·기관 간 인계·현장 이동에 만드는 충돌과 지연을 사전 검토하고, 선택 이유를 최종 대본까지 추적하기 어렵다는 문제.**

“3D 맵이 없다”와 “LLM이 없다”는 문제 정의가 아니라 특정 해결책의 부재다. 사람의 노력과 오류가 실제로 어디서 발생하는지를 먼저 확인해야 한다. 해당 고객에게 이 문제가 얼마나 자주·심각하게 발생하는지는 아직 측정하지 않았다.

### 2.2 근거와 추론

행정안전부는 상시훈련의 목적을 초기 임무·역할 숙지와 매뉴얼의 적절성 점검·개선으로 설명하며, 2025년 41개 기관에 전문가 컨설팅을 지원했다고 공개한다. 이는 제도적 과업의 존재를 보여주지만 특정 직원의 불편 크기나 소프트웨어 구매 의사를 의미하지 않는다. [S01]

2026년 3월 11일 율현터널 합동훈련에는 5개 기관·80여 명·고속열차 2대가 참여했다. 새벽 2시 실시된 사실은 실제 철도환경의 훈련 창이 제한될 수 있다는 참고 근거다. 80명은 작성자 수나 소프트웨어 좌석 수가 아니다. [S03]

SR은 2023년부터 가상 철도 비상훈련 시스템을 구축했고, 운영·정비 때문에 실제 현장 훈련에 제약이 있다고 설명한다. 따라서 가상 훈련이라는 문제 접근에는 현실적 근거가 있으나, 그 자체가 CHOOGuard의 차별점은 아니다. [S04]

### 2.3 실제 고객에게 확인할 세 문제

P1. 변경 영향 추적: 한 업무나 통로를 바꾸면 어떤 문서·인력·기관의 역할을 다시 검토해야 하는가?  
P2. 실행 가능성 점검: 문서상 자연스러운 순서가 자원 점유·정보 전달·공간 이동에서 충돌하지 않는가?  
P3. 근거와 합의 보존: 채택·기각한 운영안의 이유와 적용한 매뉴얼 판본을 대본에 연결할 수 있는가?

한계도 명시한다. 담당자들이 가장 큰 문제를 “기관 회신을 받는 행정 절차”라고 답한다면 시뮬레이터만으로 그 대기를 제거할 수 없다. 실제 병목이 승인용 서식 편집뿐이라면 RTS는 과잉 해결일 수 있다. 이를 확인하기 전 게임성의 우월성을 단정하지 않는다.

## 3. 타겟 정의와 사용자 조사

### 3.1 첫 타겟

**같은 철도 현장 또는 재사용 가능한 현장 묶음에서 다기관 합동훈련을 반복 기획하고, 초안의 기관별 업무와 대본을 통합하는 작성 책임자·실무팀.** 본사/지역본부 안전·훈련 업무 또는 현장 훈련 조정 기능을 후보로 삼되, 현재 조직의 정확한 직명과 권한은 고객 인터뷰로 확인한다. 코레일 공개 재난관리체계는 협조 역할을 파악하는 자료이지 작성자 직무기술서는 아니다. [S18]

타겟을 반복 작성팀으로 좁히는 이유는 초기 규칙·공간 입력 비용을 여러 번 사용할 때 회수할 수 있기 때문이다. 사용 빈도가 낮고 공간이 매번 완전히 다른 일회성 행사에는 다른 비용 구조가 필요하다.

| 역할 | 하고 싶은 일 | 제품과의 접점 | 아직 모르는 것 |
|---|---|---|---|
| 주 작성자 | 조건을 바꾸고 모순을 줄여 검토 가능한 안을 만들기 | RTS·업무 보드·분기·대본 | 실제 빈도, 게임 숙련, 현재 도구, 수정량 |
| 기관별 협조 담당자 | 자기 기관의 역할·자원·인계 검토 | 근거 카드·기관별 보기·검토 의견 | 승인 범위, 자료 반출 가능성 |
| 훈련 책임자·검수자 | 적용 가능한 대본인지 결정 | 변경점·가정·미해결·승인 기록 | 실제 수용 기준과 서식 |
| 구매·정보화 담당자 | 도입·배포·유지보수 판단 | 보안·설치·계약·운영 비용 | 예산, 구매 단위, 보안환경 |
| 현장·모델 전문가 | 자료와 계산을 검증 | 독립 관측·정확도 검토 | 협조 시간과 보정자료 |
| 교육 사용자 | 기관 공조와 도구 사용법 숙지 | 튜토리얼 | 학습 이전·이후 평가 |

가상 세계의 소방·경찰·철도 팀과 실제 프로그램 사용자는 별개다. 실제 훈련 참가자 총원으로 구매 좌석을 계산하지 않는다. 작성자에게 가상 분석 권한이 있다고 모든 실제 기관의 지휘권이 생기지도 않는다.

### 3.2 초기 제외 타겟

일반 승객·재난게임 소비자, 반사신경·현장 동작 훈련만 필요한 개인, 정형 대본의 문구 수정만 하는 일회성 사용자, 민감자료 제공·규칙 검수 모두 불가능한 현장을 첫 실증 타겟으로 삼지 않는다. 일반화 이전에 한 반복 작성팀의 실제 문제를 해결한다.

“합동훈련의 자원·역할·공간 조건이 변경됐을 때, 변경으로 생기는 충돌과 대기를 확인하고 대안을 비교해서, 관계기관이 검토할 수 있는 운영안과 대본을 다시 만들고 싶다.”

대표적 사용 유발 상황은 새 훈련 기획, 기관·자원 변경, 이전 강평의 개선 요구, 시설·통로 변경이다. 이는 조사에 사용할 가설이지 이미 고객에게 관찰한 빈도가 아니다.

### 3.4 현재 공개 사용자 연구가 주는 것

2010년 Collario 연구 초록은 비상상황 시나리오 공동 저작을 현장시험과 사용자 피드백으로 검토한 사례다. 2015년 보건 비상훈련 연구는 실제 기획자에게 평가 양식을 생성하는 도구를 사용하게 하고 유용성·선호를 조사했다. 둘 다 협업과 검토 가능한 산출물이 중요하다는 연구 방향을 제공한다. 그러나 시대·분야가 다르며 RTS 조작이 한국 철도 작성시간을 줄인다는 근거는 아니다. [S22][S23]

따라서 가상 인물 이름·나이·월급을 만들어 정밀한 페르소나처럼 쓰지 않는다. 실제 최근 업무와 문서를 기준으로 사용자를 정의한다.

## 4. 시간 조사: 네 가지 시간을 분리한다

### 4.1 확인한 사실과 미확인 수치

FEMA HSEEP은 훈련 기획에 팀·회의·목표·시나리오·문서·실행·평가·물류 준비가 포함된다고 설명한다. 국내 인접 사례에서는 과천시의 2024년 10월 31일 훈련 준비에 컨설팅 2회와 기획회의 6회가 있었다고 보도됐다. 이는 복수 조정 단계의 사례일 뿐 철도 작성 업무의 평균 인시를 제공하지 않는다. [S05][S06]

이번 조사로 “철도 대본 한 건 평균 40시간”이나 “작성비의 70%가 편집”처럼 일반화할 수 있는 신뢰할 만한 기준값은 확인하지 못했다. 공개 보도에는 훈련 인원·장소·실시시각이 많지만 준비 실무자의 능동 작업시간은 부족하다.

### 4.2 측정할 네 시계

| 시계 | 정의 | 예시·주의 |
|---|---|---|
| 달력상 리드타임 | 최초 기획부터 검토 가능한 대본까지의 경과 | 기관 회신 대기·주말 포함. 작업 인시와 다름 |
| 사람의 작업량 | 작성자·협조자·검수자가 실제 투입한 시간의 합 | 5명이 1시간 회의하면 5인시. 같은 사람의 동시 기록을 중복 합산하지 않음 |
| 도구·계산 지연 | 학습, 입력, 실행 대기, 변환, 재작업 | 무인 연산시간은 인시에 넣지 않고 경과시간·비용으로 분리 |
| 시뮬레이션 시간 | 모델 속 사건·업무가 전개되는 시간 | 게임 속 10분 개선을 실제 작성시간 절감으로 계산하지 않음 |

### 4.3 시간·비용의 경계

기존 방식의 총노력은 자료 수집 + 협의 + 운영안 설계 + 대본 편집 + 검토/재작업이다. 새로운 방식에는 규칙·현장 모델 초기 구축, 교육, 사건 입력, 운영 조작, 계산 모니터링, 결과 검토, 출력 수정, 유지보수가 추가된다. 단순 문장 생성 속도만 비교하면 새 시스템의 진짜 비용을 숨긴다.

재사용 N건에 대한 측정식은 다음과 같다.

`T_new(N) = T_initial + Σ[T_input + T_operate + T_attended_compute + T_review + T_export] + T_maintenance(N)`

`T_initial`에는 교육·설치·자료 정제·규칙 검수·현장 모델 제작의 사람 작업량을 모두 포함한다. 개발자가 대신 해준 입력도 사라진 비용으로 취급하지 않는다. `T_attended_compute`는 실제 사람이 붙어서 기다리거나 처리한 시간만 포함한다. 무인 GPU 계산은 별도 경과시간·비용으로 기록한다.

반복 유지보수까지 포함한 정상 상태의 건당 순절감 Δ가 양수라면 `N_break_even = ceil(T_initial / Δ)`로 사람 작업량 기준 손익분기 재사용 횟수를 추정할 수 있다. Δ≤0이면 시간 절감을 주장하지 않는다. 돈의 손익분기는 별도 단가·연산·유지비를 사용해야 하며 여기서 가격을 추정하지 않는다.

초기 구축과 학습을 제외한 반복 사용 비교, 그리고 이를 포함한 누적 비교를 모두 보고한다. 고객의 현실적인 사용 빈도가 손익분기 횟수에 못 미치면 도입 정당성이 약하다.

### 4.4 시간에 맞춘 제품 개선

기준 현장·매뉴얼 묶음을 한 번 검수해 재사용하고, 전체를 새로 입력하지 않게 한다. 변경된 조건의 영향 범위와 검증된 체크포인트에서 재실행한다. 작업자는 불필요한 이동 애니메이션을 끝까지 볼 필요 없이 다음 의사결정 지점으로 이동하되, 시뮬레이션 시간과 계산은 보존한다. 배속이 물리 timestep을 임의로 키우는 기능이어서는 안 된다.

초기 기획 목표는 “온보딩 30분 이내, 첫 유용한 비교 15분 이내”로 제안할 수 있지만 이는 사용자 시험 전의 목표값이다. 실측 후 고정하고 학습시간 실패를 숨기지 않는다.

### 5.2 가장 가까운 연구 선례

2024년 Safety Science의 대피모델 기반 도상훈련 연구는 기존 계획과 새 상황부여에 따른 결정의 영향을 시뮬레이션으로 피드백하는 접근을 실제 로도스 훈련에서 다뤘다. 이는 운영 중 변화의 결과를 보고 싶다는 제품 방향의 개연성을 뒷받침한다. 동시에 입력과 최적 경로 가정에 따라 낙관적 결과가 생길 수 있음을 기술한다. 한국 철도 작성 생산성이나 현장 정확도를 증명하지는 않는다. [S21]

즉, “세상에 없던 결합”보다 “국내 철도 작성 업무에 맞는 실행·검토·출력 연결이 얼마나 잘 되는가”로 차별점을 좁힌다.

### 5.3 사업성 판단

초기 시장은 대중 게임 시장이 아니라 철도 운영기관·훈련 기획팀을 대상으로 한 좁은 B2B/B2G 설계 가설이다. 2025년 상반기 안전한국훈련은 103개 기관 주관으로 발표됐지만, 이 숫자를 그대로 구매기관 수나 국내 시장 규모로 사용하지 않는다. [S02]

현실적인 검증 경로는 한 작성팀과 공동 실증을 하고, 실제 검수자를 확보하며, 다음 작성 건에 다시 사용되는지 보는 것이다. 계약 단위(기관·현장·작성자), 유지보수 책임, 보안 배포, 예산은 미확인이다. 연 구독 매출이나 TAM 숫자는 만들지 않았다.

잠재적인 방어력은 버전 관리된 철도 규칙·공간·검수 근거와 운영안-실행-대본 연결 자산이다. 특정 LLM 접근권, 일반 무료 3D 모델, 시뮬레이터라는 이름은 독점적 장점이 아니다. 처음부터 고객마다 완전 맞춤 제작이 필요하면 제품보다는 전문 용역에 가까울 수 있다. 공통 커널과 현장별 설정 비중을 실제 입고에서 측정한다.

## 6. 기술 조사와 구현 가능성

### 6.1 핵심 설계: 운영 판단에 필요한 정확도부터

최신 기술을 모두 연결하는 것이 아니라 사용사례별로 어떤 결과를 믿어야 하는지를 정한다. 기관별 인계 누락은 업무·정보 규칙이 핵심이고, 이동시간 비교에는 기하·이동행동, 연기와 이동의 상호작용에는 검증된 열·연기 모델과 결합이 필요하다. 정밀화는 기술을 단순화한다는 뜻이 아니라 입증할 적용 범위를 좁힌다는 뜻이다.

| 영역 | 근거 있는 후보 | 실제 어려움 | 첫 기술 판정 |
|---|---|---|---|
| 운영·공조 | 이산사건 실행, 시간·유색 Petri net/TAPAAL [S14] | 매뉴얼의 예외·권한·위임을 정확히 모델링 | 지원·보고·인계 한 흐름의 추상모델과 실행 로그 대조 |
| 공간 | 실제 기하 + MapAnything/COLMAP 보조 [S17] | 대상·시점이 맞는 관측과 독립 치수 부족 | 렌더 외관 아닌 연결·축척·핵심 개구 검증 |
| 보행 | JuPedSim 복수 모델 [S13] | 대상 계단·병목·보조이동·인지 차이 | 독립 관측/실험과 이동량·혼잡 지표 비교 |
| 열·연기 | FDS 기준 계산 [S12] | 물성·열원·환기·격자·시간 수렴 및 비용 | 지정 구획·조건에서 검증 후 보행 영향 연결 |
| 도로·차량 | SUMO [S15] | 한국 조건·지원 범위·가상 편의 규칙 | silent teleport 등 결과 왜곡 처리 탐지 |
| 실시간 가속 | ROM/PhysicsNeMo [S16] | 학습자료, 시계열 오차, 보존량, 분포 이탈 | 독립 형상·경계조건에서 정확도/비용 검증 |

이 후보들이 세계 최고이거나 서로 즉시 결합된다는 뜻은 아니다. FDS·Petri net처럼 성숙한 기반과 최신 학습기법을 구분한다. 2026년 현재 문서가 있다는 사실과 제품에서 실행·검증됐다는 사실도 별개다.

### 6.2 단일 도구보다 결합이 더 위험하다

SUMO 긴급차량 문서에는 특정 교차로 상태의 silent teleport가 명시돼 있다. “긴급차량 지원”을 켰다고 한국 현장을 재현한 것은 아니다. 이 예는 기본값을 정밀 모델로 승인하지 말아야 하는 이유다. [S15]

같은 사람의 위치를 Unity와 군중 모델이 동시에 지배하거나, 연기모델의 시간과 업무시간이 어긋나거나, 분기 후 전달 중 메시지가 사라지면 운영안 비교가 무효가 된다. 따라서 필드별 소유자, 단위·좌표·시간, 이벤트 순서, 입력·출력 해시, 모델 상태 복원과 버전 결속이 인터페이스 계약이어야 한다.

가속모델이 기준 solver를 잘 근사하는 것은 모델 간 일치다. 실제 물리현상을 맞추는 검증은 독립 관측·실험과 별도로 수행한다. 단순히 그럴듯한 연기와 사람 애니메이션으로 이를 대체하지 않는다.

NIST 연구는 트윈 신뢰성에 검증·타당화·불확도 평가가 생애주기에 필요하다고 설명한다. 제조 분야 연구이므로 철도 적용의 근거 방법론이지 철도모델 인증이 아니다. [S11]

### 6.3 기술적 성공과 제품적 성공을 분리한다

운영 이벤트가 정확히 기록되고 모델이 돌아가는 기술 시제품은 만들 수 있는 방향이다. 그러나 “현재 현장 수준 정확도”와 “사용자가 더 빨리 좋은 대본 작성”은 각각 별도 실험을 통과해야 한다. 학부 프로젝트라는 이유로 임의 산식을 최종 정확도로 승인하지 않되, 전체 물리모델 완성이 아니면 사용자 검토도 시작하지 못한다는 순환 의존성을 만들지 않는다.

무료 에셋은 시각 제작 구매비를 줄일 후보일 뿐, 기관별 복장·협동 동작·계산 치수·운영 능력·물성·검수 비용을 제거하지 않는다. 공급자 링크가 있는 자산과 실제 Unity 입고된 자산을 구분한다. [S20]

## 8. 반증 가능한 타당성 검증 계획

### 8.1 사용자 발견 — 아직 미실행

제안 표본은 실제 최근 작성 경험이 있는 담당자 6명(가능하면 3개 작성 조직), 기관별 협조·검수자 3명, 자료·정보화 담당자 1명이다. 같은 사람이 중복 역할을 맡으면 독립 표본으로 중복 집계하지 않는다. 시장 크기를 추정하는 통계 표본이 아니라 문제와 흐름을 확인하는 목적이다.

“좋아 보이나요?” 대신 최근 완성한 훈련 한 건의 초기·최종 대본, 변경 이력, 검토 의견, 허용된 일정 기록을 함께 본다. 사용자가 말한 기억과 실제 문서·작업 로그를 구분한다. 훈련 평가자료가 제한되어 있으면 허용된 비식별 사례를 쓰되 현장 수용 근거의 범위를 제한한다.

### 8.2 비교 실험 — 아직 미실행

실제 작성자 8~12명을 대상으로 형성적 교차 실험을 제안한다. 표본 수는 제안이며 안전성·경제성을 입증하는 검정력이 계산된 임상시험 같은 설계가 아니다. 가능한 경우 실제 운영팀별로 확장 확인한다.

A: 고객의 기존 방식과 실제 사용하는 도구.  
B: 동일 자료·같은 AI·같은 규칙과 계산을 사용하는 표/타임라인 중심 시제품, 3D 제외.  
C: 동일 코어에 Unity RTS·공간 보기와 직접 조작을 추가한 CHOOGuard.

B는 제품 전환안이 아니라 3D 조작의 추가 가치를 분리하는 비교군이다. A와 C만 비교하면 AI·구조화·3D 중 어느 기능이 효과를 만들었는지 알기 어렵다.

순서를 균형 배치하고, 같은 정답을 외우지 않도록 난이도를 맞춘 서로 다른 사례를 사용한다. 원문·기관·자원 조건·계산 예산은 가능한 동일하게 유지한다. 사용자 과업 결과는 도구 조건을 가린 검수자가 사전에 정한 기준으로 판정한다. 개발에 쓴 사례와 숨겨 둔 검증 사례를 분리한다.

측정은 총 작업시간, 첫 유효 비교 시간, 검토 후 수정량, 필수 인계·역할·자원 결함의 탐지율/오경보, 공간 오해, 근거 추적성, 조작 부담, 개발자 도움 없이 두 번째 작업을 끝내는지를 포함한다. 화면만 예쁘다는 선호와 실제 품질은 나눠 본다.

### 8.3 사전 고정할 제안 합격·중단 조건

| 검증 | 진행 조건의 제안 | 불충족 시 조치 |

20%·인원수·온보딩 시간 등은 산업 기준이 아니라 제품팀이 시험 전에 합의할 **제안 목표값**이다. 파일을 작성한 시점의 현재 결과는 모두 NOT_RUN/NOT_EVALUATED다. 실패한 실험을 같은 숫자로 계속 반복해 통과할 때까지 선택적으로 보고하지 않는다.

### 8.4 정확도와 현실 전이의 별도 검증

제품 생산성 실험과 실제 대응 적합성 검증을 분리한다. 기하·물성·행동 입력과 uncertainty를 추적하고, 현상별 독립 검증과 solver 결합 검사 후 허용된 도상·시범훈련에서 기관 검토를 받는다. 실제 위험을 일으켜 검증하는 시험이나 운영설비 원격조작은 지시하지 않는다.

좁은 검증범위에서 통과한 결과만 해당 용도로 표시한다. 다른 역사·사고·계절·인력 구성을 자동으로 동일 정확도라고 승인하지 않는다.

## 9. 비평 후 수정한 제품 개요

### 제품명과 한 문장 정의

**CHOOGuard — 철도 비상대응 운영안 설계·검토 실험실**  
반복 합동훈련의 작성 담당자가 실제 공간·매뉴얼·자원 제약 아래 기관별 운영안을 RTS처럼 실행·분기·비교하고, 근거가 연결된 훈련 시나리오·대본으로 전환하는 Unity PC 도구.

### 가치 제안

원하는 결과는 더 많은 문장을 만드는 것이 아니라 **검토 가능한 운영안까지의 총노력과 중대한 공조 모순을 줄이는 것**이다. 현재는 가치 가설이며 실측 성과가 아니다. 작성자는 최종 운영안을 선택하고 기관 검수자가 사용 범위를 승인한다.

### 사용자 여정

검수된 현장·규칙 묶음 열기 → 교육 또는 일반 모드 선택 → 초기 조건 구성 → 팀/차량 또는 업무를 선택해 운영 → 대기·충돌·공조 근거 확인 → A 보존·B 분기 → 같은 조건·변형 조건 비교 → 운영안 선택 → 사람이 검토한 대본·실행형 시나리오 저장.

### 초기 범위

실험용 작은 흐름은 2개 기관·소수 팀부터 시작한다. 제품 실증은 현장 입력과 검수에 맞춰 철도·소방·구급 등 소수 기능의 협조, 하나의 연결된 철도 구간과 지정한 사건 계열로 제한한다. 통합 범위를 작게 잡아도 지원하는 핵심 규칙과 물리 정확도를 임의로 낮추지 않는다.

두 모드는 유지한다. 튜토리얼은 실제 사례 기반 안내·힌트 축소·복기, 일반 모드는 조건부 랜덤 상황과 운영안 비교다. 둘은 같은 운영·물리 코어를 사용한다. 편집·분기·대본 보기는 세 번째 모드가 아니라 공통 기능이다.

### 차별화 가설

국내 철도 매뉴얼의 판본·관할·예외와 기관별 작업을 연결하고, 운영 중 발생한 자원·정보·공간 모순을 설명하며, 수정 운영안과 대본의 일치를 보존한다. 이 연결의 정확성과 실제 작성 효율로 기존 대체재와 비교한다. 단순 3D·AI·디지털 트윈이라는 이름을 차별점으로 쓰지 않는다.

### 시스템 경계

공간/객체 ID → 기관·업무·자원·정보 코어 → 검증된 범위의 보행·열·교통 어댑터 → 실행·분기 기록 → 비교/근거 → 대본. LLM은 설명·규칙 후보·저작을 돕고 운영 결과·기관 승인·물리값의 정본은 아니다. 외부 자료의 지시를 실행 권한으로 받아들이지 않는다.

가정·현실 관측·모델 출력·기관 승인 상태를 별도로 표시한다. 임의의 안전보증·대테러 공격 최적화·전투·실제 설비 제어·VR 장치 시험·자유 건설·수익 경영은 제외한다. 무료 에셋을 쓰되 시각·리깅·물리치수·운영능력은 별도 검수한다.

### 제품 지표

주 지표: 품질 기준을 충족한 대본까지의 총인시, 중요 공조 결함의 잔존·오경보.  
보조 지표: 첫 유효 비교까지의 시간, 수정량, 출처·버전 추적 가능성, 재실행 성공, 두 번째 작업의 자립 사용, 초기비용 회수 가능한 재사용 빈도.  
정확도 지표: 지정 기하·이동·물리 출력의 독립 오차와 유효범위. 실제 피해 감소를 대리지표에서 추정하지 않는다.

### 첫 인계물

허용된 대표 대본과 현장·규칙 묶음 한 개, 사용자가 실제 조작할 수 있는 작은 공간, 요청·배정·보고·인계·자원 점유가 작동하는 운영 코어, A/B 비교와 근거 연결, 검수 가능한 대본 출력, 실패·미실행을 포함한 실행 기록. 거대한 맵이나 대량 애니메이션만으로 완료하지 않는다.
