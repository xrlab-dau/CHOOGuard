# choo guard 요구사항 기준선 v1.1

- 작성일: 2026-09-05
- 상태: 사용자 역질의 완료, KORAIL 회신 대기
- 적용 대상: D-RAIL 「비상대응훈련 VR 프로그램 개발」 대회 MVP
- 팀: xr lab

## 1. 문서의 역할

이 문서는 구현안을 설명하는 설계서가 아니라, 현재까지 확정된 사용자 요구와 아직 확정할 수 없는 항목을 분리하는 기준선이다.

### 요구사항 권위

1. 현재 대회 MVP의 제품 범위는 소크라테스식 역질의로 사용자가 확정한 이 기준선을 따른다.
2. KORAIL은 촬영·자료 취급·보안·실제 직무·공식 매뉴얼과 운영환경의 권위 주체이며, 해당 행위에는 KORAIL의 최신 서면 조건을 적용한다.
3. KORAIL 답변이 현재 MVP 제품 범위의 확대·축소·교체를 요구하면 영향과 대안을 기록하고, 사용자 승인 후 기준선·아키텍처·백로그를 함께 개정한다. 답변만으로 MVP 범위를 자동 변경하지 않는다.
4. 폐쇄망, 실제 네트워크, 보안자료 처리, 실제 직무·매뉴얼 관련 미결정은 팀이 임의 확정하지 않는다.
5. 요구가 바뀌면 변경 사유, 승인자, 영향 범위, 대체된 요구사항 ID와 새 문서 버전을 기록한다.

## 2. 용어와 범위

| 용어 | 정의 |
|---|---|
| 대회 MVP | 심사에서 사용자 흐름과 기술 가능성을 보여 주는 실행 가능한 시연본 |
| 운영판 | KORAIL의 실제 자료·장비·폐쇄망 정책을 반영해 검수하는 후속 제품 |
| 대표 직무 | 시작부터 행동·팀 상태·피드백까지 전체 흐름을 시연하는 한 개 직무 |
| 나머지 직무 | 각 직무를 구분하는 핵심 행동 한 개가 VR·Desktop에서 동작하는 네 개 직무 |
| MVP 실제 조작자 | 한 실행 인스턴스에서 VR 또는 Desktop으로 조작하는 1명의 사용자 |
| 가상 팀 상태 | 실제 네트워크 접속 없이 최대 5개 역할의 진행·보고·인계를 시뮬레이션한 상태 |
| 공식 평가 | KORAIL 승인 매뉴얼과 평가기준에 근거한 점수 또는 이수 판정. MVP에는 포함하지 않음 |

## 3. 확정된 제품 요구사항

### 3.1 목적과 사용자

| ID | 요구사항 |
|---|---|
| BR-01 | 이번 단계의 성공은 대회 시연 성공으로 판단한다. 폐쇄망 운영 검증은 MVP 성공 조건이 아니다. |
| BR-02 | 핵심 사용자는 비상대응훈련에 참여하는 KORAIL 직원이다. |
| BR-03 | 실제 공간 기반 맵, 싱글·멀티 지원, 3D Flat Art 표현은 제품의 장기 방향이다. 단, MVP의 ‘멀티’는 실제 접속 기능이 아니라 가상 팀 상태로만 표현한다. |
| BR-04 | 직무 선택은 실제 소속과 무관하게 자유롭게 제공한다. |
| BR-05 | VR 사용이 어렵거나 장비가 부족한 사용자를 위해 Desktop 모드를 MVP부터 제공한다. |

### 3.2 MVP 콘텐츠

| ID | 요구사항 |
|---|---|
| FR-01 | MVP는 1개 맵, 1개 역사 대피 상황, 5개 임시 직무로 구성한다. |
| FR-02 | 5개 직무 체계는 유지하되 명칭과 책임은 임시이며 KORAIL 회신 후 교체할 수 있어야 한다. |
| FR-03 | 대표 직무 한 개는 역할 선택부터 사후 피드백까지 전체 흐름을 완주할 수 있어야 한다. |
| FR-04 | 나머지 네 직무는 각각 핵심 행동 한 개가 VR과 Desktop에서 실제 동작해야 한다. |
| FR-05 | VR과 Desktop은 입력 방식이 달라도 같은 핵심 퀘스트 상태와 피드백을 사용해야 한다. |
| FR-06 | 개인 숙달용 직무 퀘스트와 팀 협업용 연결 퀘스트를 모두 표현할 수 있어야 한다. |
| FR-07 | MVP의 멀티플레이는 실제 네트워크 연결이 아니라 가상 팀원의 상태·보고·인계 변화로 사용자 흐름을 시연한다. |
| FR-08 | 싱글플레이에서는 빈 직무를 NPC가 대신하지 않는다. 다른 직무 절차를 싱글용으로 단순화한다. |
| FR-09 | KORAIL 검수 전에는 공식 점수·이수 판정을 제공하지 않고 수행 행동에 대한 설명형 피드백만 제공한다. |
| FR-10 | 공식 매뉴얼을 받지 못하면 가상 자료를 사용하되 ‘KORAIL 검증 전 예시’임을 화면과 문서에 표시한다. |

### 3.3 맵과 촬영

| ID | 요구사항 |
|---|---|
| MAP-01 | MVP 플레이 맵은 역사 내부를 직접 촬영한 자료를 공간 근거로 사용한다. |
| MAP-02 | 촬영은 KORAIL 또는 역사 운영 주체의 사전 서면 승인 후, 승인된 구역·기기·시간·용도 안에서만 수행한다. |
| MAP-03 | 승인 전에는 역사 촬영을 시작하거나 자료를 저장소에 반입하지 않는다. |
| MAP-04 | 촬영 이미지에 DA3·Open3D 파이프라인을 적용하고, 결과를 경량 3D Flat Art 플레이 맵으로 변환한다. |
| MAP-05 | 맵 제작 파이프라인은 별도의 사용자 기능이나 독립 데모가 아니라 게임에서 플레이되는 맵을 만드는 내부 작업이다. |
| MAP-06 | MVP는 주요 구역·출입구·이동 동선의 구조를 우선한다. 운영판은 안전설비 위치와 치수 정확도를 KORAIL 기준으로 추가 검수한다. |
| MAP-07 | 고성능 DA3 가중치는 비상업 대회 시연으로 제한한다. 실제 사용 전 체크포인트 ID·리비전·가중치 해시·라이선스 URL·변경 여부·필수 고지를 기록하고, 대회 이용약관과 사용 목적이 비상업 조건에 부합하는지 확인한다. 운영 전에는 권리자 허가를 받거나 허용 가능한 모델로 교체한다. |

### 3.4 실행과 성능

| ID | 요구사항 |
|---|---|
| RUN-01 | MVP 최종 실행물은 Unity 기반 VR 실행본과 실제 플레이 가능한 Desktop 실행 경로를 포함한다. |
| RUN-02 | MVP의 실제 조작자는 실행 인스턴스당 1명이다. 화면과 가상 팀 상태는 최대 5개 역할을 표현하지만 네트워크 멀티플레이를 구현하지 않는다. |
| RUN-03 | 운영판의 실제 동시 사용자 규모, 네트워크 방식, 서버 구조는 KORAIL 회신 후 결정한다. |
| RUN-04 | MVP 성능은 합격선으로 차단하지 않고 개발 PC에서 프레임·프레임시간·메모리를 측정해 기록한다. |
| RUN-05 | 코레일 장비에 대한 저사양 대응, 품질 프로필, 최소 사양은 실제 장비 정보 수신 후 결정한다. |

## 4. MVP 비목표

다음 항목은 대회 MVP에 포함하지 않는다.

- 실제 2~5인 네트워크 멀티플레이
- 전용 서버, 세션 할당기, 조직 단위 동시접속 확장
- NPC가 빈 직무를 수행하는 싱글플레이
- KORAIL SSO·HR·LMS 연동
- 공식 점수, 이수·인증, 인사평가 연계
- 폐쇄망 설치·업데이트 방식의 확정
- 실제 설비 위치·치수의 운영 수준 정밀 검증
- KORAIL 승인 전 실제 절차라고 주장하는 콘텐츠

## 5. MVP 수용 기준

### P0 시연 기준

1. Unity 실행본에서 역사 대피 시나리오 맵에 진입할 수 있다.
2. 5개 임시 직무가 표시되고 자유롭게 선택할 수 있다.
3. 대표 직무 한 개는 `역할 선택 → 안내 → 핵심 행동 → 가상 팀 상태 변화 → 사후 피드백`을 중단 없이 완주한다.
4. 나머지 네 직무는 각각 한 개의 구별되는 핵심 행동이 VR과 Desktop에서 동작한다.
5. 같은 핵심 행동을 VR과 Desktop에서 수행했을 때 퀘스트 완료 상태와 피드백 의미가 일치한다.
6. 대표 직무의 행동에 따라 다른 직무의 가상 상태·보고·인계가 변한다.
7. 결과 화면은 공식 점수 대신 수행·누락·팀 상태에 대한 설명형 피드백을 제공한다.
8. 가상 절차를 사용하는 경우 ‘KORAIL 검증 전 예시’ 표시가 보인다.
9. 판정용 역할 행동 확인표가 존재하며 각 행에 `역할 ID / 대표 여부 / 행동 ID / 대상 Anchor / 사전 상태 / 기대 Quest 상태 / 기대 가상 팀 이벤트 / 피드백 의미`가 정의되어 있다. VR·Desktop은 같은 행의 기대 결과를 공유한다.

### P1 필수 증거 기준

P1은 선택 사항이 아니다. P0 시연 기준과 함께 모두 충족해야 MVP를 완료로 판정한다. 단, 성능 수치에는 합격선을 두지 않고 측정·기록의 존재와 재현 가능성만 확인한다.

1. 승인된 역사 촬영 자료에서 맵을 생성한 처리 이력과 입력·출력 해시를 남긴다.
2. DA3 가중치와 외부 에셋의 출처·버전·라이선스를 기록한다.
3. VR·Desktop 각각의 실행 영상 또는 연속 화면 캡처를 남긴다.
4. 프레임·프레임시간·메모리 측정값을 장비 사양과 함께 기록한다.
5. 자동 테스트, Unity 로그, 독립 에이전트 검토 결과를 작업 실행 기록에 연결한다.

## 7. 기존 v3와의 충돌

| v3 가정 | 새 기준선 |
|---|---|
| 싱글에서 빈 직무를 NPC가 수행 | MVP 싱글은 절차를 단순화하며 NPC를 사용하지 않음 |
| MVP부터 실제 멀티플레이·서버 권위 구조 | MVP는 가상 팀 상태만 시연, 실제 네트워크는 후속 |
| 전용 서버·SSO·LMS·조직 제어면 제안 | KORAIL 회신 전 미결정이며 MVP 비목표 |
| PC VR 72 FPS를 합격 기준으로 사용 | MVP는 성능을 측정·기록하되 합격선을 두지 않음 |
| 5개 직무의 구체 명칭과 퀘스트를 사실상 확정 | 역할 수만 유지하고 명칭·책임은 임시 |
| 운영 수준 지도·보안 배포 구조를 선행 확정 | MVP는 승인 촬영 기반 플레이 맵에 집중하고 운영 구조는 회신 후 결정 |

## 8. 변경 규칙

- KORAIL 회신을 받으면 O-항목을 갱신하고 영향 분석을 작성한다. 촬영·자료·보안 조건은 해당 행위에 즉시 적용하되, 제품 범위 변경은 사용자 승인 후 반영한다.
- ‘확정’ 요구사항을 변경할 때는 변경 사유, 대체안, 승인자와 영향을 받는 테스트·검토·산출물 해시를 기록한다.
- PM 통합 또는 후속 수정으로 검토 대상 해시가 바뀌면 영향을 받은 테스트와 독립 검토를 다시 수행한다.
- 구현 편의를 위해 요구사항을 임의 축소하지 않는다.
- 구현안은 요구사항이 아니다. 기술은 교체 가능하지만 사용자 행동과 수용 기준은 별도 승인 없이 바꾸지 않는다.
