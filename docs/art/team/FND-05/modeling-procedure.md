## 0. 한 줄 요약

공개된 층별 평면도·안내도에서 **읽을 수 있는 것**(층 소속, 상대 연결, 운영자가 공표한 수치)과 **읽을 수 없는 것**(치수·축척·설비 사양)을 분리 기록하고, 확정된 앵커 위에만 블록아웃을 세운 뒤, 그 블록아웃의 축척을 검사해 통과한 것만 다음 단계로 승격한다.

## 1. 용어와 표기 등급

| 표기 | 의미 | 축척 근거로 쓸 수 있는가 |
| --- | --- | --- |
| `confirmed_public_measure` | 운영자/공공기관이 문서·안내 페이지에 **수치와 단위를 함께** 공표한 값. `surveyedByProject=false` 이며 프로젝트 현장 측량값이 아니다. | 예 (해당 구역 범위 안에서만) |
| `estimated_synthetic_measure` | 공개 자료에 수치가 없어 상대 구성·단일 앵커에서 유도했거나 게임 요구로 저작한 값. | 아니오 |
| `prohibited_measure` | 출처가 없거나 원문과 산술 불일치하여 수치로 쓰지 않기로 한 값. | 아니오 (기록만) |

값을 기록할 때 항상 **출처 ID · 값 · 단위 · 등급 · 취득일** 다섯 항목을 함께 남긴다. 하나라도 비면 그 값은 `estimated_synthetic_measure` 로 내린다.

## 2. 평면도 판독 절차

### 2.1 도면 종류 판별 (순서대로)

1. **층 구분** — 도면이 어느 층인지, 숫자 층(B1/B2) 표기가 있는지 확인한다. 표기가 없으면 "층 번호 미확인"으로 기록하고 임의로 B1 을 부여하지 않는다.
2. **도면 종류** — 아래 중 하나로 분류한다.
   - `plan` (평면도): 벽선·개구부가 축척으로 그려짐
   - `layout` (배치도): 외곽·기둥열 중심
   - `section` (단면): 높이 관계
   - `schematic` (안내도): 도식, 축척 없음
   - `exploded` (투시/조감): 상대 구성만
   - `masterplan` (계획도): 계획 단계, 준공도면 아님
3. **축척 표기 유무** — 축척표·축척자·치수선 중 하나라도 있으면 `scalePresent=true`. 없으면 §4(축척 없는 이미지의 한계)로 간다.
4. **이미지 출처·취득일·라이선스 기록** — 출처 ID, URL, sha256, 취득일, 라이선스 ID. sha256 이 없는 온라인 문서는 열람일과 색인 경로를 남긴다.
5. **운영자 일치성** — 같은 공간을 다루는 두 출처가 다른 번호·개정을 말하면(예: 출구 1~7 도식 vs 8·10번 출구 안내) **버전 일치가 확인되기 전까지 어느 쪽도 좌표 근거로 쓰지 않는다.**

### 2.2 읽어도 되는 것 / 읽으면 안 되는 것

읽어도 되는 것:

- 층 소속 (이 도면은 2층 맞이방이다)
- 설비의 상대 연결 (대합실 → 계단 → 상대식 승강장)
- 운영자가 수치로 공표한 항목 (지하연결통로 길이 99.6 m, 폭 8.0 m)

읽으면 안 되는 것:

- **화면 배율·원근에서 환산한 치수.** 이미지 픽셀 비율로 계산한 값은 실측이 아니다. 기록은 하되 등급은 반드시 `estimated_synthetic_measure` 로 두고 "화면 배율 환산"이라고 적는다.
- 한 층 도면의 형상을 다른 층에 같은 평면으로 옮기는 것.
- 다른 운영자 시설을 같은 층번호라는 이유로 같은 공간으로 합치는 것.
- 안내용 투시도를 실측 CAD 로 변환했다고 주장하는 것.

## 3. 승격 순서 (각 단계에서 확정/추정을 분리 표기)

```
층별 평면도 (판독)
  → 구역 경계·동선 (매핑)         ← #70 구역 ID 에 매핑, confirmed/estimated 분리
  → 블록아웃 (box geometry)       ← 확정 앵커 위에만 세움
  → 상세 모델 (meshes/props)      ← 블록아웃 축척 검사 통과 후
```

각 단계의 산출물에는 **확정 목록과 추정 목록을 따로** 적는다. 확정 목록이 비어 있으면 다음 단계로 승격하지 않는다.

### 3.1 매핑 산출물 형식

평면도 층 ↔ #70 구역 ID ↔ portal 연결을 한 표로 만든다. 각 행에:

| 항목 | 필수 |
| --- | --- |
| `sourceRef` (P01~P09 또는 null) | 예 |
| `regionId` (#70 구역 ID) | 예 |
| `result` (`공개 평면도로 확정` / `공개 자료로도 미확정`) | 예 |
| `confirmedAspect` / `unconfirmedAspect` | 예 |

`공개 평면도로 확정` 은 **층 소속 또는 운영자 공표 수치까지만** 뜻한다. 평면 형상·치수가 확정되었다는 뜻이 아니다.

### 3.2 파일럿 결과 (1구역)

- 구역: `underground_connector` (부산역 지하연결통로)
- 앵커: 길이 99.6 m, 폭 8.0 m — P04, `confirmed_public_measure`
- 추정: 높이 3.2 m, 바닥고 Y=-4.0 m, portal 개구 3.2×2.7 m — `estimated_synthetic_measure`
- 검사: `python3 scripts/art/team/FND-05/blockout_pilot.py --check` (스키마·치수·정렬·portal 경계), `--test` (단위 테스트)

## 4. 축척 없는 이미지의 한계 — 배율 잡는 규칙

1. **기준 치수(anchor)는 `confirmed_public_measure` 에서만 가져온다.** 승강장 길이·궤간·계단 폭처럼 "공개된 알려진 값"을 쓰려면 그 값의 출처 ID 와 공표 주체를 먼저 확인한다. 이 저장소에서 현재 그 자격을 가진 값은 **P04 의 99.6 m · 8.0 m 뿐**이다.
2. **앵커의 적용 범위를 넘기지 않는다.** P04 값은 `underground_connector` 구역 안에서만 쓴다. 맞이방·승강장·광장의 축척 근거로 전이하지 않는다(`notScaleAnchorFor` 목록).
3. **배율을 잡은 결과는 항상 `synthetic_design` 으로 표기한다.** 배율로 만든 형상이 공표 수치와 일치해도 실측이 아니다.
4. **사진 원근에서 계산한 값은 실측으로 기록하지 않는다.** 원근 보정값은 `estimated_synthetic_measure` 이며, 산출 근거란에 "사진 원근 환산"이라고 쓴다.
5. **앵커가 없는 구역**은 무허용 오차 `0.50 m`(상대 5%)로 저작하고, 배치가 게임 요구에서 나왔다고 명시한다.
6. **검사 오차**

| 등급 | 절대 | 상대 | 근거 |
| --- | --- | --- | --- |
| `confirmed_public_measure` | 0.05 m | 0.1% | 공표값의 0.1 m 단위 반올림 |
| `estimated_synthetic_measure` | 0.10 m | 2% | 앵커 정렬 블록아웃 |
| `estimated_synthetic_measure_unanchored` | 0.50 m | 5% | 앵커 없는 저작 배치 |
| 각도 | 0.5° | — | — |

7. **블록아웃 축척 검사**는 최소한 다음을 확인한다.
   - 생성 메시의 X/Y/Z 범위가 구역 `worldBounds` 안에 들어간다.
   - 앵커 치수와 메시 치수의 차이가 해당 등급 오차 이내다.
   - 길이/폭 비율이 공표 비율(12.45)과 허용 오차 이내로 일치한다.
   - 메시는 1:1 스케일(1 단위 = 1 m)이며 단위 변환 계수를 적용하지 않는다.
   - portal 끝점이 구역 경계면(끝단 캡·측벽)에 정확히 놓인다.

## 5. 금지 사항 (prohibited practices)

1. 치수를 **발명하지 않는다.** 공개 자료에 없는 수치는 저작값이며 `estimated_synthetic_measure`/`synthetic_design_not_surveyed` 로 표기한다.
2. **역·운영자를 넘어 평면도를 혼합하지 않는다.** KORAIL 역사 도면을 도시철도 대합실에, 유라시아플랫폼 도면을 KORAIL 맞이방에 쓰지 않는다.
3. **층을 넘어 평면도를 재사용하지 않는다.** 1층 자료를 2층 맞이방에 같은 평면으로 적용하지 않는다.
4. **개정이 다른 자료를 합치지 않는다.** 2003 계획·2014 임대 배치를 현재 준공도면으로 쓰지 않는다. 출구 번호 불일치(P03 1~7 vs P04/P09 8·10)는 해소 전까지 좌표 근거가 아니다.
5. **화면 배율·원근 환산값을 실측으로 표기하지 않는다.**
6. **산술 불일치 수치를 쓰지 않는다.** P07 의 7.5×7.5 m 와 57.76 m2 는 제외한다.
7. **비공개 설비 사양·내부 운영 규정을 확정값으로 쓰지 않는다.**
8. **실행하지 않은 검사·재구성을 PASS 로 표시하지 않는다.**
9. **원본 이미지를 저장소·이슈·외부 생성 API 에 넣지 않는다.**
10. **`accepted`/`final`/`complete` 로 자기 선언하지 않는다.** PM 검토를 거친다.

## 6. 권리·공개 라이선스 준수

### 6.1 공공누리 제4유형 (KOGL Type 4)

P02(`도면_경부선_부산역_141231.pdf`)에는 공공누리 제4유형 표시가 있다. 제4유형 조건:

- **출처표시** — 이용 시 출처를 밝힌다.
- **상업적 이용금지** — 상업적 목적으로 이용하지 않는다.
- **변경금지** — 원본을 변경·개작하지 않는다.

제4유형은 **2차적 저작물 작성이 금지**되므로, 원본 도면을 잘라 쓰거나 변형·합성·복제 배포할 수 없다. FND-05 는 원본을 변형하지 않고 **사람이 읽어 수치·서술만 추출**한다.

### 6.2 이 저장소의 운영 규칙

1. **원본 이미지 자체는 저장소에 넣지 않는다.** (#119 완료 기준)
2. 모든 출처에 대해 이미지 파일이 아닌 **메타데이터만** 저장한다: 출처 ID, 제목, 운영자, URL, sha256, 문서일, 라이선스 ID, 사용 가능 제약, 한계.
3. 라이선스가 **미확인**인 자료(P01, P03~P09)는 `metadata_only` 로 기록하고 재배포·변형을 추정하지 않는다.
4. `All Rights Reserved` 표시 자료(P03, P04)는 열람·수치 인용까지만 하고 이미지 재사용을 가정하지 않는다.
5. 라이선스가 확인된 자료도 **외부 LLM·생성 API 로 원본을 전송하지 않는다.**
6. 차량 제원·weights·제한 geometry·credentials/Unity secrets 는 Git/이슈에 넣지 않는다.
7. 저장소에 남기는 수치는 운영자 공표값이며, 그 사실(`surveyedByProject=false`)을 값 옆에 적는다.

### 6.3 라이선스 확인 체크리스트

- [ ] 출처 ID 와 라이선스 ID 를 매핑 JSON 에 적었다.
- [ ] KOGL 유형이면 유형 번호와 3개 조건(출처표시/상업적 이용금지/변경금지)을 적었다.
- [ ] 원본 이미지가 저장소에 없음을 확인했다.
- [ ] 변경금지 조건이면 원본을 변형·합성하지 않았음을 확인했다.
- [ ] 라이선스 미확인 자료는 `unverified` 로 표기했다.

## 10. 이번 검토의 반증된 가정 (증거 없는 질문)

- "공개된 층마다 평면 도면이 있다"는 전제는 **P04(지하연결통로) 1건에서만** 수치로 확인됐다. 나머지 12구역은 도식·시설목록·투시도이며 치수가 없다. 전체 13구역에 같은 방법을 적용할 수 있다고 가정하지 않는다.
- "1년 전 다른 팀이 공개 평면도로 3D 모델을 만들었다"는 사용자 진술은 그 팀의 입력·허가·정확도를 이 저장소에서 검증할 수 없다. 이 절차는 그 경로를 **어떤 조건에서 허용하는지**만 규정한다.
