# Pi 도구 체인 인계와 M0-00 사람 검사 계획

> M0-00은 사람이 실행한다. 이 문서는 에이전트 보조 초안이며 실행 승인·서명·완료 영수증이 아니다. 자동 실행용 계획으로 사용하지 않는다.

**Goal:** 검토용 공개 산출물을 Git으로 전달하고, 별도 승인된 사람 검사로 local과 school-pc의 M0-00 선행 조건을 확인한다.

**Architecture:** 문서·도구 후보의 인계와 실제 설치·실행을 분리한다. 현 검증기의 누락·덮어쓰기·실패 종료 결함을 먼저 회귀 시험으로 보완해야 한다. 위생 검사와 자료 분류·OS 실행 경계의 증거는 별개다.

**Tech Stack:** Git, GitHub CLI, 관리자가 확인한 Python 실행기, Pi 0.85.0 및 ADR 0002의 후보 도구.

**Spec:** [명세 001](../../../specs/001-m0-00-safe-bootstrap/spec.md). [명세 004](../../../specs/004-m0-03-ai-tool-allowlist/spec.md)와 [학교 PC 절차](../../choo-guard-school-pc-bootstrap-v1.md)를 함께 따른다.

## Global Constraints

- 호스트명·개인 계정·비밀값·실제 자료 경로를 공개 기록에 넣지 않는다. machine-label은 local 또는 school-pc다.
- AGENTS.md, .pi, .specify/memory, scripts/ci, .github, docs/evidence 변경은 PM 승인 뒤 사람이 한다. 이 계획은 그 승인이 아니다.
- main/develop 직접 푸시·자동 PR 생성·승인 없는 병합·삭제·권한 변경 금지.
- 학교 PC 자료·네트워크·설치·로그인은 기본 비허용이다. 승인 유형을 서로 대체하지 않는다.
- 기존 증거는 덮어쓰지 않는다. 문서 작성에 에이전트가 사용됐으므로 고정 문구로 “에이전트 없음”을 서명하지 않는다.
- 스크립트 실행이 차단됐으면 미실행으로 기록한다. 예상 실패는 RED 증거가 아니며 구문 검사만으로 GREEN을 주장하지 않는다.

## Task 1: 공개 초안 전달

**대상:** README, specs, 발견 기록, ADR, 운영 문서, 정제 검토 기록. 새 도구·vendored 파일·보호 경로는 소스·라이선스·고지·승인 확인 후 별도 전달한다.

- [ ] 현재 브랜치와 tracked/untracked diff를 모두 확인한다. ignored 자격·캐시는 열거나 포함하지 않는다.
- [ ] 파일 분류·라이선스·비밀 탐지 결과를 확인한다. 비밀 탐지는 매치 내용 대신 경로·수만 보고하며 실패 원문을 출력하지 않는다.
- [ ] 검토된 경로만 명시적으로 stage한다. staged diff와 검사 결과를 재확인한다. 무조건 `git add .`를 하지 않는다.
- [ ] Conventional Commit으로 작업 브랜치에 커밋하고 사용자가 요청한 브랜치로 push한다. 실패하면 전달 미완료로 남긴다.
- [ ] 원격 커밋에 필요한 파일이 있는지 확인한다. 보호 설정·라이선스가 미검토면 설치 가능한 번들로 표시하지 않는다.

읽기 전용 확인 명령:

```bash
git branch --show-current
git status --short
git diff --check
git diff --cached --check
git diff --cached --stat
```

## Task 2: 검증기 보완의 선행 게이트

**대상:** scripts/bootstrap의 검증기·POSIX/PowerShell wrapper·회귀 테스트. CI와 Pi 보호 설정 변경은 별도 승인 대상이다.

- [ ] 먼저 합성 fixture 테스트를 실행해 실제 RED를 관측한다. 현재 테스트 파일의 존재만으로 이 항목을 체크하지 않는다.
- [ ] git 실패·필수 uv/환경 누락·비정상 버전·중첩 자격·대소문자 확장자·외부 링크·재귀 설정 키·라벨·경로 이탈·기존 파일 덮어쓰기의 거부를 구현·시험한다.
- [ ] 기본 무설치·무네트워크, native 종료 코드 전달, Python 부재 실패를 POSIX와 PowerShell에서 검증한다.
- [ ] 정책 해시 단일 출처·필수 누락 실패·target 귀속·정책 검사 결과를 검증한다. mount/junction·자료 분류는 별도 사람/OS 증거로 남긴다.
- [ ] 변경 전후 같은 테스트의 결과·범위·coverage를 보존하고 다른 제공자의 독립 검토를 받는다.

실제 실행할 회귀 테스트 명령:

```bash
python3 -m unittest discover -s scripts/bootstrap -p 'test_*.py' -v
```

Windows는 관리자가 확인한 Python 실행기에 맞춰 동일 unittest 인수를 사용한다. 테스트가 실행되지 않으면 코드 수정·합격 판정은 보류한다. 현 `--write`는 이 작업 완료 전 사용하지 않는다.

## Task 3: local·school-pc 사람 정적 검사

**사람 생성 산출물:** 명세 001의 verify 기록, 분류 manifest와 hash, school-pc-environment 기록. 기존 이름이 있으면 새 실행 식별자를 붙이며 덮어쓰지 않는다.

- [ ] 두 머신의 실행 대상 전체 커밋과 파일 manifest를 고정한다. 학교 PC에는 Task 1의 실제 원격 전달과 별도 실행 승인이 먼저 필요하다.
- [ ] 추적·비추적·ignored 에이전트 가시 입력을 PUBLIC_SYNTHETIC 분류 목록과 대조한다. 실제 자격 내용은 읽지 않는다.
- [ ] 사람이 승인된 Python으로 기존 저장소 위생 검사를 실행하고 종료 코드·출력 요약·검사기 hash를 기록한다. 범위 밖 자격·자료가 안전하다는 결론으로 확대하지 않는다.
- [ ] POSIX mount와 Windows reparse point·junction·volume을 사람이 대조한다. .pi/npm·가상환경 루트 링크를 이름만으로 제외하지 않는다. 읽기 실패는 미검증이다.
- [ ] D-01~D-09를 비공개 환경 기록으로 확정한다. 공개 school-pc-environment 문서에는 항목 ID·결정 역할·상태·증거 hash만 두고 실제 호스트·계정·목적지 매핑은 복사하지 않는다.
- [ ] 미분류·검사 실패·미승인 프로파일이 있으면 M0-00과 다음 실행 게이트를 보류한다.

검사 예시:

```bash
python3 scripts/ci/repository_policy.py
```

현 스크립트는 전체 명세의 자료 분류·mount·자격 보호를 증명하지 못한다. 이것은 부분 위생 검사의 종료 코드를 얻는 명령이다.

## Task 4: 소유권과 승인 역할 확정

**사람 변경 대상:** .github/CODEOWNERS와 승인된 docs/evidence/M0-00 기록. 공개 문서에는 개인 로그인을 하드코딩하지 않는다.

- [ ] PM이 최소 보호 경로 및 ADR·조사 코드·기록의 추가 보호 범위를 결정한다.
- [ ] 자료 접근, 모델 전송, 공개·병합 각각의 승인 역할과 대체자를 지정한다. 개인 매핑은 GitHub 또는 비공개 기록에 둔다.
- [ ] 사람이 승인된 리드 계정을 GitHub CODEOWNERS에 반영한다. 전역 팀 규칙과 마지막 일치 규칙을 실제 경로별로 검사한다.
- [ ] 작성·검토·조사·reducer·verifier의 허용 모델과 실제 호출 검증 위치를 기록한다. 설정 선언만으로 강제 완료라 하지 않는다.
- [ ] 보호 변경 자체도 독립 팀 검토·필수 검사·PM 승인 절차를 거친다.

## Task 5: 전체 해시·증거·사람 서명

**사람 생성 대상:** baseline.sha256, review-providers.md, signoff의 새 실행 기록. 최초 파일이 있으면 새 이름을 사용한다.

- [ ] 보완·검토된 POLICY_GLOBS를 단일 출처로 사용한다. Pi prompts·CODEOWNERS·GitHub workflows·ADR·bootstrap·research·추적 dependency manifest/lock을 빠뜨리지 않는다.
- [ ] 필수 파일 누락·읽기 실패를 실패로 처리하고 상대 경로 정렬 SHA-256을 두 번 생성해 비교한다. 단일 AGENTS hash 비교만으로 전체 일치를 주장하지 않는다.
- [ ] 검토 대상·검사 결과·정제 판정의 hash 연결을 확인한다. 사후 hash로 초기 manifest 부재를 숨기지 않는다.
- [ ] 사람이 실제 확인한 FR-001~007, 날짜, 커밋, 역할, 비공개 승인 원본 참조의 비식별 ID를 서명한다. 공개 파일은 개인 이름·로그인 대신 승인 역할을 쓴다.
- [ ] 에이전트 보조 초안·미실행·unknown·학교 PC 미검증을 그대로 남긴다. 변경이 생기면 영향 검증과 독립 재검토 후 새 서명을 받는다.

## Task 6: 사람 PR과 운영 승인

- [ ] 사람이 PR을 만들고 변경 범위·명세·검증·미결·판정 기록을 본문에 연결한다. 이 실행 계획을 그대로 PR 본문으로 사용하지 않는다.
- [ ] PR 작성자와 다른 팀원의 CODEOWNER 승인과 필수 검사 통과를 확인한다.
- [ ] PM 승인 후 develop에 squash 병합한다. 병합은 모델 전송·학교 PC 설치·자료 접근 승인을 대신하지 않는다.
- [ ] M0-03, M1-02~07의 해당 실행 경계와 공급망 검증이 끝난 프로파일에만 설치·trust·로그인·워크플로 실행을 허용한다.

현재는 검토 지적을 반영한 계획 초안이다. 테스트 실행·학교 PC 확인·권한 승인·실제 공급망 검증·독립 재검토가 미완료다. 계획을 작성했다는 이유로 이 작업들을 완료 처리하지 않는다.
