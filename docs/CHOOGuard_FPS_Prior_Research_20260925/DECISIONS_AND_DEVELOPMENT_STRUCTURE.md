# 사용자 결정과 CHOOGuard 개발 구조

기준: 2026-09-25 대화·선행조사. **요구 구조와 개발 의존관계의 정리이며, 구현 완료나 전체 일정·패키지 도입 승인이 아니다.** 기존 계획·active plan·graph·모델링 파일을 변경하지 않는다.

**현재 제품: FPS 기반 비상상황 대응 시뮬레이션 게임.** 한 명의 인간이 정비·청소·승무·역무를 전환하며 수백 명의 자율 NPC와 공유 세계에서 대응한다. 변화한 현재 상태와 플레이어/NPC의 행동을 바탕으로 JEV 추론을 매 단계 합성해 미래상황을 만들고 다시 예측한다. 완성 사건 pack 선택이나 NPC 행동 선택만으로 좁히지 않는다. 최신 규범 설계는 [DESIGN](../CHOOGuard_Story_Plan_v5/design/fps-ai-20260925/DESIGN.md), [자율 NPC·동적 미래](../CHOOGuard_Story_Plan_v5/design/fps-ai-20260925/NPC_SCENARIO.md), [OSS 경계](../CHOOGuard_Story_Plan_v5/design/fps-ai-20260925/OSS_INTEGRATION.md)를 따른다. 아래 기존 발언·실측 이력은 보존하되 후속 사용자 정정이 제품 해석에 우선한다.

## 1. 역질의 결정 원장

### 1차: FPS와 AI 월드의 의미

| 질문 | 사용자 선택 | 반영 |

| AI 월드 | 시민 자율생활·대화 / AI 사건 구성 / 행동학습·실험 | 생성영상·생성공간은 본게임의 필수 기반이 아님 |

### 3차: JEV의 실제 능력과 제품 경계

| 질문 | 사용자 선택 | 반영 |
|---|---|---|
| 대화 | JEV + 별도 대화 모델 | JEV 판단과 생성 대사를 분리 |
| 학습 | 경험·기억 변화 + 별도 정책 학습 연구, 둘 다 | 외부 기억과 외부 학습기를 구분; JEV 자체 fine-tuning으로 표현하지 않음 |
| NPC 규모 | 수백 명 | 인물별 상태는 유지하되 전원 고빈도 API 호출을 전제하지 않음 |
| 연결 | 온라인 연결 허용 | JEV 원격 API 사용 가능. 지연·단절 시 행동 지속/보류 처리는 필요 |

인증을 위한 별도 질문의 비밀 값은 이 원장에 기록하지 않았다.

### JEV에 위임한 질문의 실제 응답

- 모델: `jev-1.13.0`, 실제 응답 556ms.
- 선택: **shared_truth_flexible_presentation**.
- 의미: **작업·권한·선행조건·완료 판정의 일관성은 유지하고, 표현·피드백·일상 행동·진행 속도는 플레이에 맞게 조정**.
- 선택 확률 0.95, confidence 0.93. 이는 조언의 분포이지 성공률이나 사용자 승인 확률이 아니다.
- [질문](JEV_PRIORITY_INPUT.json), [원응답](jev-live/jev-priority-20260925.result.json).

이하에서는 이를 **연구상 기본 원칙**으로 사용한다. 미확보된 안전 수치를 임의로 만들어도 된다는 뜻은 아니다. 최종 전문 절차 검수와 사용자 우선순위 변경을 막는 절대 규칙으로도 취급하지 않는다.

| 정보 경계 | 개인의 관측과 기억만 NPC 질문/계획에 들어간다. 다른 사람의 판단이나 숨은 세계 사실을 공유하지 않는다. 답을 받는 동안 전제가 바뀌었으면 오래된 계획을 적용하지 않는다 |
| 비용 | 기존 공통 예산 $3/시간·1,000요청/분을 유지한다. 디렉터 $1/시간은 예약 몫이지 별도 상한이 아니며 공통 여유를 빌릴 수 있다. 비용 절약을 위해 live 사건 판단을 고정 사건 일정으로 대체하지 않는다 |
| 팀원 PR #264 | 국소 NavMesh 측정 도구와 변경 파일 겹침은 없고 전역 자산과 컴파일·측정 호환을 확인했다. 기본 에이전트 설정과 실제 베이크 설정의 혼동, 콜라이더 원인 단정, 예외 시 자산 해제·열린 씬 보존을 수정 요청했다. [검토 코멘트](https://github.com/xrlab-dau/CHOOGuard/pull/264#issuecomment-5924449408). 병합·승인은 하지 않았다 |

- **요청 기반 출동(표준·실전)**: 보고만으로는 아무도 오지 않는다. 요청은 플레이어가 지각한 대상(최근 보고·살펴봄·지각 순)에 묶이고, 출동한 팀은 그 대상으로만 간다. 지각한 것이 없으면 역무실은 `현장 확인 후 다시 보고 바랍니다`라고만 답한다. 팀 단위 적합성은 `Teams.Fits`(그 기관이 관여하는가, 시설 쪽은 그 설비 담당인가)로 판정해, 맞지 않는 팀은 와서 일하지 않는다. 기관당 한 팀만 출동하는 기존 구조는 그대로다(한계).

- **보고 슬롯**: [어디]=위험의 역 지명, [무엇]=이름, [상태]=마지막으로 직접 본 것(살펴보기로 갱신), [인원]=그 근처에서 확인한 부상자. 직접 보지 못했으면 `현장을 직접 확인했습니까?`, 가까이 가 보지 못했으면 `부상자 있습니까?`로 되묻고 응답 묶음(예·아니오·확인 중)으로 답한다. 수신기 복구는 감지기를 직접 확인하지 않았으면 한 번 확인 질문을 한다.

## 2. 한 문장 제품 정의

> **FPS 기반 비상상황 대응 시뮬레이션 게임. 별도의 직무별 상세 조작 튜토리얼을 갖추고, 한 명의 인간이 정비·청소·승무·역무를 전환하며 수백 명의 자율 AI 동료·시민과 철도 세계를 공유한다. 현재 상태와 인간/NPC의 개입에 따라 JEV 기반 루프가 다음 전개와 조건부 미래를 동적으로 합성하며, 플레이어는 변화하는 비상상황에 대응한다. 자유대화·외부 기억·정책학습 연구는 각자의 책임으로 분리한다.**

‘공유 세계’는 여기서 여러 인간 클라이언트가 아니라 **인간과 NPC가 같은 설비·도구·위험·행동 결과를 공유하는 것**이다. 온라인은 우선 AI 서비스 연결을 뜻한다.

## 3. 두 모드의 경계

| 요소 | 튜토리얼 | 본게임 |
|---|---|---|
| 목적 | 실제 자료에 근거해 업무의 관찰·판단·조작·확인·인계를 익힘 | 살아 있는 NPC 세계의 변화와 사건에 대응 |
| 역할 | 직무별 역할 전환 | 선택된 역할의 권한과 AI 동료의 분담을 유지 |

| 진행 | 설명·관찰 도움·반복 연습·실제 상태 확인 | 불완전한 정보, 동료 협업, 시민의 목적/관계, 사건 전개 |

본게임에서 시민이 반드시 재난을 일으키는 것은 아니다. 자연재해는 환경 사건이며 시민·동료는 발생 장소의 생활 주체이자 영향을 받는 주체다. 사고·행동에 따른 문제·의도적인 위해 사건도 다룰 수 있지만 조사/개발의 구체 대응은 보호·신고·대피·접근 제한·전문 인계에 둔다.

## 4. 공통 기능의 책임

### 세계와 행동

- **세계 사실:** 물체 상태, 설비 상태, 작업 단계, 위험 필드, 사람/도구 위치, 실제 완료 증거.
- **역할:** 할 수 있는 작업과 승인할 수 있는 작업, 요청·수신·수락·인계 상태.
- **상호작용:** 접근·관찰, 집기·운반·회전·배치, 도구 선택·적용, 설치·체결·분리, 측정·기록, 청소·보충·검수. 서로 다른 성공 조건을 하나의 E키 완료 판정으로 합치지 않음.
- **실행기:** 이동·접근·도구 확보·작업·중단·결과 확인을 실제 세계에서 수행. 사람과 AI가 동일한 조작 의미와 자원 규칙을 따름.
- **공유 자원:** 도구·카트·좁은 작업점·같은 지원 대상의 예약과 책임 인계. JEV 후보 선택과 별개.

### NPC

- 인물별 욕구·목표·일정·동행자·관계·기억·지원 필요·현재 약속·`GoalPlan`.
- 인물별 관측: 본 것, 들은 것, 전달받은 것, 추정, 모르는 것을 분리. 숨은 world truth나 예측 가지를 개인 지식으로 주입하지 않음.
- 코드 소유 `NpcAgentRuntime`: 플레이어 요청 없이도 목표 수립→관측에 근거한 후보 구성/JEV 추론→실행→결과 관측→협상/재계획을 반복. JEV는 그때의 목표·의도·상황·다음 행동에 관한 좁은 typed 판단을 담당하며 runtime 자체가 아님.
- 생성 대화 모델: 허용된 사실과 발화 의도를 자연어로 표현. 실제 작업 완료를 발명하지 않음.
- 움직임: navigation/crowd solver와 애니메이션. API를 기다리며 매 프레임 판단하지 않음.
- 기억: 출처와 실제 행동 결과에 근거한 저장·검색·갱신. 발화 하나로 세계 사실을 덮어쓰지 않음.
- 학습: 별도 learner/평가 환경. JEV 자체의 고객별 가중치 학습을 전제하지 않음.

### 사건과 동적 미래

현재 상태·플레이어 개입·자율 NPC의 목표/관측 → `AffordanceBuilder`의 동적 행동/전이 후보 → JEV 추론 → 공통 `TransitionKernel`·실행기의 다음 상태 계산 → 새로운 관측·재계획/재예측을 반복한다. `TransitionDefinition`은 원자적 인과 연산자/제약, `InitialWorldSeed`는 초기 상태만 담는다. 미래 전개/결말을 정한 완성 사건 pack에서 고르는 방식이 아니다.

`FutureComposer`의 조건부 예측은 격리 상태에서 같은 규칙으로 다음 단계마다 다시 추론한다. 실세계 기억·예약·완료 receipt·actor sequence를 변경하거나 예측 결말을 강제하지 않는다. 즉시 가능한 환경 효과만 최신 상태에서 재검사해 live writer에 제안하며 가상의 플레이어/NPC 선택은 자동 실행하지 않는다. 미지원 solver 결합은 incomplete로 표시한다.

JEV의 확인된 primitive는 Choice/Score/Noul이며 자유 텍스트·코드·임의 물리 수치를 만드는 생성기가 아니다. [공식 합성 지침](https://docs.typesafe.ai/concepts/how-to-build-with-system-one.md)과 [공식 한계](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)에 따라 제어흐름·계산·권한·실행은 코드가 소유한다. [사양 조사 §3–5](JEV_MODEL_SOURCES.md)의 능력/한계는 유지하되 과거의 사건 선택 예시를 제품 범위의 상한으로 해석하지 않는다. 재생은 기록된 입력·규칙·모델 결과를 쓰며 같은 seed로 새 API를 호출하면 동일 답이 온다고 보장하지 않는다.

## 5. 개발 순서의 의존관계 — 제안, 아직 미구현

전체 목표를 작은 샘플로 축소하는 계획이 아니다. 먼저 공통 기능의 실제 연결을 확인하고, 그 위에 확정된 직무·시민·사건 범위를 확장하는 순서다. 날짜·공수·최종 인원수는 이번 자료로 추정하지 않았다.

| 순서 | 작업 묶음 | 선행조건 | 완료를 확인할 관찰 |
|---|---|---|---|
| A | 직무·차종·작업 근거 등록 | 확보 자료와 요청 공백 정리 | 각 작업이 문서명·판본·역할·장치·확인 조건에 연결되고, 미확보 수치가 정답으로 쓰이지 않음 |
| B | 1인칭·물체·도구의 공통 의미 모델 | 현재 FPS/튜토리얼 코드와 모델링 자산의 접점 | 사람이 실제로 도구를 집어 조작하고 세계 상태가 바뀜. 단순 UI 클릭이나 애니메이션 완료가 검수 통과를 대신하지 않음 |
| C | 직무별 상세 튜토리얼 | A+B, 해당 장치/작업 자료 | 정비·청소·승무·역무 과정의 관찰→판단→조작→확인→인계가 각각 타당한 근거로 완결됨 |
| D | NPC 자율 목표·계획·행동 실행과 관측 경계 | B, 이동 가능 공간·의미 있는 장치 | 플레이어 요청 없이 NPC가 목표를 세우고 행동·협상·결과 관측·재계획. 약속·예약·취소·인계가 세계 상태에 남음 |
| E | JEV 판단 + 생성 대화 + 기억 | D, 온라인 서비스 경계 | 다른 관측/역할/기억에 따라 행동과 대화가 달라짐. 응답 지연·실패·오래된 답에서도 권한/물체 상태가 깨지지 않음 |
| F | JEV 동적 미래 합성과 본게임 대응 | D+E, 사건별 검증된 인과 규칙·물리 범위; Scenic은 필수 아님 | 현재 상태·개입에 따라 후보와 후속 미래가 다시 구성되고, 실제 행동 결과가 달라짐. 격리 예측이 live 기억/예약/행동을 변경하지 않음 |
| G | 수백 NPC 규모와 행동 학습 연구 | E+F, 고정된 관측·행동·결과 기록 | 실제 플레이의 FPS·응답 적용 지연·요청량·교착과 정책의 일반화를 따로 평가 |

C와 D는 B의 공통 계약이 안정되면 독립적으로 진행할 수 있다. 학습 환경의 기록 형식은 D/E부터 고려하되, 정상적으로 동작하지 않는 세계를 JEV 자기평가 점수만으로 최적화하지 않는다.

### 모델링 세션과의 작업 경계

- 모델링 세션: 형상·공간·머티리얼·관측된 실내 구성.
- 이후 gameplay 작업: 해당 자산의 식별자, 상호작용점, 동작 가능부, 접근/작업 위치, 충돌·navigation 접점.
- 이 조사에서는 두 번째 항목도 실제 부착/편집하지 않았다. 모델링 중인 씬과 생성 스크립트의 소유권을 침범하지 않는다.

## 6. 수백 NPC의 설계 기준

정확한 주기는 아직 채택하지 않는다. [JEV 정밀검토](JEV_NPC_FEASIBILITY.md)의 계산은 다음을 보여준다.

- 공개 direct API 1,200 RPM에서 300 NPC의 매초 판단 18,000 RPM은 맞지 않는다.
- 모든 인물이 개별 상태를 유지하되, 일상 진행·이동은 로컬 실행기가 수행하고 중요한 관측·요청·과업 전환에서 JEV가 재판단하는 구성이 필요하다.
- 낮은 평균 비용만 보고 동시 사건 burst·여러 사용자 세션·긴 기억 상태·대화 모델 비용을 누락하지 않는다.
- 실제 상한은 Unity 군중/애니메이션/물체 상호작용과 원격 판단을 함께 구동해 측정해야 한다. 4요청 성공을 수백 NPC 검증으로 외삽하지 않는다.
- 최신 상세 설계의 `/npc/decision`·`/future/step` 실험 시작 한도는 **합계 12 dispatch/sec·12 in-flight·pending 128**이다. 실제 계정 예산도 적용하며 foreground/live NPC를 예측 가지가 굶기지 않는다. 두 API에 각자 같은 예산을 주거나 60Hz 원격 AI를 약속하는 값이 아니다.

## 7. 아직 결정하거나 검증하지 않은 항목

| 항목 | 현재 상태 | 다음 결정에 필요한 것 |
|---|---|---|
| 정확한 차량 형식·장치 세트 | 전 직무 조사와 별개로 미확정 | 모델링 자산과 차종별 승인 작업자료의 교집합 |
| 세션 길이·저장·재개 범위 | 과거 문서의 20~30분을 새로 승인받지 않음 | 학습 목표·사건 전개·플레이 리듬 |
| 목표 하드웨어/FPS·정확 NPC 수 | Windows x64/Mono 유지, 수백 명 목표; 구체 하드웨어/성능 값 미확정 | 실제 Windows Player 부하와 제공 환경; macOS 관찰로 대체 불가 |
| 생성 대화 모델·음성 | 별도 생성 모델 결합만 확정 | 한국어 품질, 지연, 역할/사실 준수, 비용·데이터 경로 |
| 사건별 물리 정확도 범위 | 기존 제한된 FDS/군중 연동 확인 | 공간·시간·경계조건·hazard별 검증 자료 |
| 내부 매뉴얼·세부 수치 | 공개 확보 공백 존재 | 기관/제작사 정상 제공 및 전문 검토 |
| 교육/연구 인증 | 주장하지 않음 | 별도 검증·승인 절차 |

위 미정 항목은 지금까지 합의한 싱글플레이·네 직무 전환·세부 조작·수백 자율 NPC·JEV 동적 미래·별도 대화·기억/정책학습 목표를 취소하는 사유가 아니다. 이후 상세 구현계획에 필요한 구체 값으로 남긴다.
