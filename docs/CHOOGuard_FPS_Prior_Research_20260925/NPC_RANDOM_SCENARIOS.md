## 3. 랜덤화할 것과 고정할 것 — [INFERENCE] 설계 후보

### 랜덤화 축

1. **평상시 세계:** 시간대, 열차 도착/출발 단계, 대기·환승·상점 이용·정리 작업, 인원 구성.
2. **발단 사건:** 설비 이상, 화재/연기 관측, 정전, 풍수해, 지진 이후 점검 필요, 응급환자, 보안 위협 신고.
3. **사건 위치와 상태:** 검증된 시나리오 가능 지점 중 선택. 플레이어 주변에 자의적으로 생성하지 않음.
4. **인지 조건:** 누가 무엇을 보거나 들었는지, 안내방송 도달, 신고 지연, 서로 다른 목격 정보.
5. **진행과 연쇄:** 승인된 인과 관계에 따른 통로 가용성·열차 운행·설비·혼잡·지원 도착 변화.
6. **사람의 반응:** 정보 확인, 동행자 대기, 도움 요청, 이동 경로 변경, 협조/주저, 안내 이해 여부.
7. **회복 조건:** 지원 요청·업무 인계·우회·집결·운영 재개 검토. 전문기관 업무와 직원 업무 분리.

### 고정 또는 승인해야 할 것

- 객체 ID와 위치 기준, 층/차량 좌표계, 통행 가능 공간.
- 직무 권한, 승인된 작업 선행조건, 규정의 판본/적용 범위.
- 실제 물리 결과와 연출용 효과의 구분.
- 같은 상황에 대한 객관적 평가 기준. 플레이어를 어렵게 하려고 도중에 기준을 바꾸지 않음.
- 사람·공구·설비 상태의 소유권. NPC 또는 물품의 순간이동/복제로 목표를 충족시키지 않음.

### 생성 흐름 후보

```text
교육/게임 목표 + 공간판본 + 장비상태 + 인구/운행 조건 + seed
    → 허용 사건군 선택
    → 조건부 매개변수 표본추출
    → 인과 사건 그래프 구성
    → 공간·권한·자원·정보·완료/인계 가능성 검사
    → 유효한 사건만 운영 상태에 반영
    → 인간/NPC의 관측과 행동에 따라 전이
    → 원인·행동·결과를 기록
```

단순 균등 추첨 확률은 현실 사고 빈도가 아니다. 게임 다양성 분포와 실제 위험도 분포를 별도 이름으로 관리해야 한다. 학습용 의도적 희귀상황도 현실 발생률처럼 설명하지 않는다.

### 페이싱과 훈련평가를 혼동하지 않기

L4D의 `Build Up → Sustain Peak → Peak Fade → Relax`는 게임 긴장도 참고다.[N04] 이를 코레일 업무의 정답 시간이나 실제 위험 변화로 번역할 수는 없다.

- 자유 게임이라면 미확정된 다음 사건의 시점을 조절하는 director가 가능하다.
- 동일조건 비교/평가라면 사건표·seed·규칙판본을 고정하거나 적응 정책 자체를 기록해야 한다.
- 적응은 이미 관측된 사실, 과거 원인, 현존 위험을 소급 변경하지 않아야 한다.
- 지원이 필요한 상황을 무조건 생성 실패로 보지 않는다. `자체 대응 가능`, `지원·인계 필요`, `모델 미지원`을 구분한다.
- 게임의 기술적 막힘을 플레이어의 직무 실패로 채점하지 않는다.

FEMA HSEEP는 목표·시나리오·통제/평가 문서와 MSEL 템플릿을 분리 제공한다.[N12] 이는 게임 사건 저작 데이터 구조의 참고이며 한국 철도 절차의 근거는 아니다.

## 4. NPC 행동을 분해하는 방법 — [INFERENCE] 적용 제안

### NPC를 단순 '패닉 확률'로 만들지 않기

`이동 속도 + 공포 수치 + 출구 추적`만으로는 평상시 세계도 비상 협력도 충분하지 않다. NIST와 집단협력 실험은 신호 해석, 행동 선택, 사회적 상호작용을 따로 볼 근거를 준다.[N09–N11]

| 층 | 상태/입력 후보 | 역할 |
|---|---|---|
| 일정/목표 | 열차편, 대기 위치, 환승, 구매, 동행자, 업무 | 위기 이전에도 목적 있는 생활 |
| 신체·접근 요구 | 이동보조, 보행 속도 범위, 짐, 피로, 계단 이용 가능 여부 | 이동 가능성과 필요한 지원; 특정 집단을 불복종과 결부하지 않음 |
| 지각 | 시야·가림·청각·방송 구역·언어 이해·직접 대화 | 각 사람이 실제로 획득한 정보 |
| 지식/기억 | 관측 사실, 전달자, 시각, 확실/미확인/상충 | 전지적 시민 방지, 잘못된 정보 수정 |
| 의도/사회관계 | 동행자 기다리기, 안내 확인, 돕기, 재합류, 협력 | 서로 영향을 주는 시민 |
| 행동 선택 | FSM/Behavior Tree/Utility/GOAP | 일관된 우선순위와 취소·재개 |
| 경로/보행 | 목적지, 경유점, 줄서기, 국소 회피, 층간 연결 | 물리적으로 실제 이동 |
| 표현/대화 | 시선, 손짓, 음성, 자막, 생성형 문장 | 관측 가능한 상태를 표현; 상태 자체를 몰래 결정하지 않음 |

### 상태 전이 예시

```text
열차 대기
  → 이상 단서 인지
  → 안내 확인/동행자 확인
  → 안내 이해 또는 추가 질문
  → 이동 결정
  → 경로 이동/양보/도움 요청
  → 집결 또는 전문인력 인계
```

시민별로 시작 신호와 정보가 달라야 한다. 방송 요청 버튼을 눌렀다는 사실과 시민이 들었고 이해했고 움직였다는 사실은 다르다. 일부는 직원 안내 전에 스스로 이동할 수 있다. 모든 시민을 버튼 하나로 활성화하는 것만으로 현실 행동을 표현하지 않는다.

|---|---|---|---|

짧은 재사용 단위는 API를 감싸는 호출보다 **행동 시작/실행/중단 계약, 여정 전환, 지각 업데이트, 제약 검증, 원인 기록**이다. 한 번에 완성된 '코레일 NPC' 오픈소스를 발견한 것은 아니다.

### 보행 엔진과 게임 엔진을 함께 쓸 때

- NPC 한 명의 위치를 JuPedSim과 Unity NavMeshAgent가 동시에 갱신하지 않는다.
- 보행 소유자가 결정한 위치를 렌더링하고, 문·통로·차량 상태는 명시적인 어댑터로 전달한다.
- 대기열·층간 포털·열차 출입구에서 소유권을 넘길 경우 동일 인물 ID와 시각을 유지한다.
- 시야 밖 NPC도 존재와 인원 계수는 유지한다. 낮은 빈도의 판단/애니메이션과 삭제는 다르다.
- 렌더 LOD로 사람 수나 대피 판정의 의미를 몰래 줄이지 않는다.

### LLM을 쓰는 위치

**후보:** 중요한 동료·목격자의 발화, 자연어 지시를 제한된 행동으로 번역, 사건 후보 저작, 관측 기반 설명.

**판정 코어로 부적절:** 매 프레임 위치 결정, 볼트/장비의 실제 상태, 전문 업무 정답 생성, 물리 결과 창작, 모든 승객의 매 틱 독립 호출.

**[INFERENCE] 실행 경계:** 관측 가능한 상태만 제공 → 허용된 행동 ID/대상/조건을 제안 → 권한·상태·공간 검증 → 운영 코어가 반영 → 결과를 다시 관측. 게임 지시를 통해 규정이나 서버 권한을 수정할 수 없게 하는 구조가 필요하다. 응답이 늦어도 이동·물리는 계속되어야 한다.

## 5. 현실성과 재미를 검증할 근거

실제 적용 전 필요한 검증 후보이며, 이번 조사에서 측정한 결과가 아니다.

- **보행:** 문 폭/병목, 역류, 계단, 대기열, 합류, 길 막힘, 안내자와 추종자의 분리.
- **인지/협력:** 방송이 닿지 않은 사람, 서로 다른 정보, 동행자 대기, 이동보조 요청, 구조 인력에 길을 내주는 행동.
- **무작위 생성:** seed 재생, 인과 관계, 사용 가능한 자원/경로, 사건군의 분포 및 거부 편향, 전문 지원이 필요한 종료 조건.
- **멀티플레이:** 두 사람이 같은 도구를 동시에 집는 경우, 지연된 지시·중복 승인, 접속 중단, 지원 역할 인계.
- **교육:** 독립 전문가가 검토한 행동 기준, 안내 유무에 따른 수행 변화, 새로운 변형 상황으로의 전이. 게임 점수만으로 실제 직무 자격이나 현장 안전을 인증하지 않음.

Jülich DATA에는 병목·계단·합류 등 실험 자료군이 공개되어 있다.[N17] 이는 비교 후보이지 부산역/KTX의 실측값이 아니다. 이번 조사에서는 목록과 설명을 확인했으며 원시 궤적을 다운로드·분석하지 않았다.
