# 개발보드 Review 재개 결과 · 2026-09-09

대상은 재개 당시 개발보드 Review의 이슈 #10, #14, #25, #26, #32, #52, #64, #65와 이미 승인된 PR #1~5다. 연결 구현 PR #97, #98, #104와 새 수정 PR #105를 대조했다. Fal은 사용하지 않았다.

## 실제 실행과 수정

Hugging Face Jobs에서 작성자 OpenAI와 다른 Qwen 모델을 실제 실행했다. 1차 21회, 2차 12회, 3차 12회로 총 45개 응답을 받았으며, 모든 원 응답의 SHA-256을 다시 확인했다. 모델은 공개 텍스트만 받았고 도구를 갖지 않았다. 세션별 모델·불변 대상·응답·실패는 `review-call-index.json`과 각 round 파일에 보존한다. 판정 모순과 스키마 실패를 승인으로 바꾸지 않았다.

재현된 자산 입력 결함 두 종류를 [PR #105](https://github.com/xrlab-dau/CHOOGuard/pull/105)에 수정했다. 잘못된 참조 레코드/URL/관측/이미지-해시 입력과 잘못된 자산 ID/행 목록이 정상 검증 오류로 반환된다. 각 수정에서 먼저 실패를 재현한 뒤 회귀시험을 통과시켰다. 최신 코드 `f246a87ecd52c15ada7dec5cd51ea61a6bb06981`의 자산 시험 15/15, 현재 33종 데이터 오류 0, 필수 CI의 정책 7·Foundation Python 31·context 17 시험이 통과했다.

검토 중 PR97이 `39e5dc24892744feacec09eac0c2e71951cb31c8`로 갱신됐다. 이전 정책 판정을 그대로 적용하지 않고, 아직 실행 전이던 정책 관점을 최신 코드로 전환했다. 해당 CI는 Windows 119개 중 107통과/12제외, Linux 119개 중 103통과/16제외이며 profile 검증은 각각 9/9다. 실제 학교 PC·Unity 실행과 구분한다. 자세한 커밋·CI 연결은 `ci-followup.json`에 있다.

## 지적을 처리한 근거

- 코어: `TrainingAction`의 잘못된 enum 값은 `ValidateAction`에서 상태 변경 전에 거부하며 해당 회귀시험이 있다. `CopyValidated`는 역할/이벤트를 깊게 복사하고, `CreateRoleActionFixture`에는 Ready 검사, 팀 상태에는 ordinal 정렬이 있다. C# 문자열이 가변이라는 3차 명세 주장은 사실과 다르다. 이런 주장에 맞추어 정상 계약을 변경하지 않았다.
- 자산: `dict.get`이 필드 누락으로 KeyError를 낸다는 주장, 이미 있는 이미지/해시 길이 검사의 부재 주장과 콜론 허용 주장은 현재 코드와 충돌한다. 동일 이미지 바이트가 다른 URL에서 올 수 있으므로 모든 SHA의 고유성을 강제하지 않는다. ID 타입 문제는 실제 예외로 재현되어 추가 수정했다. 추정 성능 최적화나 메시지 취향은 완료 차단 결함으로 채택하지 않았다.
- PR104: texture null·배열 길이·view/angle 범위 검사는 존재하고, FileStream은 using과 Flush(true)로 정리한다. 두 .NET SHA-256 API가 다른 알고리즘이라는 주장은 사실과 다르다. 이 정정이 Unity 수명주기·렌더 실측을 대신하지는 않는다.
- PR97: 현재 정책 검사에는 중복 키/정확 필드 집합·정규 상대 경로·일반 파일·reparse 검사와 도구 실행 후 재순회가 있다. 외부 manifest는 신뢰된 호출자가 별도 핀을 제공하는 의도된 계약이다. 막연한 Unicode/case 정규화나 Windows junction 검사 부재 주장은 재현 입력과 실제 분기로 뒷받침되지 않았다. 원본 저널 부재 및 실제 정책 승인은 구현 승인과 구분한다.

작성자의 반박만으로 독립 승인을 생성하지 않는다. [ADR 0003](https://github.com/xrlab-dau/CHOOGuard/blob/e7a6bb7a7fff0c301c04f93aeea8850dbde34779/docs/adr/0003-independent-review-and-adversarial-graph.md)의 필수 관점·동일 대상·최대 3라운드 조건에 따라 미승인 단위는 `cannot_proceed`다. 수정 후 새 승인도 받았다고 주장하지 않는다. 남은 다섯 이슈는 단순히 실행 환경을 준비하지 못한 상태가 아니라, 실제 검토를 거쳤으나 필수 승인을 확보하지 못한 상태다.

## 범위

모든 PR은 미병합이다. 배포, KORAIL 메시지 전송, 기관 승인, Unity 라이선스 활성화, 학교 PC/HMD 조작을 수행하지 않았다. 자동 승인 검토의 최초 거부와 공개 코드로 범위를 줄여 허용받은 과정, 작업 중 대상 갱신, 모델/구문 실패와 실제 GPU 작업 상태는 `execution-boundaries.md` 및 원 기록에 보존했다.
