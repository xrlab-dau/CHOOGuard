# CHOOGuard 제품 개요
## 철도 비상대응 운영안 설계·검토 실험실

**기준일:** 2026-09-19 · **상태:** 근거 기반 제품 가설 / 제한된 실증 진행 권고  
**주 사용자:** 같은 철도 현장의 유관기관 합동훈련을 반복 기획하는 시나리오 작성 책임자·실무팀  
**플랫폼:** Unity PC · **개발 방향:** AI-native, 무료 에셋 우선, 용도별 정확도 검증  
**현장 검증·사용자 시간 시험:** NOT_RUN

## 문제

기관별 업무·자원·보고·시설 조건을 수정하면 후속 작업과 인계·현장 이동도 달라진다. 작성 담당자가 이 영향을 검토하고, 모순을 줄이며, 채택한 이유를 최종 대본까지 보존하기 어렵다는 문제를 해결한다. 문제의 크기와 현재 총작업시간은 실제 작성팀에게 확인해야 한다.

정부의 매뉴얼·역할 점검 목적, 실제 철도 합동훈련과 가상훈련 도입은 이 문제 분야의 존재를 뒷받침한다. 그러나 CHOOGuard의 효용·지불의사를 입증하지는 않는다. [S01][S03][S04]

## 제품 정의

**작성 담당자가 실제 공간·매뉴얼·자원 제약 안에서 기관·팀·차량·업무를 RTS처럼 운영하고, 대안을 분기·비교해 정합한 운영안을 선택한 뒤, 근거가 연결된 훈련 시나리오·대본으로 출력하는 운영 시뮬레이터.**

운영 시뮬레이션이 본체이고 로그는 검토 근거이며 대본은 결과물이다. AI가 대본을 먼저 정답처럼 생성하거나, 사용자를 반사신경·정해진 클릭 순서로 평가하는 제품이 아니다.

## 핵심 사용자와 역할

작성자는 운영안을 만든다. 기관별 협조자는 자기 역할·자원·인계를 검토한다. 훈련 책임자는 실제 훈련 사용 여부를 판단한다. 정보화·구매 담당자는 설치·자료·유지보수를 판단한다. 제품 사용자의 권한과 가상 세계 속 기관의 지휘권은 구분한다.

첫 실증 파트너는 실제 최근 대본·수정 기록·허용된 규칙·대표 공간/자원 입력과 검수 협조를 제공할 수 있는 반복 작성팀으로 좁힌다. 일반 게이머나 훈련 참가자 총원을 초기 시장으로 계산하지 않는다.

## 경험과 두 모드

**상황 설정 → 운영안 A 실행 → 충돌·대기 근거 확인 → B 분기 → 동일·변형 조건 비교 → 작성자 선택 → 대본 검토·출력 → 재실험.**

`TUTORIAL`: 실제 훈련 사례·검토된 매뉴얼을 익히는 안내·힌트 축소·복기 과정.  
`RANDOM_OPERATIONS_LAB`: 기관·공간·자원·인과 제약을 지키는 상황에서 운영안을 시험하는 일반 모드.

두 모드는 같은 물리·운영 코어를 사용한다. 일시정지·배속·기관별 정보 보기·대본 편집은 공통 도구다. 작성자는 전체 정보를 분석할 수 있지만 시뮬레이션 속 각 기관에는 실제로 전달된 정보만 반영한다.

## 필수 기능

팀/차량 우선 선택과 업무 우선 배정, 요청·접수·예약·수행·보고·인계의 상태 관리, 권한·정보·자원·이동·안전 원인의 동시 표시, 분기 기록 보존, 근거 기반 비교, 문서와 실행 데이터의 같은 버전 출력.

첫 공간은 외부 도착 경계–현장 업무 공간–맞이방–승강장–선택 객실이다. 초기 통합은 소수 기관·팀으로 검증하고, 전체 13구역과 여러 사건 계열로 확대한다. 구역 수 확대는 첫 제품 효용 검증의 선행이 아니다.

## 기술·정확도 원칙

운영 코어는 이산사건·자원·업무 그래프를 중심으로 만들고, 필요 부분에 TAPAAL 형식검사, JuPedSim 보행, FDS 열·연기, SUMO 교통을 연결한다. 신경 대체모델은 독립 검증된 범위에서 가속에 사용한다. 도구 기능의 존재는 현장 성능 증거가 아니다. [S12–S16]

SOTA는 최신 이름을 모두 채택하는 것이 아니라 같은 목적·입력·예산에서 정확도·비용·재현성을 비교하는 선정 원칙이다. 실제 활용을 주장하는 출력은 관측·보정·독립 검증·불확도·유효범위를 갖춰야 한다. [S11]

무료 모델은 시각 제작의 기본 선택이며 실제 치수·물성·장비 능력은 별도다. 기관 절차는 판본·관할·예외·검수자와 결속한다. 규칙, 실행 사실, AI 가설, 검토된 권고, 기관 승인을 섞지 않는다.

## 차별화 가설과 시장

국내 철도 매뉴얼과 공간·자원·정보를 연결해 운영 중 모순을 설명하고, 수정안과 대본의 정합성을 보존하는 데 집중한다. AI 시나리오 생성, 3D 사건 훈련, 자원 운영은 이미 대체재가 존재한다. [S04][S07–S10]

초기 도입 가설은 기관·현장 단위의 제한 실증이다. 구매자·가격·예산·유지비 수용은 아직 확인하지 않았다. 전국 역 수나 훈련 참가자 수로 시장규모를 추정하지 않는다.

## 성과와 검증

주 성과는 품질이 충족된 대본까지의 **총인시와 중대한 공조 결함 감소**다. 최초 규칙·공간 구축, 교육, 입력, 조작, 사람이 지켜본 계산 대기, 검토·출력·유지보수를 포함한다. 무인 계산은 인시가 아닌 별도 경과시간·비용으로 본다.

기존 방식 A, 같은 구조화·AI·운영 코어에 3D가 없는 B, RTS·공간 화면이 있는 C를 비교한다. 순서·난이도를 균형화하고 검수자는 사용 도구를 모르게 한다. 총인시 중앙값 20% 감소는 실험 전 합의할 제안 목표일 뿐 이미 입증한 수치가 아니다.

시간 절감, 3D의 추가 가치, 규칙·근거 정확성, 재사용 의사와 실제 두 번째 사용, 지정 물리 정확도를 각각 검증한다. 전부 같은 하나의 게임 점수로 합치지 않는다.

## 경계와 최종 판단

VR 기기·입력·시험, 자유 건설·경제 경영, 전투·공격 최적화, 실제 운영설비 제어, 자동 현장 안전 인증은 제외한다. 제품 내 검토 승인과 기관의 실제 사용 승인은 다르다.

**문제의 근거는 있으나 해결책의 효용은 미검증이다. 운영 시뮬레이션 방향은 유지하고, 실제 작성자의 한 업무와 한 공조 상황을 대상으로 제한 실증을 진행한다. 전면 확대와 현장 예측 주장은 그 증거가 나온 뒤 판단한다.**
