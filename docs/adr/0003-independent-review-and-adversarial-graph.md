# ADR 0003: 독립 검토 정책과 적대적 검토 그래프

Status: proposed (1차 검토 changes_required, 수정 후 독립 재검토 미실행)
Date: 2026-09-06

## 맥락

파이프라인 v1.2 §3의 Codex CLI 또는 Gemini CLI 검토와 §7~9의 독립 제공자·증거 요구를 Pi 그래프에 연결하는 제안이다. 이 문서는 실행 강제가 구현됐다는 증거가 아니다.

## 결정안과 현재 상태

1. 그래프는 저장소의 pi-agents YAML을 사용한다. `adversarial-review`는 명세·적대·보안 관점을 병렬 실행한다. `plan-review`는 검토 뒤 문서 수정과 재검토를 반복한다. 현재 `wu-develop`의 순서는 scout → implementer → adversarial-review → 수정·재검토 루프 → verifier다. 검증이나 수정으로 대상이 바뀌면 다시 독립 검토한다.
2. 실제 스키마를 계층별로 구분한다. 리뷰어 출력은 `outcome, actionable, notes`이고 병합 출력은 `outcome, reason, actionable, report`다. `outcome`은 `approved|changes_required|cannot_proceed`, 지적은 `id, severity, title, problem, fix, locations`를 필수로 갖는다. Pi 보안 지적 접두어는 `SEC-`, 대체 오케스트레이터 원본의 `SAF-`는 출처와 함께 보존한다. 서로 다른 묶음의 동일 ID는 합치지 않는다.
3. 작성자는 anthropic, 독립 검토자는 openai-codex 프로파일을 사용한다. 프로파일 값과 modelScope/watchdog 설정만으로 강제가 검증됐다고 판정하지 않는다. pi-subagents와 pi-agents의 실제 호출 경로, 역할명 매핑, 상속·재시도·fallback 각각을 M1-07에서 시험한다. 같은 제공자의 수정 후 검토는 독립 제공자 게이트를 충족하지 못한다.
4. 각 리뷰어는 분리된 세션에서 동일한 불변 대상 manifest를 읽는다. manifest는 상대 경로, 파일 SHA-256, base/head, 미커밋 파일 해시를 포함한다. 시작·종료 시 대상이 같아야 한다. 이전 요약은 참고일 뿐이며 파일과 diff를 직접 다시 읽는다. 현재 자유 텍스트 target은 이 계약을 강제하지 못하므로 운영 승인의 근거로 사용하지 않는다.
5. 필수 관점 누락, 오류, 스키마 불일치, 제공자 불일치, 대상 해시 변경은 `cannot_proceed`다. 유효한 지적이 있으면 `changes_required`다. 세 관점이 모두 정상 완료하고 미해결 지적이 없어야 `approved`다. 판정은 모델 밖 결정적 검증기로 집계해야 한다. 현재 YAML의 `onError: collect` 및 나머지 결과로 승인하는 reducer는 이 요구와 충돌하며 수정·시험 전 사용 보류다.
6. 목표 상한은 초기 검토를 포함한 총 3라운드다. 현재 YAML의 초기 검토와 `max: 3` 수정·재검토 루프는 최대 4회 검토이므로 목표와 다르다. 보호 설정의 사람 승인·수정·시험 전에는 운영하지 않는다. 상한은 승인으로 바뀌는 조건이 아니다. 남은 지적은 PM이 수정·반박·보류 사유와 영향 단위를 기록한다. 사람의 수정·반박 뒤에도 새 대상 manifest에 대한 독립 재검토가 필요하다. 영향 단위는 재검토 전 Done이 될 수 없다.
7. Pi 인증이 준비되지 않은 계획 환경은 다른 오케스트레이터로 문서 검토를 실행할 수 있다. 실제 제공자·모델, 분리 방식, 도구 강제 여부, 실패 관점, 대상 해시 유무를 기록해야 한다. 읽기 전용을 프롬프트로만 지시했다면 Pi 실행 경계 검증과 동등하다고 주장하지 않는다.

## 대안

| 대안 | 판단과 한계 |
|---|---|
| Codex CLI 또는 Gemini CLI 읽기 전용 세션 | 권위 문서의 기존 경로다. M1-07에서 실행 격리와 증거 연결을 비교한다. |
| pi-agents 병렬 검토 | 세션·그래프 구성이 편리하다. 별도 sandbox, 결정적 결과 검증, manifest 고정이 필요하다. |
| 단일 리뷰어 | 비용은 작지만 필수 세 관점의 대체로 인정하지 않는다. |
| 무한 수정 반복 | 비용·수렴을 예측할 수 없어 제외한다. |

## 위협·비용

- 도구 이름에서 edit/write가 빠졌다는 사실은 호스트 파일 접근 제한을 증명하지 않는다. 읽기 전용 sandbox와 실행별 변경 감사를 병행한다.
- 검증기는 bash를 사용하므로 별도 실행 사본의 생성 폴더·빌드·임시 로그만 쓸 수 있어야 한다. 확정 증거는 append-only다. 자유 문자열 테스트 대신 검토된 test ID와 고정 argv를 모델 밖에서 실행한다.
- 검토 한 회는 리뷰어 3개와 병합 모델 호출을 사용한다. 수정·재검토, 중첩 workflow, 실패 재시도는 별도 비용이다. 본체 세션 수와 모델 호출 수를 혼동하지 않고 실제 trace로 집계한다.

## 이번 실행 기록

2026-09-06 대체 오케스트레이터 실행은 종료됐지만 승인되지 않았다. 리뷰 작업 하나는 과도한 프롬프트로 실패했고 수정 작업 전부는 API 제한으로 실패했다. 수정 후 재검토는 실행되지 않았다. 세부 상태는 `docs/reviews/2026-09-06-workflow-status.json`을 참조한다.

## 검증 게이트

- YAML 파싱은 구문 검사일 뿐이다. Pi에서 `workflow_list`와 `workflow_inspect`를 실행한 학교 PC 영수증은 아직 없다.
- M1-07은 필수 리뷰어 실패·누락, 잘못된 스키마, 제공자 우회, target 변경을 각각 차단해야 한다.
- 검토 판정 원본과 이후 수정 상태를 분리 보존한다. 이번 실행 결과를 승인된 최종 계획으로 표시하지 않는다.
