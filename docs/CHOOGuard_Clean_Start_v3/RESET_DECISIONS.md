# 초기화 전제에 따른 설계 정정

## 현재 결정
새 개발 기준은 GREENFIELD다. 기존 에픽을 유지하거나 번호만 치환하는 방식은 사용하지 않는다. 이번 설계는 11개 capability epic, 45개 작업, 신규 파일 구조와 인계 산출물을 독립적으로 정의한다.

## 제거한 시작 조건
과거 에픽·스토리·의존성 그래프, Foundation 확장·기존 권위 클래스 연결, 사전 고정 커밋, 옛 work-order·문맥 CLI, 기존 패키지·CI·테스트 성공·담당자 배정, 13개 구역 ID·이전 파일 호환 조건을 새 실행 전제에서 제거한다.

## 유지하는 것
작성자 중심 운영 실험이라는 제품 목적, Unity native UI, RTS와 업무중심 조작, 교육/랜덤 두 모드, 무료 자산 우선, 실제 매뉴얼·공간 근거, 정밀 모델·독립 검증, 로그·분기·비교·대본, 한정된 현장 수용, 사용자 효용 검증은 유지한다. 외부 공개 solver·UI package 사용은 허용하되 새로 설치·버전 고정·통합 검증한다.

## 기존 요구 중 변경한 것
REQ-015: 과거 root ID 보존 대신 새 구역 ID와 공간범위 등록.
REQ-061: 예전 에픽/CLI 대신 이번 패키지의 새 task 문맥.
REQ-063: 과거 자산 확보상태 상속 대신 현재 환경의 새 원본 입고검사.
REQ-066: 기존 코드 재사용 대신 빈 저장소의 새 프로젝트·빌드·계약.
REQ-075: 특정 구역 수 강제 대신 검증된 현장별 확장.
다른 제품 요구는 그대로 읽을 수 있게 self-contained requirements.json에 옮기고 새 작업 소유자를 배정했다. REQ 번호는 기능 요구 추적자이며 기존 에픽 호환 계약이 아니다.

## 이전 문서와의 관계
이번 패키지가 저장소 초기상태·에픽 분해·구현 순서·소스 경로에 우선한다. 과거 문서의 제품 연구와 외부 레퍼런스는 참고할 수 있지만 이전 구현 지시를 함께 실행하지 않는다. 과거→새 에픽 일대일 대응표를 실행 전제로 제공하지 않는다.

## 이번 실제 작업
문서·JSON·검사/조회 도구를 새로 만들었다. 원격 저장소 상태를 조회하지 않았고 초기화·파일 삭제·force push·이슈/보드 변경·실행 코드 구축을 수행하지 않았다. 초기화 완료 여부는 사용자의 새 개발 전제이며 외부 검증 사실로 표기하지 않는다.
