# TEAM-26 평가 질문·익명 기록 양식

2026-09-13 작성 · 이슈 [#94](https://github.com/xrlab-dau/CHOOGuard/issues/94) · candidate 후보

비공식 게임 평가의 질문·과업·관측·교란 요인·누락 처리와 익명 기록 보관을 정의하는 설계 양식이다. 합성 예시는 [`foundation/team-fixtures/TEAM-26/anonymous-record.json`](../../../foundation/team-fixtures/TEAM-26/anonymous-record.json)에 있다.

**실제 참가자 실험이 아니다.** 이 양식은 무엇을 어떻게 기록할지 정할 뿐이며, 공식 점수·이수 판정·효과 크기를 만들지 않는다. 게임 내 완주를 현장 대응 역량 향상의 증거로 쓰지 않는다.

앞의 두 입력은 **후보이며 PM 수용 전**이다. 병합 시 해시가 바뀌면 이 양식의 질문–관측 연결을 다시 대조해야 한다.

## 2. 질문 작성 규칙

질문 하나는 **과업 → 관측 → 교란 요인 → 누락 처리**까지 한 줄로 이어져야 한다. 관측에 연결할 수 없는 질문은 "측정 불가"로 표시하고 남겨 둔다. 지어낸 지표로 채우지 않는다.

| 필드 | 내용 |
|---|---|
| `questionId` · `text` | 질문 식별자와 문장 |
| `task` | 참가자가 실제로 수행하는 과업 |
| `observation.flowId` · `stages` | #72 fixture의 실제 흐름·단계. 존재하지 않는 단계를 쓸 수 없다 |
| `observation.measure` | 무엇을 어떤 단위로 재는가 |
| `confounders` | 결과를 흐리는 요인. 최소 1개 |
| `missingDataRule` | 관측 실패·미수집·기록 손실을 각각 어떻게 적는가 |
| `deferred` | 승인 후 정할 항목 |

## 3. 정의한 질문 네 가지

| 질문 | 관측 | 측정 | 주요 교란 |
|---|---|---|---|
| Q1 사건 발생 후 관측까지 걸리는 시간 | F01 `onset`→`observe` | 초 | 순회 위치와 사건 위치의 거리, 시드별 조용한 구간(40~85초) |
| Q2 관측 전 대응 시 선행 조건 거부 작동 | F04 `act` | 거부 횟수와 위치·유형 노출 여부 | 이전 세션의 기억, 직무별 첫 설비 차이 |
| Q3 인솔 대상의 집결 도달 | F05 `escort`→`assemble` | 확인 인원 ÷ 대상 인원 | 대상 2~6명 변동, 고장 구역, 통로 양면 통과 판정 |
| Q4 복기 기록의 실제 사용 | F02 `observe`→`resume` | 열람 횟수·시점 | 휴식 목적의 일시정지, 관찰자 존재 |

## 4. 누락 데이터 처리

빈 값을 0이나 평균으로 바꾸지 않는다. 네 가지를 구분해 적는다.

| 코드 | 의미 |
|---|---|
| `observed_absent` | 관측했고 그 행동이 일어나지 않았다. **0이 아니라 '없음'이다** |
| `not_collected` | 관측 자체를 하지 못했다. 추정하지 않는다 |
| `record_lost` | 기록이 손실됐다. 대체하지 않는다 |
| `out_of_scope` | 이 세션의 범위 밖이라 측정 대상이 아니다 |

특히 `observed_absent`(0회)와 `not_collected`(모름)를 절대 합치지 않는다.

## 5. 익명 ID와 보관 범위

- **ID 형식:** `P-NN`. 세션별로 새로 발급하고 이전 세션과 연결하지 않는다.
- **수집하지 않는 것:** 실명, 연락처, 이메일, 직원번호, 소속·부서, 계정 ID, 얼굴·음성 녹화, 기기 식별자, IP, 정확한 생년월일.
- **수집하는 것:** 익명 ID, 세션 ID, 시드, 프로필 버전, 관측 항목 값, 시각(분 단위), 누락 사유 코드.
- **연결 대장을 만들지 않는다.** 필요하면 저장소 밖 승인된 위치에서 별도 관리하고 공개 기록과 분리한다.
- **보관 기간은 정하지 않았다.** 승인 후 결정한다. 삭제 요청 경로는 실행 전에 정한다.
- **재식별 방지:** 자유 서술 칸을 두지 않고 사전 정의 코드로 받는다. 시각은 분 단위로 절삭한다. 소규모 집단에서 식별 가능한 조합(시각+위치+직무)을 공개 결과에 함께 싣지 않는다.

저장소에는 **합성 예시만** 둔다. 실제 기록은 넣지 않는다.

## 6. 거부 사례

| 사례 | 시도 | 판정 |
|---|---|---|
| N01 | `participantId`에 실명과 연락처를 적고 익명 ID로 취급 | `refused` — ID 형식과 미수집 목록으로 거부 |
| N02 | 미수집 항목을 0으로 바꾸고 "효과가 있었다"고 기재 | `refused` — 누락 코드와 보류 결정으로 거부 |

## 7. 승인 후 정할 항목

임의로 정하지 않는다. 전부 `null`로 두고 결정 주체를 적었다.

참가자 수, 효과 크기, 세션 반복 횟수, 보관 기간, 기관 협조·현장 일정(이 이슈 범위 밖).

## 9. 한계

- 실제 참가자 실험·기관 협의·현장 훈련을 수행하지 않았다. 일정을 가정하지 않는다.
- 공식 점수·이수 판정·효과 크기를 만들지 않는다.
- 관측 가능 행동의 출처인 #72 fixture는 후보이며 PM 수용 전이다.
- 범위는 legacy 단일 조작자다. FMP 20/100/2 목표의 평가 설계가 아니다.
- 읽기 전용 참고 2종이 미게시라 상태별 관찰·미검증 범위의 원문 대조를 수행하지 못했다.
