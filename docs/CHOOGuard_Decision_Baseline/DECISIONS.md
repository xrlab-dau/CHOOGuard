## 1. 제품의 정체성을 고정한다

CHOOGuard는 **시나리오 작성 담당자를 위한 현실 기반 철도 비상대응 운영 실험 도구**다. 사용자가 기관·팀·인력·차량·업무를 조작하고, 매뉴얼·권한·정보·자원·공간·물리 제약 아래에서 운영안을 시험·비교·개선한 뒤, 선택한 운영안을 종합훈련 시나리오와 대본으로 출력한다.

운영 시뮬레이션이 본체다. 맵은 운영을 실행하는 공간이고, 로그는 검토 근거이며, 대본은 설계 결과다. 대본을 먼저 완성하고 확인만 하는 서비스, 훈련생의 정답률 게임, 자유 건설·수익 경영 게임으로 방향을 바꾸지 않는다.

**핵심 루프:** 상황 설정 → 운영안 A 실행 → 병목·모순 확인 → B 분기 → 같은 조건 및 변형 조건 비교 → 작성자 선택 → 사람 검토 → 대본·실행형 시나리오 → 재실험.

제품 플랫폼은 **Unity PC**다. 기본 조작은 **조감형 RTS + 업무 중심 운영 UI**다. VR/HMD/XR, 별도 FPS, 자유 건설, 경제 시스템은 현재 범위에서 제외한다. 테러·보안 위협은 검토된 대응 훈련 배경으로만 표현하며 공격 최적화·전투 조작·실제 설비 제어는 제공하지 않는다.

## 2. 사용자의 조작과 기관의 권한을 구분한다

기본 선택 단위는 **팀 또는 승무 인력이 연결된 차량**이다. 구성 인력은 펼쳐서 확인하지만 모든 사람의 이동을 한 명씩 클릭하게 하지 않는다.

두 입력 방식을 함께 제공한다.

- **팀 우선:** 팀/차량 선택 → 대상·업무 선택 → 가능한 조치와 부적합 이유 확인 → 요청/배정.
- **업무 우선:** 업무 카드 선택 → 요구 능력·자원·정보 확인 → 적합한 후보 팀 비교 → 배정.

기관 내부 명령과 외부기관 협조 요청은 서로 다른 이벤트다. 작성자에게 전체 운영안의 편집·분석 권한이 있다고, 시뮬레이션 속에 모든 기관을 직접 지휘하는 만능 지휘관을 만들지 않는다. 각 기관은 자신의 수신 정보와 위임된 권한에 따라 움직인다.

한 업무는 요청, 접수, 배정, 예약, 이동·준비, 수행, 완료·실패, 보고·인계, 자원 해제의 필요한 단계로 진행한다. 유형에 따라 단계를 생략할 수 있지만 명시적으로 모델링해야 한다. 클릭은 요청이지 완료가 아니다.

**운영 상태는 직교하는 축으로 저장한다.** `lifecycle`, `authority`, `knowledge`, `resources`, `mobility`, `safety`, `evidence`를 하나의 거대한 상태 enum으로 합치지 않는다. v10의 22개 원인 코드를 유지하고, 하나의 업무에 복수 원인과 각 근거·담당·해결 조건을 연결한다.

예시: 업무는 현장 대기 중이고, 이동은 완료됐지만, 인계 확인과 최신 보고 수신이 남을 수 있다. UI는 '실행대기'만 보여주지 않고 왜 기다리는지, 어떤 기관·업무·메시지와 연결되는지 표시한다.

## 3. 사용자 모드는 정확히 두 개다

| 모드 | 확정 역할 | 불변 조건 |
|---|---|---|
| `TUTORIAL` | 실제 훈련·검토된 매뉴얼을 바탕으로 안내 실행, 힌트 축소, 복기를 제공하는 하나의 교육 과정 | 허용 가능한 여러 작업 순서를 인정한다. 동일 물리·운영 코어를 사용한다. |
| `RANDOM_OPERATIONS_LAB` | 작성자가 새 조건에서 운영안을 시험하는 일반 모드 | 인과·기관 권한·공간·자원·모델 유효범위 안에서 조건부 상황을 생성한다. |

첫 교육 과정의 **조사 기준 사례**는 2026-03-11 KTX·SRT 합동 비상대응훈련으로 유지한다. 공식 보도는 훈련 사례의 근거일 뿐 세부 대본·기관별 편성·정확한 소요시간을 모두 제공하지 않는다. 실제 장소가 다른 맵으로 옮긴 콘텐츠는 '공개 사례 기반 재구성'으로 표시한다. [SRC-TRAINING]

새로운 기관별 대본 원본이 확보되면 교육 콘텐츠의 출처·버전을 갱신한다. 실제 해당 매뉴얼의 적용성과 학습목표 검토 없이 공식 교육 이수나 절차 인증을 주장하지 않는다.

일반 모드는 사건 효과를 무작위로 아무 곳에나 붙이지 않는다. 정보 지연, 자원 가용성, 공간 사용, 시설 상태와 사건 전개의 조건부 의존성을 사용한다. 발생확률 근거가 없으면 시나리오 표본이라고 표시하며 현실 발생확률로 해석하지 않는다. 추가 지원이 필요한 상황은 `ESCALATION_REQUIRED`, 모델 범위 밖 상황은 `UNSUPPORTED`로 구분한다.

일시정지, 배속, 복기, A/B 비교, 기관별 정보 보기, solver 프로파일은 공통 도구·설정이지 세 번째 사용자 모드가 아니다. 배속은 표시·실행 속도 요청이며 검증된 물리 timestep을 임의 확대하는 명령이 아니다.

## 4. 화면·아트의 방향을 확정한다

**실제 공간 비례를 보존하는 세미리얼리스틱 3D + 명료한 운영 오버레이**를 선택한다. 과도한 실사 텍스처와 복고 PSX 스타일을 기본 미술 방향으로 채택하지 않는다. 무료 저폴리곤 자산을 재료로 쓰되 형상·재질·아이콘·색상·애니메이션 규격을 통일한다.

| UI 영역 | 확정 기능 |
|---|---|
| 중앙 맵 | 조감·회전·확대, 층 선택, 상층/지붕 숨김, 선택 강조, 현장과 외부 도착 경계 |
| 왼쪽 조직 패널 | 기관 → 팀 → 인력·차량·장비, 가용 능력과 예약 상태 |
| 오른쪽 업무 패널 | 대상 업무, 선행 조건, 권한, 요구 자원, 차단 이유, 관련 원문·로그 |
| 하단 타임라인 | 기관별 병렬 업무, 메시지 전달, 인계, 대기 원인 |
| 상단 실험 도구 | 정지/재개, 계산상태, 저장·분기, A/B 비교, 선택 운영안 내보내기 |

작성자는 전체 상태를 분석할 수 있다. 기관 시점에서는 실제로 수신한 정보만 표시한다. 정보가 표시된 것, 확인한 것, 이해했다고 사용자가 진술한 것은 다른 사실이다.

지붕·벽을 숨기는 것은 표현만 바꾸며 충돌·통행·물리 경계를 삭제하지 않는다. 카메라·LOD·렌더 구역 로딩에 따라 운영 계산 결과가 달라지지 않아야 한다.

## 5. 맵 구축을 운영 목적에 맞춘다

첫 공간은 **외부 도착 경계 → 현장 외부 업무 공간 → 맞이방 → 승강장 → 선택 객실**이다. 부산역을 작업 대상의 기준으로 유지하되 실제 확인한 구역과 가정한 연결을 구분한다. 외부 기관 건물 전체는 만들지 않고 지도 밖 자원 노드와 접근 조건으로 표현한다.

최종 지역 확장은 기존 13개 root RegionId를 유지하되, 합성 연결·임시 치수를 실물의 정답으로 고정하지 않는다. 실제 자료가 달라지면 topologyVersion과 ID migration을 적용한다. 전국 철도망 전체는 현재 완료 조건이 아니다.

공통 실물 ID 아래 네 표현을 둔다.

1. **시각:** 메쉬·재질·애니메이션·LOD.
2. **이동:** 충돌·보행·차량 경로·수직 연결·동적 통과 조건.
3. **계산:** 체적·개구·작업 공간·물성·경계조건·모델 유효영역.
4. **의미·상태:** 기관·시설·권한·관측·버전·가용 상태.

자료가 있는 구간은 **MapAnything와 COLMAP을 초기 복원·정합 조합**으로 시험한다. 사진·카메라·깊이 자료에서 공간을 복원하는 MapAnything의 공식 구현을 사용하고, 독립 검증 치수로 정확도를 확인한다. 깊이 단위, 카메라 좌표, 재투영, 이미지 크기 변경에 따른 보정값을 기록한다. 신경망 confidence를 측정 불확도로 동일시하지 않는다. [SRC-MAPANYTHING]

GS/2DGS 표현은 선택적 연구 항목이다. 물리·충돌·재조명까지 해결한 완성 메쉬라고 취급하지 않는다. 관측이 부족한 구역은 증거 수준을 표시한 모델로 기능 개발을 이어가되 실측 수용은 보류한다.

## 6. 무료 에셋은 '기본 입고 선택'을 줄여서 고정한다

아래 선정은 실제 Unity 입고 통과를 뜻하지 않는다. 실패하면 아래의 고정 대안을 사용하고 모든 후보를 동시에 혼합하지 않는다. 25개 기존 무료 후보 원문은 `basis/free-assets.json`에 그대로 보존한다.

| 역할 | 첫 입고 선택 | 남는 제작 |
|---|---|---|
| 소방·구급·경찰 차량 | `FREE-001` RGS_Dev 차량 팩 | 실제 차종·차폭·점유·문·적재부·한국 표시 확인 및 수정 |
| 일반인·직원 베이스 | `FREE-010/011` Quaternius Animated Men/Women | 한국 기관별 복장·보조 이동·장비 동작; rig가 부적합하면 `FREE-012` 베이스 검토 |
| 기본 동작 | 기존 캐릭터 동작 → `FREE-015` Standard → 부족분 `FREE-017` Mixamo | 전문 협동 동작은 자체 제작·검수. 무료판의 실제 clip 목록 확인 |
| 외부 도로·배경·가구 | Kenney의 기존 무료 카탈로그 항목 | 실제 역사 실내 치수·연결의 근거로 사용하지 않음 |
| 철도 기능 시험 | `FREE-003` Kenney Train Kit | KTX·부산역 재현 모델이 아님. 최종 핵심 형상은 실제 근거로 제작 |
| 안전장비 | `FREE-018` Poly Haven 한국형 소화기 | LOD·부품·적용 기종·운영 데이터 확인 |
| 의료·통신 소품 | `FREE-019/020/021` AED·들것·FREE APOCA | 개별 다운로드·리깅·동작·장비 의미 검수 |
| UI | `FREE-023/024` Kenney UI·아이콘 | 기관·업무·정합성 전용 정보 설계와 아이콘 보강 |
| 일반 재질 | `FREE-025` ambientCG | 시각 재질은 물리 물성값의 근거가 아님 |

RGS 팩에는 경찰차·구급차·소방차가 명시돼 있고 무료 제공 경로가 있다. Quaternius의 두 인물 팩은 FBX·OBJ·Blend와 애니메이션을 안내한다. 한국형 소화기는 무료 모델이고, Kenney Train/UI Pack도 무료 개별 다운로드를 제공한다. [SRC-ASSET-RGS][SRC-ASSET-MEN][SRC-ASSET-WOMEN][SRC-ASSET-EXT][SRC-ASSET-TRAIN][SRC-ASSET-UI]

**결정:** 무료 자산 구매비 0원 경로를 기본으로 삼는다. 이는 가공·검증·연산·호스팅 비용 0원을 보장하지 않는다. 유료 대형 팩은 필수 선행에서 빼고, 필요한 경우 별도 의사결정으로만 구매한다. 기존 모델의 다운로드 가능성과 가공·배포 조건은 기록하되 자료 출처 자체를 삭제하지 않는다.

모델 파일이 확보돼도 운영 능력·인원·수용량·물성을 이름이나 외형에서 생성하지 않는다. 무료 팩의 형상 비율이 계산에 맞지 않으면 치수 기반 계산 메쉬를 따로 만들고 시각적으로도 오해를 낳지 않도록 조정한다.

## 7. 내부 기술 조합을 역할별로 고정한다

| 계층 | 설계 선정 | 채택 경계 |
|---|---|---|
| 3D·입력·편집 UI | 현재 저장소와 호환되는 Unity PC + C# | 엔진·렌더 파이프라인을 확인 없이 교체하지 않음 |
| 운영 커널 | 기존 운영 코드를 우선 재사용하는 C# 이산사건 실행·업무 그래프·능력 기반 자원 예약 | Unity 표현 객체와 논리 수명을 분리. 새 서버/스케줄러 중복 제작 금지 |
| 형식 검증 | timed/colored Petri net으로 검증 가능한 부분을 투영하고 TAPAAL로 대조 | TAPAAL은 우선 오프라인 모델검사 도구. Unity에 내장된 runtime이라고 가정하지 않음 |
| 공간복원 | MapAnything + COLMAP 초기 실험 | 자료·코드·가중치 고정, 독립 정합검사. DA3/VGGT 계열은 추가 비교군 |
| 보행·군중 | JuPedSim 어댑터, 기존 CFS 계열 기준과 V3/AVM 비교 | 현장 데이터로 최종 모델 선정. NavMesh와 동일 인물 위치를 이중 지배하지 않음 |
| 외부 접근·교통 | SUMO 어댑터 | 대상 교통·철도 사용사례의 범위에서 도입. 문서의 순간이동 등 가상 편의 동작은 검토·탐지 |
| 화재·열·연기 | NIST FDS 기준 계산 | 저속 화재 유동 범위. 폭발 충격파·구조붕괴·임상 결과로 범위 확장 금지 |
| 실시간 물리 가속 | 검증된 ROM/대체모델, 필요시 PhysicsNeMo의 과도상태 모델 비교 | 기준 solver·관측·독립 데이터와 보존량·시간 이력 검증 후 사용 |
| LLM | 검색·근거 기반 설명/규칙 초안/운영안 정리/대본 생성 | 승인·권한·물리값·정답 운영을 임의 결정하지 않음 |

TAPAAL의 시간·확률·유색 Petri net 및 검증 기능, JuPedSim의 복수 미시 보행모델, SUMO의 긴급차량 기능은 공식 문서에서 확인했다. SUMO의 일부 긴급차량 동작에는 silent teleport가 존재하므로 설정 이름만 보고 현실성을 승인하지 않는다. [SRC-TAPAAL][SRC-JUPEDSIM][SRC-SUMO]

FDS는 화재 연기·열 수송을 중심으로 하는 LES 코드다. PhysicsNeMo는 신경 연산자·그래프 모델 등의 개발 프레임워크이며, 철도 현장별 학습 완료 모델을 제공한다는 뜻이 아니다. FDS와 TAPAAL처럼 오래 검증된 기반과 최신 학습 기법을 결합하되 모두를 '가장 최신 발명'이라고 표시하지 않는다. [SRC-FDS][SRC-PHYSICSNEMO]

**SOTA 채택 규칙:** 최신 후보라는 이유로 자동 배포하지 않는다. 동일 입력·정제·추론/보정 예산으로 기존 기준과 비교해 정확도·실행비용·재현성·적용범위가 목적에 맞는 것을 선택한다. 아키텍처와 첫 실험 도구는 확정하지만 데이터 없이 최종 승자나 모델 가중치 성능을 확정하지 않는다.

## 8. 계산 속도와 정확도를 별도로 관리한다

표현 프레임, 운영 사건 시각, solver timestep, 현실 관측 시각을 분리한다. 물리·상태 필드별 책임 모듈은 하나다. 예를 들어 사람의 위치를 JuPedSim이 결정하는 동안 Unity NavMeshAgent가 별도로 같은 사람을 이동시키지 않는다.

각 solver는 입력/출력 단위·좌표·실행 순서·적용 영역·불확도·모델 버전을 명시한다. 결합 오차는 각 solver의 오차와 별도로 시험한다. 계산이 느리면 계산 진행 상태를 표시하거나 검증된 대체모델로 전환한다. 검증되지 않은 저정밀 계산으로 조용히 바꾸지 않는다.

분기 복원은 위치와 시드만으로 완료되지 않는다. 진행 업무·예약·메시지·기관별 수신 정보·난수 스트림·solver 내부 이력까지 복원한다. restart를 지원하지 않는 solver는 검증된 checkpoint 또는 시작 상태에서 기록된 입력을 재실행한다. 복원 불가 상태에서는 해당 시점의 정확 분기를 비활성화하고 원인을 알린다.

출력의 자격을 네 층으로 분리한다: `SCHEMA_VALID`, `MODEL_EXECUTABLE`, `DOMAIN_VALIDATED`, `APPROVED_FOR_EXERCISE_USE`. 이름이 상위라고 기관 승인이 자동 생성되지는 않는다. 검증이 끝난 모델도 맵·물성·경계조건·버전이 변하면 해당 증거의 유효성을 다시 판단한다.

## 9. 매뉴얼을 실행 규칙으로 옮기는 방법을 고정한다

규칙 원천은 문서 제목이 아니라 **기관·사건 범위·개정판·절/쪽·원문 파일 해시**다. 규칙에는 조건, 담당, 수행능력, 선행 정보, 결과, 인계, 예외, 검수 상태를 연결한다.

LLM은 원문에서 후보를 추출한다. 프로그램이 타입·참조·규칙 충돌을 검사하고, 담당 검수자가 적용성을 확인한다. 매뉴얼에서 허용하는 재량과 예외를 무조건 금지로 바꾸지 않는다. 반대로 재량을 이유로 물리적 불가능이나 다른 기관의 권한을 우회하지 않는다.

`필수 규칙 / 허용된 재량 / 권고 / 공학적 불변식 / 미확인`을 구분한다. 원문 적용성이 미확인인 기능은 연구·개발용임을 명시하고 정식 교육·현장 적용 자격은 보류한다. 영상은 역할·활동·공간 관찰 근거이며 편집 시간을 실제 소요시간으로 변환하지 않는다.

튜토리얼은 원문 기반의 설명을 제공하고 일반 모드는 같은 규칙 아래에서 운영 결정을 받는다. 매뉴얼 개정은 기존 실행기록을 덮어쓰지 않고 새 규칙 번들과 변경 영향 분석으로 처리한다.

## 10. 운영안 비교는 단일 게임 점수가 아니다

**하드 제약을 먼저 검사하고, 유효한 안들 사이의 다목적 비교를 제공한다.** 역할 위반·누락·자원 중복·불가능한 이동·허용되지 않은 정보 사용을 빠른 완료시간으로 상쇄하지 않는다.

비교 입력은 맵·초기 상태·규칙·자원·모델 버전과 통제한 외부 사건을 포함한다. 동일 시드만으로 공정한 실험이라고 주장하지 않는다. 외생 난수 스트림은 가능하면 고정·분리하고, 사용자 선택으로 달라진 결과는 내부 결과로 남긴다. 서로 다른 조건의 실험은 동등 비교가 아닌 탐색으로 표시한다.

공조 대기, 업무 완료, 자원부담, 경로·혼잡, 재작업, 불확실성과 민감도를 함께 보여준다. 관측으로 확정하지 못한 매개변수는 범위·가정으로 기록하고, 변화에 따라 A/B의 우열이 바뀌는지도 확인한다.

'세계 최적 대응'이라고 선언하지 않는다. **시험한 조건과 검증 범위에서 어떤 안이 어떤 기준을 더 잘 만족했는지**를 제시하고, 채택 여부와 이유는 담당자가 남긴다. 시뮬레이션 안에서 관찰된 효과를 현실의 인과적 증명으로 확대하지 않는다.

## 11. 로그에서 대본으로 가는 연결을 고정한다

네 산출물은 별도 버전으로 저장한다.

- 상황: 무엇이 주어졌는가.
- 운영안: 조건에 따라 누가 무엇을 수행할 것인가.
- 실행 기록: 실제 시뮬레이션에서 무엇이 일어났는가.
- 대본: 선택된 운영안과 대표 실행을 훈련에 어떻게 표현할 것인가.

특정 실행에서의 '3분에 완료'를 일반 규칙의 '항상 3분에 다음 작업'으로 바꾸지 않는다. 고정 시각, 조건 충족 시각, 시간 범위, 담당 확인 필요를 구분한다.

출력은 종합 상황전개표, 기관별 역할·업무표, 보고·안내·진행 대본, 상황부여/분기, 평가표, 근거·가정·미검증 목록, Unity 실행 시나리오다. 하나의 구조화된 운영안에서 문서와 실행 데이터를 만들고 승인 후 변경은 재검토를 요구한다.

로그 사실에는 eventId, 규범적 권고에는 적용 원문과 검토 기록을 연결한다. 사후 설명과 추측은 사실에 섞지 않는다. LLM은 허용된 schema와 동작 목록만 사용하며 생성 코드·임의 경로·새 권한을 실행할 수 없다. 문서/로그 내용에 들어 있는 지시는 데이터로만 취급한다.

음성·개인정보·로그의 외부 모델 전달은 명시적인 허용 범위로 제한한다. 최소 정보만 수집하고 개인 식별정보와 공개 가능한 실행 증거를 분리한다. 로그의 변경 추적 원칙을 개인정보 무기한 보존으로 해석하지 않는다.

## 12. 개발·출시 순서를 결정한다

| R0 운영 수직구간 | 두 기관·소수 팀·하나의 협조 업무, 작은 공간, 로그·분기·설명 | 요청→자원 예약→이동/업무→보고→후속 업무가 실제로 연결되고 A/B 차이가 기록됨 |

이 단계들은 **사용자 모드가 아니다.** R0/R1 개발 성공을 R2의 현실 정확도 승인으로 승격하지 않는다. 최종 정확도 요구를 미루어 없애는 계획도 아니다.

v10의 16팀·대응인력64·일반인120·도로차량10·열차1편성·작성자1명은 **통합 부하 시험용 가설**로 유지한다. 실제 기관 출동편성, 공식 최소인원 또는 현장 적정인원으로 쓰지 않는다. 인원수보다 공조 규칙이 먼저지만 최종 부하 조건은 시험 전에 고정하고 결과를 보고 몰래 줄이지 않는다.

첫 물리 연계 대상은 선택된 한 철도 구간의 **화재·연기 관련 운영과 사람 이동**으로 한정해 깊게 검증한다. 시설 장애·보안 의심 신고는 승인된 추상 사건 조건으로도 추가할 수 있으나, 검증하지 않은 폭발·화학·구조·생리 모델을 지원한다고 하지 않는다. 추가 현상은 개별 도입·검증 결정을 거친다.

**EP 번호는 재발명하지 않는다.** EP00 범위·평가 → EP01 규칙·계약 → EP02 운영 코어와 EP03 공간의 독립 산출물 → EP04 UI/EP05 분기/EP06 모드 → EP07 이동·교통 및 EP08 위험장 결합 → EP09 대본 → EP10 수용 → EP11 확장. 실제 phase·artifact 의존성은 보존된 계약을 따르며 이 줄을 새 전역 barrier로 쓰지 않는다. 필요한 mock 입력을 명시하면 UI·대본 후보 개발을 먼저 할 수 있지만 mock 결과로 통합 완료를 선언하지 않는다.

## 13. AAA급 품질 목표와 승인 기준을 결정한다

AAA를 외부 인증이나 독립 검수가 끝난 제품 상태로 쓰지 않는다. 내부 품질 목표로 사용하고 개별 축에서 검수한다.

**조작·가독성:** 작성자가 팀/업무를 배정하고 차단 원인·기관 관계를 이해할 수 있는가.  
**논리:** 권한·예약·인계·정보 상태의 부정 사례를 탐지하는가.  
**정확도:** 선택 수량이 독립 자료와 합의 오차를 만족하는가.  
**재현성:** 맵·규칙·코드·가중치·매개변수·외생 입력을 고정해 반복 가능한가.  
**대본:** 문서와 실행 시나리오가 같은 조건·기관·분기를 나타내는가.  
**현장 활용:** 지정 기관·용도에서 검토·수정·수용됐는가.

계산과 공간을 실제 대상과 관측 갱신까지 연결한 범위만 '디지털 트윈'으로 부른다. 동기화 전 모델은 현실 기반 시뮬레이터/디지털 트윈 프로토타입으로 구분한다. 디지털 트윈은 사용사례에 맞는 충실도와 실제 대상·프로세스의 동기화를 포함한다. [SRC-DTC]

같은 입력·같은 기준으로 결함을 재현하고 수정·재시험한다. 한정된 검수에서 해결되지 않는 자료·기관 판단은 남겨 보고하고, 무한 반복이나 합격 기준 사후 완화로 PASS를 만들지 않는다. 문서 테스트 횟수와 과거 내부 계획 등급을 제품 등급으로 상속하지 않는다.

## 14. 실행 AI에게 넘길 최소 문맥

`START_HERE.md → 이 결정서에서 해당 결정 ID → decisions.json의 EP/UR/source 연결 → basis/contracts의 해당 요구·인수시험 → 필요한 원문` 순서로 읽는다. 전체 과거 대화를 기본 문맥으로 넣지 않는다.

본 결정서의 선택 범위에서는 이 문서를 적용하고, 나머지 세부 요구·시험은 v10을 유지한다. 무료 우선 선택은 기존 유료 후보의 필수성을 대체한다. 새 사용자 요구 `UR-23`은 무료 자산 우선 정책이며, v10 원본의 UR 목록 자체를 소급 변경하지 않고 `decisions.json`에 추가 연결한다.

실제 구현 전에는 현행 저장소의 커밋·기존 모듈·work-order·수정 경로·활성 작업을 읽어야 한다. 이 문서가 그 정보를 확인한 것처럼 가장하거나 새 명령 권한을 만들지 않는다. 이번에는 원격 이슈와 기존 코드를 변경하지 않았으므로 저장소 반영은 별도 변경 작업이다.

**첫 행동은 EP00을 짧게 고정한 뒤 실제 R0 산출물을 만드는 것이다.** 모든 정밀 공간·매뉴얼을 확보할 때까지 UI와 운영 코어를 멈추지 않고, 반대로 자료가 없는데 현실 검증이 끝났다고 하지도 않는다.

## 15. 최종 결정 한 줄

**무료 에셋 기반의 명료한 RTS 화면에서, 실제 매뉴얼과 검증 가능한 다중 모델을 사용해 다기관 대응 운영안을 실험하고, 비교·검토된 결과를 훈련 대본으로 내보내는 Unity PC 프로그램으로 만든다.**

직접 링크·이번 조회 범위는 `SOURCES.md`와 `sources.json`, 기계 판독 선택은 `decisions.json`에 있다. 이 결정서의 작성·구조 검사는 실제 에셋 입고, Unity 실행, 물리·기관 검증의 성공 증거가 아니다.
