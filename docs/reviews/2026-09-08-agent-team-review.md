# PR #97·#98 에이전트 팀 적대적 리뷰

사용자가 독립된 세션의 에이전트 리뷰를 요청해 **새 세션 4개, 총 7회 리뷰 호출**을 실행했다. PR #97의 명세·적대·보안 세션은 각각 수정 전후 2회, PR #98의 그래프 세션은 변경되지 않은 그래프를 1회 검토했다. 수정된 구현의 재검토에서는 미해결 지적을 찾지 못했다. 이는 같은 OpenAI 제공자의 코드 검토 결과이며 저장소의 다른 제공자 승인 게이트는 여전히 `cannot_proceed`다.

| PR #97 · 수정 후 2차 | `00dcd1625b3d45374d0a4232a012244831445343` | 879개 추적 파일의 시작·종료 해시, 수정 diff와 전체 검증기 |
| PR #98 · 그래프 | `61309b3f83457d9b7e89de2ca409b18358bebe61` | 850개 추적 파일, 29개 노드·57개 의존성 및 canonical backlog |

기준은 `e7a6bb7a7fff0c301c04f93aeea8850dbde34779`다. 각 세션은 이전 작성 대화 없이 시작했고, 첫 판정 전에 다른 리뷰 결과를 읽지 않았다. `AGENTS.md`, context validate/brief와 해당 canonical source를 읽은 뒤 실제 파일과 diff를 검토했다. 읽기 전용은 프롬프트 지시와 전체 대상의 전후 변경 감사로 확인했으며 별도 파일시스템 sandbox로 강제했다고 주장하지 않는다. 실제 제공자는 OpenAI이고 상속된 정확한 모델 식별자는 노출되지 않았다.

## 발견과 처리

| 원 지적 | 영향 | 수정 및 재검토 |
|---|---|---|
| `adversarial/ADV-1` · P2 | 정책 glob의 FIFO가 해시 목록에서 빠져, 새 정책 입력이 있어도 기존 핀으로 통과 | 일반 디렉터리 외의 특수 파일을 오류로 처리. 실제 CLI에서 실패하고 도구 probe가 추가 실행되지 않음을 확인 |
| `adversarial/ADV-2` · P2 | FIFO 승인 manifest를 열다가 실패 영수증 없이 정지 | 일반 파일 검사, POSIX 비차단·no-follow 열기, 열린 파일 종류 확인. 일반 파일을 stat 직후 FIFO·링크로 치환한 경우도 거부 |
| `safety/SAF-R1-1` · P2 | 순회 중 바뀐 설정을 이전 승인 해시로 사용하고 성공 영수증 생성 | 순회 전후 비교, 실제 파싱할 바이트 해시 대조, probe 이후 정책 비교. 변경 시 probe를 막거나 실행 사실을 보존한 실패 영수증 생성 |

원 판정은 덮어쓰지 않았다. 명세 1차와 그래프 검토에서는 지적을 찾지 못했고, 적대·보안 1차는 `changes_required`였다. 수정 후 세 관점의 실질 코드 판정은 모두 `approved`다. 원문과 대상 manifest는 [1차 집계](../evidence/R-07-REVIEW/round1-summary.json), [2차 집계](../evidence/R-07-REVIEW/round2-summary.json)에 연결했다. 필수 필드·판정·대상 해시는 Python으로 결정적으로 대조했으며, 운영용 리뷰 그래프의 실행 강제를 구현했다는 의미는 아니다.

## 실행 증거와 한계

- 새 회귀 검사 5개를 수정 전에 실행해 실패 4개와 제한 시간 내 종료시킨 FIFO 정지 1개를 확인했다. 수정 후 Linux 로컬 검사는 73개 중 63개 통과·10개 환경별 제외다. [RED/GREEN·소스 결속](../evidence/R-07/run-20260908-04.json).
- 수정 커밋의 [Windows·Linux Required Quality Gate](https://github.com/xrlab-dau/CHOOGuard/actions/runs/34246477608)가 통과했다. 실제 OS 범위는 해당 실행 기록을 따른다.
- 검토 후 커밋은 리뷰 기록·탐색 문맥만 추가한다. 검토한 구현의 해시를 유지하며, 기록 파일을 추가한 새 PR 전체가 외부 리뷰어에게 다시 승인됐다고 표시하지 않는다. context 갱신 도구의 길이 제한으로 빠진 기존 refreshLog 항목도 복원해 이전 이력을 보존한다.
- Git HEAD가 없는 경우에도 성공할 수 있는 기존 provenance 한계, 실제 정책 소유자의 승인 핀, 105키 원본 저널 처리, 학교 PC·Unity·HMD·현장 수용은 이번 결함 수정으로 완료되지 않는다.
- 파일시스템 검사 사이의 변경·복구나 멈춘 mount I/O를 완전히 통제하는 원자적 스냅샷·실행 sandbox는 제공하지 않는다. 이미 시작된 probe를 사후 비교가 취소하지 않으며, 변경을 관측하면 성공 영수증을 거부한다.

이슈 종료, Done, PR 병합, 다른 제공자 승인이나 정책 승인으로 전환하지 않았다. 해당 요건을 바꾸지 않고 사용자 요청의 독립 세션 리뷰와 확인된 결함 수정까지 수행했다.
