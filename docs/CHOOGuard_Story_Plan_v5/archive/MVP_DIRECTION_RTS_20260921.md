# 부산역 비상대응 RTS MVP

2026-09-20 사용자 확정 사항. 활성 Story는 CS-EXEC.01.01 하나로 유지한다.

- 대상: 부산역 철도역 전체(KTX·SRT). 같은 이름의 도시철도역과 구분한다.
- 오픈월드 범위: 부산역–초량–중앙동–남포동–북항을 잇는 실제 도시 권역. 실제 도로·철도·건물의 위치 관계를 이용하며 GTA처럼 이어지는 공간으로 접근한다.
- 도시 운영의 중심: 기관 클릭 → 지원 업무 선택 → 사건·대상 클릭 → 대응팀 자동 이동·수행·복귀. 사용자가 2026-09-21 명시적으로 승인한 방식이다. 실제 위치의 기관을 거점으로 업무·대응팀·담당 구역을 관리하며, 화면에 보이는 차량·사람마다 별도 명령을 요구하지 않는다. 한 대응팀의 여러 차량은 공동 업무를 표현한다. 현장 실행 채널 배정은 자동으로 처리한다. 시민은 이동·대기·대응 상태를 쉽게 읽을 수 있도록 표현한다.
- 포지셔닝: 심시티·쥬라기 월드 에볼루션 3·RTS 운영 시뮬레이션 계열의 오픈월드 비상대응훈련 게임. 1차 사용자는 시나리오 작성 담당자이며 랜덤 비상상황을 운영·배치·대응하면서 인사이트를 얻는다. 직원·교육생의 기존 매뉴얼/사례 학습용 튜토리얼은 후속 모드다.
- 공간: 실제 역의 안내도·건물 외곽·승강장 관계를 참고한다. 2026-09-21 최신 요구에 따라 1 Unity 단위 = 1m로 통일하고 실제 공간·인물·가구·차량의 크기 관계를 유지한다. 공개자료 기반 수치와 미확인 높이·가구 등의 제작 기준값을 구분하며, 이전의 자유로운 축척 조정은 이 요구로 대체한다.
- 공간 표현: UI 밖의 설명 텍스트와 3D 문자 모델은 사용하지 않는다. 공간·시설·인물은 형상과 동작으로 표현하고 역할·상태·수치는 한국어 UI에 표시한다. 내부 상세화 범위는 부산역 전 층과 주요 훈련 거점 내부다.
- 언어: 사용자가 보는 화면·버튼·상태·오류·훈련 안내는 모두 한국어다.
- 2026-09-21 맵 재구축: 사용자가 내려받은 부산시 공식 부산역·KTX 원본을 새 오픈월드의 기준 에셋으로 사용한다. 기존 부산역과 공식 원본이 덮는 광장·주변 건물·도로의 중복 모델은 활성 맵에서 교체한다. 원본 약 450m 범위 밖의 부산역–남포동–북항은 공개 지리자료로 연결하며, 원본에 없는 내부·관공서까지 확보됐다고 주장하지 않는다. 원본 미터 축척과 근거 있는 위치 정합을 유지하고 새 출입구·도로에 맞춰 게임 기능을 연결한다.
- 에셋: 무료 모델·아이콘·폰트·소리·애니메이션을 실제 씬에서 사용한다. 이미 확보한 적합한 에셋을 재사용하고 필요한 에셋만 추가 취득한다.
- 이번 핵심 흐름: 평시 시민 흐름·팀 배치 → 같은 시민의 랜덤 사건 전환 → 현장 지시·전문 계산 → 계속되는 복구 운영 → 실제 플레이 로그 복기. 기본 한 판은 사용자 확정 20~30분이며 대응이 미흡해도 즉시 게임오버하지 않는다. 데이터 유효범위 밖은 판정 불가로 남긴다. 시나리오 초안 생성·문서 자동 작성은 MVP에서 제외한다.
- 물리 범위: 역사 화재·연기 확산과 군중 압박·병목·피난·의료 대응을 함께 다룬다. 물리·행동·결과 판정은 실제 훈련에 도움이 되는 전문 모델과 적용 근거를 요구한다. 단순 타이머 종료나 애니메이션을 물리 계산·클리어 근거로 사용하지 않는다.
- 게임화 허용 범위: 조작·배치 UI는 접근성을 위해 추상화한다. 최신 요구에 따라 건물 외관·내부 구조도 디지털 트윈 복원을 목표로 한다. 공개 근거·측정된 구조와 미확인 추정 부분을 분리하고 모델 보정 작업을 계속한다. 물리·행동 계산의 정확도 요구는 유지한다.
- 최신 우선순위: 그래픽 품질보다 게임성·행동 방식·모델링/조립 방법을 먼저 벤치마킹한다. 공식 JWE3 가이드의 입력→조건→현장 수행→피드백을 Unity의 동작으로 이식한다.
- 화면: 연속 3D 현장을 중심으로 커서 기준 휠 확대·축소와 클릭 조작을 우선한다. 기관·대응팀을 선택하는 클릭과 위치 보기·추적을 분리하고, 추적 중 사용자가 바꾼 줌을 유지한다. WASD는 선택적 보조 조작이다. 층 선택은 건물 내부를 보는 문맥에서 제공한다. JWE3의 정확한 마우스 기본값·보간 시간·내부 객체 구조는 공개자료로 확인되지 않았으므로 사용자 승인 사양과 구현 조정값을 공식 사실로 표현하지 않는다.
- 게임 분기와 Jev: 선택·업무·관찰 결과·다음 진행 조건은 내부 실행 그래프로 관리한다. Jev 출력은 내부 운영 산술에 사용하며, 별도 예측 확률·노드 편집 패널을 플레이 화면에 노출하지 않는다. 사용자는 실제 건물을 선택한 정보창에서 호출·지원 요청을 하고, 팀 행동·가용성·현장 결과로 영향을 확인한다. 메인과 조건 평가기가 실제 접수·물리 결과를 기준으로 상태를 확정한다. 대피 완료를 의료 회복으로 처리하지 않으며, 모델 확률이나 시간 계수를 실측 비상대응 정확도로 표현하지 않는다.
- 최우선 게임·UI 레퍼런스는 **쥬라기 월드 에볼루션 3**다. 팀을 선택하고 작업 대상을 지정하면 캐릭터·오브젝트가 실제 게임 상태에 따라 이동·현장 작업·복귀하는 흐름을 보여준다. 선택 링·작업 연결선·현장 상태 표식과 팀 작업 목록으로 지시의 결과를 읽을 수 있게 한다.
- JWE3의 짙은 반투명 패널·청록색 강조·간결한 팀 명령 카드·사건/목표 카드와 같은 정보 배치 원리를 참고한다. 게임 화면을 단순 관리 대시보드로 대체하지 않는다.
- 개발: Astra low 구현 워커의 독립 파일 작업을 병렬 실행한다. TDD·작은 Story 분해·반복 전수시험은 하지 않는다. 컴파일과 변경된 핵심 흐름 확인 후 실제 결함만 수정한다.
- 오케스트레이션: 메인이 작업 배정·도구 실행·통합·최종 결정을 소유한다. Jev에는 중복·중단·실패 원인·보고 과장 및 근거가 있는 추론 후보 비교를 짧게 맡긴다. Jev의 판정만으로 완료를 선언하지 않는다.
- 컨텍스트: 필요한 graph 노드와 원본 경로만 전달하고 워커 결과도 작은 graph로 받는다. 현재 세션 상태는 `.planning/2026-09-20-integrated-build/session-graph.json`에 둔다.

MVP의 실행 여부와 전체 제품 수용은 구분한다. 기존 자료·실패 기록·사용자 씬을 보존하며, 필수 기능을 시험 개수로 완료 처리하지 않는다.

2026-09-21 추가 승인: 게임개발에 필요한 OSS·개발도구의 설치와 활용이 승인됐다. 현재 프로젝트에 연결할 목적과 버전을 기록하고, 실제 사용과 호환성을 확인한다. 엔진 교체는 요청되지 않았으며 Unity를 유지한다.

판단 원칙: 사용자 요구사항은 목표·우선순위·허용범위이며 실측/성능/정확도의 증거가 아니다. Jev는 자료 탐색 후보·가설·검증과 비교를 보조한다. 메인은 원자료, 고정 버전, 코드와 실제 실행 결과를 대조해 작업을 지시한다. 모든 자료를 “사실/반증/근접 참고/불충분”으로 구분하고 관찰과 설계 추론을 섞지 않는다.
