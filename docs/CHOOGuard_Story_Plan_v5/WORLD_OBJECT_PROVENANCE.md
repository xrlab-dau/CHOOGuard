# 월드 오브젝트의 현장 근거

2026-10-02 사용자 교정에 따라, 모든 월드맵에서 실제 장소에 존재한다는 근거 없이 추가한 오브젝트와 배치를 제외한다. 이전의 훈련용 임의 내부 형상 허용보다 이 요구를 우선한다.

원본 공간 모델, 실제 도면, 사진·영상 관찰 기록처럼 대상과 장소를 연결하는 자료를 사용한다. 법규상 간격, 가장 가까운 벽, 점포 종류, 빈 공간, 모델 라이선스는 현장 배치의 근거가 아니다. 확인되지 않은 방 안에 종류별 기본 가구나 주방을 합성하지 않는다. 존재가 기록된 비품과 실제 좌표까지 확인된 비품은 구분한다.

`EquipmentPlacement.placementEvidence`가 없는 항목은 프리팹 조회, ID 예약, 충돌체·격자 생성, 설비 등록 전에 제외한다. 현재 일곱 설비 파일의 5,221개 규칙 기반 배치를 비웠다. 프리팹과 동작 구현은 보존하며, 재배치할 때 대상·장소·위치의 출처를 기록해야 한다.

부산역 실내의 활성 입력은 `content/world/observed-interiors/manifest.json`이다. `MajibangBuilder.RebuildObservedInteriors`로 재생성한다. 보존한 명시적 집기에는 기존 관찰 기록과 `sourceIndex`를 남기고, 추정 집기 39개와 자동 점포·사무실·화장실 내부 배치를 제외했다. 과거 `.planning` 입력은 이 수정 전의 작업 기록이며 활성 생성 입력이 아니다. 플레이어 주변에 소화기를 임의 생성하는 fallback도 중단했다.

원본 부산역·부지·KTX 구조와 관찰 기록이 있는 비품은 보존한다. 일부 원본 사진 파일은 현재 없으므로 관찰 기록을 새 현장 측량이나 좌표 검증으로 간주하지 않는다. 층별 외피와 시설 종류가 기록돼 있다는 사실만으로 가려진 내부 상세를 채우지 않는다.

MVP 월드는 OSM 건물과 원본 way가 확인된 랜드마크를 유지한다. 격자로 배치한 나무·가로등, 임의 실내·거점·캐노피·옥상 설비·점포 차양은 생성하지 않는다. 계산용 기준 형상은 화면에 표시하지 않는다.

이번 정리의 원본 백업, 제외 기록, Unity 실행 영수증과 검증 범위는 `.planning/2026-10-02-majibang-flow-detectors/`에 기록한다. 로컬 데이터·씬·실행 검증은 실제 현장 전체에 대한 대조 검수를 대신하지 않는다.

로컬 검증 결과: 부산역의 기존 임의 집기·소화기 루트 250개와 MVP의 임의 배치 루트 413개를 저장된 씬에서 제외했다. 부산역 원본 `FPSWorld` 784개 오브젝트의 계층·위치·메시·재질 참조와 MVP 원본 건물 배치 107개·랜드마크 3개를 보존했다. `EquipmentRegistryTests` 6개와 `FireSafetyEquipmentTests` 12개가 PlayMode에서 통과했고, JEV를 끈 부산역 근무 실행에서 제거한 카탈로그 설비·기존 임의 소화기·집기가 재생성되지 않았다. 관찰된 AED·옥내소화전·발신기 마커는 남아 있다. 저장된 두 월드맵의 끊어진 로컬 참조와 해당 실행의 신규 Unity 오류는 0건이다.

## 2026-10-05 에스컬레이터 비상정지 버튼 실측

에스컬레이터 비상정지 버튼은 코드가 '오른쪽 난간 0.9 m'라는 일반 위치에 17대 × 2곳 모두 만들어 왔다. 이제 `Assets/ChooGuard/Art/Emergency/Resources/EscalatorStops.json`의 관찰 레코드로만 만든다(`EscalatorStopSurvey`, `Escalator.AddStopButtons`). 레코드가 없는 승강장에는 버튼이 없다. 버튼이 하나도 없는 에스컬레이터에서는 곁의 승객이 비상정지를 누르는 전개(JEV 후보 `escalator_stopped`, 넘어짐 직후 정지)도 생기지 않는다. 지진·정전 정지와 역무원 열쇠 재가동은 그대로다.

공개 보행 영상·블로그 사진으로 원격 조사해 승강장과 쪽이 확인된 버튼을 레코드 8개로 만들었다(트윈 에스컬레이터 21대, 승강장 42곳).

- 2F↔3F: 상행 아래(탄 사람 오른쪽)·위(왼쪽), 하행 아래(왼쪽).
- 가운데 5·6 내려가는 줄 위(오른쪽, esc-well-m-56-1).
- 3·4 북측 데크 우물 아래(오른쪽, esc-well-n-34).
- 1층 중앙 뱅크: 올라가는 줄 아래(오른쪽)·위(왼쪽), 내려가는 줄 위(오른쪽).

여덟 곳 모두 보인 것은 유리 끝단의 빨간 비상정지 표지다. 버튼 본체·덮개·키 스위치는 보이지 않았다. 높이와 위치는 추정이며, 트윈 형상(난간 면·끝)에 맞춰 두고 레코드의 `positionBasis`에 적었다. 위치 기준은 그 승강장의 벨트 끝이다. 계단참 점은 navmesh에 맞추느라 옆으로 비켜 있을 수 있어 쓰지 않는다. 판 모양은 이 역에서 버튼 본체가 보인 유일한 기록(현대 에스컬레이터 뉴얼의 스테인리스 판과 빨간 버튼)을 따른다. 그 현대 1↔2층 한 쌍은 트윈의 어느 쌍인지 정하지 못해 만들지 않았다.

처음 esc-well-s-56에 붙였던 표지는 맞이방 북쪽 가장자리 5·6 우물의 것이었다. 발치 표지 '← 6 … 5 →'로 보면 내려가는 방향이 −z이고, 내려가는 사람 기준 에스컬레이터가 왼쪽이며, 홀 상점도 맞는다. 그래서 그 레코드를 옮겼다.

조사 중 트윈 에스컬레이터도 공식 모델·네이버 실내지도·국가승강기정보센터 등록에 맞춰 고쳤다(`StationSurvey`, 17 → 21대).

- 북쪽 가장자리 5·6·8·9 에스컬레이터 쌍을 더했다. 1↔2층 등록 20대 = 네이버 차선 수 20.
- s-56 차선을 계단에서 실제 에스컬레이터로 옮겼다.
- 1층 중앙 뱅크 두 차선의 방향을 킷 사양과 실제 뱅크대로 바꿨다.
- 가운데 쌍의 방향 가운데 관찰된 것은 5·6 내려가는 줄 하나다. 나머지는 [INFERENCE]다.

영수증과 조사 기록은 `.planning/2026-10-05-escalator-stop-survey/`에 있다(미디어는 `asset-library/research-public/2026-10-05/escalator-stops/`, 로컬 전용).

로컬 검증 결과(2026-10-05):

- 컴파일 오류는 0건이다.
- PlayMode 13개 클래스를 돌렸다. `CrowdEvacuationTests`는 이번 수정 전에는 중앙 뱅크 1층 발치(−11.4, 0, 23.4)에서 승객이 멈춰 실패했는데, 이제 통과한다. `Issue256NavigationSmokeTests`는 전체 실행에서 한 번 1.1 mm 차이로 실패했고 단독·순서 재실행 세 번은 통과했다. 그래서 두 번째 경로를 같은 자리에서 다시 묻게 했다.
- 실행 중 확인한 것:
  - 에스컬레이터 21대 중 6대에 버튼 8개가 있어 레코드 수와 같다.
  - 승객이 가운데 5·6 쌍(올라감 7명·내려감 5명)과 옮긴 s-56을 실제 에스컬레이터 위로 탄다.
  - 새 우물 끝에서 멈춘 사람은 탑승 대기로 매번 바뀌었다.

## 현장 실측 절차

공개 자료로 정하지 못한 위치는 팀이 현장에서 잰다. 역 측 허가를 받고 보고·재고·찍기만 한다. 설비를 누르거나 열지 않는다. 대상마다 ① 식별 사진(대상과 그 장소의 표지가 한 화면에), ② 번호판·관리 번호, ③ 대상 근접 사진, ④ 줄자를 댄 높이·거리 사진을 찍고, 높이·기준선에서의 거리·옆 거리를 cm로 적는다. 없는 것도 찍어 '없음'으로 기록한다. 기록은 런타임 레코드의 필드(대상 id·장소·위치 값·`placementEvidence`·`positionBasis`)와 같은 칸으로 남긴다. `placementEvidence`에는 촬영자·일시·사진 sha256·보이는 것을, `positionBasis`에는 잰 값, 트윈 좌표로 옮긴 방법, 남은 추정을 쓴다. 사진 원본은 `asset-library/research-public/<날짜>/` 아래 로컬에만 두고 영수증만 커밋한다. 에스컬레이터용 시트는 `.planning/2026-10-05-escalator-stop-survey/field-sheet.md`다. 제외된 설비 묶음(`EquipmentPlacement`)을 다시 넣을 때도 같은 절차를 쓴다.
