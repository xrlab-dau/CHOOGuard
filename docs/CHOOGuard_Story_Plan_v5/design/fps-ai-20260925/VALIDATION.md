**기계 검사의 한계:** NPC 의미 사례 16개 + 미래 의미 사례 18개 = **34개 semantic scenario와 AC01~AC25는 미실행**이다. 본 검사는 예측 정확도, 자율성, 실제 물리/인과 일치, 300명 성능 또는 게임의 재미를 증명하지 않는다. 계약 JSON이 허용/거부해야 하는 형태와 산출물 연결을 검증했다.

### 정정판 독립 검토

- 인과/자율성 검토: 동적 후보→추론→다음 상태의 반복, 자발적 목표/행동, 가상/실제 상태 분리, 개입에 따른 무효화, 실행 순서와 AC21~AC25 대조. **구체적 P1/P2 지적 없음.**
- 계약 경계 검토: actor/world 관점, root 환경 전이, 식별/중복/수명, 실패 응답·사용량, snapshot/원인/시간 의미, 실제 효과 적용 경계 대조. **구체적 P1/P2 지적 없음.**
- 두 검토는 읽기 전용이며 runtime/유료 API 시험이 아니다. cross-field/수명 조건은 구현 시 검사할 계약으로 남아 있고 schema 통과에 포함되지 않는다.

### 교훈: 도구의 인터페이스로 제품 경험을 축소하지 않기

이전 설계는 JEV의 유한 선택 primitive를 NPC 행동·완성 사건 ID 선택 중심으로 옮겨, 사용자가 원한 동적 미래와 자율 agent를 충분히 계약화하지 못했다. 당시의 형태 검사와 문서 검토 통과가 제품 해석까지 맞았다는 증거는 아니었다. **한 번의 모델 호출이 유한 후보를 평가한다는 것과, 게임 전체의 미래가 미리 작성돼 있다는 것은 다르다.** 다음 유사 작업에서는 사용자에게 보이는 핵심 루프를 먼저 명시하고, 모델 제약은 그 루프를 구현하는 합성 방법의 제약으로 다룬다. 재발 신호는 ‘동적/자율’ 요구의 수용 기준이 대사·seed·고정 pack 수만 확인하는 경우다. 이번에는 [총괄 설계](DESIGN.md)의 동적 전이/자율성 경계와 AC21~AC25의 실제 개입·행동·인과·격리 검증으로 교정했다.

## 검사 범위

- 기존 Python `jsonschema==4.26.0`의 Draft 2020-12 validator로 NPC 판단/미래 전이 요청·응답 schema와 합성 정상/거부 사례 확인.
- schema의 외부 `$ref` 없음, 원문 request hash 예시의 일치, 요구/수용/작업 ID·참조·의존 DAG·모든 요구/수용 기준의 작업 배정 확인.
- 설계 부록의 상대 링크와 실제 기존 소스 읽기 경로 확인.
- 신규 산출물의 명백한 credential 문자열 혼입 검사. 이는 실제 서비스 침투시험이나 완전한 비밀 탐지 보증이 아니다.
- 서로 독립인 판단 경계 검토와 기능/OSS/실행 범위 검토. 검토 지적은 적용 여부와 이유를 남긴다.

## 실행하지 않는 항목

이번 설계 작업에서는 Unity 실행·게임 코드 수정·씬/모델 변경·패키지 설치·빌드·PlayMode·Windows Player·과학 계산·새 JEV/대화 호출·학습·수백 NPC 부하를 수행하지 않았다. 다른 세션의 모델링 파일과 실행 중인 Editor를 조작하지 않았다.

schema 사례의 통과는 JSON 형태의 증거다. 오래된 응답 거부·실제 예약·완료·대화·자율 행동·미래 합성 등 runtime 의미는 구현 후 [수용 기준](work-packages.json)에 따라 검증해야 한다. 선행조사의 18회 JEV 실제 호출도 새 broker/수백 NPC/미래 합성의 실행 증거로 재사용하지 않는다.
