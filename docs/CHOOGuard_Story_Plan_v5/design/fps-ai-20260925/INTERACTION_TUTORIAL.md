# 상세 조작·직무별 튜토리얼 정밀 설계

기준일: 2026-09-25. **설계 제안이며 구현·패키지 설치·실행·정확도 검증 완료가 아니다.**
본 문서는 [통합 설계](DESIGN.md)의 사람/NPC 공통 행동 의미를 구체화한다. wire 필드·열거형·직렬화의 최종 소유자는 통합 설계의 스키마이며, 별도 API 서버나 경쟁 스키마를 만들지 않는다.

## 1. 범위와 확인한 출발점

- 제품은 **FPS 기반 비상상황 대응 시뮬레이션 게임**이며 기준은 [사용자 결정 원장](../../../CHOOGuard_FPS_Prior_Research_20260925/DECISIONS_AND_DEVELOPMENT_STRUCTURE.md)과 [통합 설계의 후속 정정](DESIGN.md)이다. 사람 1명, 네 직무 전환, 상세 조작, 각자 관측·욕구·목표·계획을 가진 수백 자율 NPC를 유지한다.
- 튜토리얼은 본게임과 별도 실행 공간이다. 같은 도구·설비·행동 실행기·NPC agent loop를 쓰되 튜토리얼의 오염·파손·성적이 본게임 사건으로 자동 이월되지 않는다. 기존의 벽시계 기반 실패 없음·플레이어 제어 시간 원칙을 유지한다. 교육용 반복 초기조건·도움말·안정된 복원점은 허용하며 본게임의 비상사건을 모든 실습에 의무적으로 섞지 않는다.
- 정비·청소·승무서비스·역무를 모두 설계한다. 총기전·배틀로얄, 기관사/관제 권한의 자동 취득은 범위가 아니다.
- native PC의 uGUI/TMP/Input System을 유지한다. Windows x64/Mono 실제 입력·실행 증명 의무는 [실행 계획](EXECUTION_PLAN.md)에 남긴다.

- 본게임에서는 사람의 조작·NPC의 자발적 행동으로 현재 상태가 달라지고 JEV가 그 상태에서 다음 전이와 조건부 미래를 다시 구성한다. 튜토리얼의 단계별 교수 순서는 본게임의 완성 사건 대본이나 NPC의 고정 결말이 아니다.

## 2. 공유 사실·관측·행동의 분리

1. **월드 사실**: 설치/체결, 도구 점유, 잔량, 오염, 전원, 통로의 의미 상태는 단일 world writer가 commit한다. 연속 위치/속도는 지정된 물리·이동 소유자가 계산하고 그 결과를 수용한다. 매 프레임 pose를 의미 revision/DB commit으로 만들지 않는다.
2. **인물 관측**: 관측자·대상 ID/revision·관측점·시각·감각/장비·출처를 가진다. 다른 방에서 NPC가 본 내용을 사람에게 자동 공개하지 않는다.
3. **작업 기록**: 사람이 “적합”이라고 기재한 내용, NPC의 보고, 수리 요청, 인계 수락은 실제 설비의 정상 상태와 별도이다.
4. **행동 의도**: 플레이어 입력과 NPC가 자기 목표/계획에서 자발적으로 선택한 JEV 후보가 같은 `ActorActionIntent` 의미로 실행기에 들어간다. JEV/대사/애니메이션이 직접 작업 완료나 측정값을 쓰지 않는다. 플레이어의 요청은 NPC가 고려할 관측/약속 중 하나이지 모든 행동의 필수 발동 조건이 아니다.
5. **완료 증거**: 실행기와 관측기가 기록한 상태 변화·검사 결과를 ProcedureRunner가 읽는다. action 완료와 전체 직무/설비 운용승인은 다르다.
6. **가정한 미래**: `FutureComposer`의 가상 조작/인계/대피는 실제 완료 증거·관측 기억·예약·재고·receipt를 바꾸지 않는다. 관련 실제 조작·revision 변경은 예측을 무효화/재합성하며, 가정한 플레이어/NPC 행동을 실제 실행으로 강제하지 않는다. wire는 [future-step schema](contracts/future-step.schema.json)를 따른다.

기관 명령용 `Assets/ChooGuard/Contracts/OperationMessages.cs`의 `CommandIntent`/`ReceiptKey`와 `OperationsSession`을 시민의 손동작 버스로 간주하지 않는다. run·stable ID·revision 관례를 재사용하되 시민에게 가짜 agency ID를 부여하지 않는다.

| 행동 상태 | 진입 조건·보이는 결과 | 다음 상태/실패 처리 |
|---|---|---|
| REQUESTED | 대상·동사·도구·관측/권한 revision 접수; 아직 손이나 대상 변화 없음 | 선행조건 확인 후 RESERVED; 불명·충돌은 BLOCKED |
| RESERVED | 물체/소켓/작업공간의 필요한 자원을 원자적으로 확보 | 실제 이동을 시작하면 APPROACHING; 이미 도달한 경우 바로 EXECUTING |
| APPROACHING | 이동 경로와 작업 자세로 접근; NPC가 걸어오고 사람은 직접 이동 | 손/도구 도달·접근점 유효성을 재검사; 막힌 경로는 BLOCKED |
| EXECUTING | 잡기·회전·닦기·측정 접촉 등 유효한 입력 구간만 반영 | 실제 조작 종결 후 VERIFYING; 손 놓기/권한 회수/위험 변화로 중단 가능 |
| VERIFYING | 현재 대상 revision·완료 predicate·필요 관측을 확인 | 증거가 충족되면 COMPLETED; 미확인은 BLOCKED, 실패 확정은 FAILED |
| COMPLETED | 확정된 결과와 증거 참조를 남기고 불필요한 예약 해제 | 같은 action 재전달은 중복 소비·부착·인계를 만들지 않음 |
| BLOCKED | 원인·이미 반영된 변화·계속 보유 중인 물체를 표시 | 원인 해소 뒤 현재 사실로 재검증하여 REQUESTED부터 재개; 자동 성공 금지 |
| CANCELLED / FAILED | 요청 철회 / 실행 불가능·실패 확정; 부분 결과는 남음 | 별도 후속 행동으로 회복; 완료로 집계하지 않음 |

즉시 읽기 전용 관찰은 예약·이동 없이 확인할 수 있다. 그러나 “관찰 action 완료”는 관찰한 부품의 작업 완료가 아니다.
예약은 소유권·보관책임·작업허가와 별개이다. NPC와 사람이 동시에 집어도 물체 소유자는 한 명이며, 제한시간 만료로 손에 든 물체를 남에게 순간 이전하지 않는다.
여러 자원은 안정적인 ID 순서로 일괄 확보하고 실패 시 새로 확보한 예약을 반환한다. 대기 중에는 넓은 통로 전체를 무기한 점유하지 않는다.

## 3. 데스크톱 정밀 조작의 물리·의미 규칙

### 3.1 초점, 관찰, 손/공구 도달

- 카메라 초점은 기존 최근접 solid 차폐 규칙을 유지한다. 벽 너머 target을 고르는 fallback은 없다. 자기 몸 collider만 제외하며 주변 작업물·문짝은 제외하지 않는다.
- 현재 `InteractionDistance=2.5`, 최대 3m 제한은 코드의 탐색 설정이지 인체 도달거리나 안전거리의 근거가 아니다. 관찰거리와 행동별 접촉 가능 영역을 별도 저작한다.
- 관찰은 표면 방향·가림·표시 판독 가능 여부를 확인한다. 확대/초점 보조가 텍스트 판독을 돕더라도 가려진 뒷면·내부 결함을 드러내지는 않는다.
- 손 조작은 몸→작업 자세→손잡이 경로, 도구 조작은 손→도구 끝→작업점의 sweep/contact를 검사한다. 시야가 열려 있어도 팔·긴 공구가 통과하지 못하면 실행되지 않는다.
- 작은 체결점은 가시적인 후보를 순환 선택할 수 있다. 확대된 선택 영역은 입력 편의용이며 실제 작업점/접촉 조건을 확대하지 않는다.
- 손에 든 물체가 시야를 가리면 현재 들고 있는 대상 표시는 유지하되, 그 뒤 새 대상의 관찰·집기를 허용하지 않는다.
- raycast buffer가 가득 차면 반환 순서가 최근접을 보장한다고 가정하지 않는다. 정해진 상한 내 재질의 또는 차폐 불확정으로 보류하며 벽 통과 선택을 만들지 않는다.

### 3.2 집기·운반·배치·조립

| 조작 | 필수 분해 | 월드 증거·실패 |
|---|---|---|
| 집기 | 물체 식별→집는 위치 선택→빈 손/허용 운반형태·점유 확인→접촉→grip | 실제 custody 이전; 설치된 부품·타인 보유물은 집기만으로 분리되지 않음 |
| 운반 | 목표 grip pose를 입력→충돌 제한 안에서 물체 이동→통과 가능성 확인 | 물체의 실제 pose, 충돌·막힘; 카메라를 돌려 벽 안으로 끌어넣지 않음 |
| 내려놓기 | 지지면/공간 지정→회전·미세 이동→겹침/안정성 확인→grip 해제 | 지지면 위 pose와 custody 변화; 배치 preview는 아직 실제 물체가 아님 |
| 설치 | 호환 부품/소켓 확인→방향 정렬→접근 궤적→자리맞춤 | 소켓 점유·삽입 상태; 정렬 snap만으로 체결/검수 완료 금지 |
| 분리 | 잔류 에너지·지지·연결/체결 해제 조건 확인→받침/손 확보→꺼내기 | 연결 해제와 이동 가능한 상태; 마지막 체결 해제 시 부품 순간 소멸 금지 |
| 전달 | 받을 인물·물품·의사 확인→공동 도달 영역→수신자의 실제 인수 | custody가 한 번 이전; “받겠다” 대사만으로 물체 이동 금지 |

- 자유 물체는 Rigidbody 기반 충돌을 유지하고, 잡기는 bounded target pose/속도 기반 제어로 번역한다. 손 transform에 무조건 parenting하여 장애물을 통과시키지 않는다.
- 문·서랍·레버는 필요한 자유도만 갖는 HingeJoint/ConfigurableJoint 등 제약을 쓴다. 한 장치에 kinematic transform 강제 이동과 joint 힘 적용을 동시에 지시하지 않는다.
- 나사산 전체의 미세 접촉해석은 기본 요구가 아니다. 체결점별 **의미 상태**와 눈에 보이는 회전·삽입 깊이를 결합한다. 물리 관절 하나가 안전한 체결의 증거는 아니다.
- 부품은 `분리됨→자리맞춤→설치됨/미체결→체결됨→검사됨`을 구분한다. 체결점은 `비어있음→삽입됨→부분체결→요구조건 충족`, 별도로 손상/검사상태를 가진다.
- 각 체결점은 호환 공구·회전 방향·작업 순서·체결 기준 출처를 가진다. 휠을 여러 번 돌렸다는 이유만으로 규정 토크 달성으로 계산하지 않는다.
- 검증된 토크/각도/순서가 없는 실제 장치는 **체결 상태 확인 불가**로 남는다. 무하중의 명시적 연습 지그에서 조작 문법을 연습할 수 있지만 실제 철도 부품 작업 합격을 부여하지 않는다.
- 모든 물체를 두 손으로 들 수 있다고 가정하지 않는다. 운반 형태·보조인원·장비 조건은 콘텐츠로 제한하고 미확인 중량을 임의의 1인 운반 허용값으로 채우지 않는다.

### 3.3 도구·소모품·오염·측정

- 공구 인스턴스 ID, 종류/규격, 부속 헤드, 상태, custody, 예약, 교정 참조를 분리한다. 인벤토리 슬롯은 표시일 뿐 멀리 있는 공구를 손으로 소환하지 않는다.
- 소모품은 용기/lot·내용물 식별·잔량·단위·사용가능 상태를 가진다. 실제 유효 접촉/작업 구간에서만 소비하고 잔량 부족은 작업 중단으로 남긴다.
- 오염은 표면 구역·종류/미상·잔류량·습윤 상태와 도구 오염을 나눠 기록한다. 시각 texture 제거와 소독/건조/폐기 완료는 별개 predicate이다.
- 닦기는 헤드 접촉 위치와 경로가 덮은 구역만 바꾼다. 잘못된 도구/다른 오염 구역 사용은 근거 있는 모델 범위에서 재오염을 남길 수 있다. 근거 없는 살균율을 생성하지 않는다.
- 쓰레기, 제공 비품, 개인소지품, 유실물 의심품, 위험/미상 물질은 분류가 다르다. “바닥 위 물건”이라는 이유로 동일 삭제 동사를 적용하지 않는다.
- 보유자·소유자·취급 동의는 별개이다. 불명 소지품은 알림/기록/담당 인계로 이어지며, 의심물은 열기·분해가 아니라 보호·통보·접근 제한의 대상이다.
- 측정은 장비 ID·유효 교정·올바른 범위/단위·영점/기준 확인이 필요한지·프로브 위치·안정된 시료 획득을 나눈다. 관련 요구는 해당 장비 문서에서 가져온다.
- 측정기 화면의 raw 값, 유효성/불확실성, 기록값, 판정 결과를 분리한다. 교정 만료 장비의 표시가 존재해도 그 값으로 합격 확정은 못 한다.
- 대상 변경·프로브 이탈·측정 중 전원/조건 변경은 샘플을 무효화한다. 무효 이유를 기록하고 재접촉/재측정한다. “측정 버튼 클릭”이나 애니메이션 종료는 증거가 아니다.
- 현재 `Assets/ChooGuard/Contracts/ContentTypes.cs`의 `SiUnit`에는 torque 등 모든 필요 단위가 없다. 별도 숫자 관례를 만들지 않고 통합 계약에서 단위 확장을 결정한다. 미확보 수치에는 0/default를 넣지 않는다.

## 4. 절차 그래프와 증거 판정

현 JSON v1의 `id/version/title/basis/sourceNote/steps` 및 단계 `id/label/basis/requires/allFacts/notFacts/effect/observe/failReason/conditional`을 출발점으로 삼는다. 새로운 저작 필드는 다음 의미를 갖되 wire 이름은 통합 스키마에 맞춘다.

- 절차 revision/해시·적용 기관/차종/역할·장치·근거 판본/조항을 고정하고, 대상 instance binding은 절차 정의와 분리한다. 같은 정의로 여러 소화기·좌석을 점검한다.
- 노드는 **적용 여부**, **시작 조건**, **행동 primitive**, **완료 증거**, **재검사 조건**을 구분한다. 현 `observe` 자유문장은 설명이지 기계 판정식이 아니다.
- `requires`의 DAG·닫힌 RuleExpression·whitelist 검증을 확장 재사용한다. 임의 C#/Python/LLM 생성 코드를 effect로 실행하지 않는다.
- 병행 가능한 관찰/준비는 열어 두고 위험한 의존만 잠근다. 화면은 지금 선택한 작업과 막힌 이유를 보여주며 DAG 전체를 상시 정답 순서로 나열하지 않는다.
- 현재 `conditional=true`는 guard가 UNKNOWN/CONFLICTED여도 건너뛴다. 확장에서는 **적용 FALSE만 근거 있는 비해당**이며 UNKNOWN/CONFLICTED는 판정 보류이다. 필수 증거 부재가 완료로 빠져나가면 안 된다.
- 현 `Next()`는 첫 수행 가능 단계만 반환한다. 독립 작업 선택은 동일 러너가 계산한 가용 노드 집합에서 하며 별도의 UI 전용 절차 엔진을 만들지 않는다.
- 현재 `Commit`은 runner revision만 본다. 실행기는 대상·도구·역할·예약·근거 revision을 변경 직전에 검증하고, 러너는 그 결과의 현재 완료 증거를 확인한 뒤 진행한다.
- 체크된 Done과 현재 상태를 구별한다. 한때 체결됐어도 누군가 풀면 과거 작업 이력은 유지하고 현재 설비 검사 충족은 다시 무효화한다.
- 증거에는 대상/작업점·관련 revision·행위자/관측자·행동 ID·simulation tick·측정/변화 참조·출처가 필요하다. 대사 confidence를 증거 유효성으로 쓰지 않는다.
- `RuleFacts`의 UNKNOWN은 미관측/자료없음, FALSE는 확인된 불충족이다. 서로 다른 시각의 값은 revision으로 정리하고 같은 적용 구간의 상충 관측은 CONFLICTED로 남긴다.
- 완료 사유는 “E 4회”가 아니라 “해당 부품의 모든 요구 체결점 충족·검사 유효”처럼 대상 상태를 가리킨다. 자연어 보고만으로 완료를 만들지 않는다.
- `docs/CHOOGuard_Story_Plan_v4/basis/v3/schemas/EvidenceRecord.schema.json`은 시험/검증 실행의 `testId/runEnvironmentRef` 등을 요구하는 기존 QA 계약이다. 이를 게임 안의 측정·작업 증거 레코드로 억지 재사용하지 않는다.

**소화기 예시:** 고유번호 관찰→해당 설비에 기록→제원표/계기/외관 관찰→플레이어 판정 기재→필요한 요구 인계→실물 점검표를 지정점에 부착→현장 단말에서 재확인. 적합 오판을 기록하는 행동은 성립할 수 있으나 설비가 정상으로 바뀌지는 않는다.
현재 `close-inspection` 효과는 Target의 E 흐름에서 `Audit()`를 호출하고 단말은 보고를 열람한다. 콘텐츠의 “단말 재스캔” 설명과 실제 단말 완료 행위를 맞추도록 이동하되, 단말 열기 자체를 전체 검사 합격으로 만들지 않는다.

## 5. 네 직무의 완결된 작업 체인

아래는 **게임 작업 체인 제안**이다. 출처는 역할/대상/확인 원칙을 뒷받침하며 상세 손동작 전부가 승인 SOP라는 뜻은 아니다. 미확보 수치·차종 조건은 콘텐츠 공백으로 보존한다.

### 5.1 정비: 차내 부품 검사·교체와 정비확인 인계

근거: [정비 보고서 M01·M06·M14·M15](../../../CHOOGuard_FPS_Prior_Research_20260925/RAIL_MAINTENANCE_MANUALS.md), 특히 M06 제4·9·13·14조. 실제 부품·순서는 선정 차종 매뉴얼과 모델링 자산의 교집합으로 고정한다.

1. 작업표의 차량/부품 ID·문서 판본과 실제 표기를 대조한다. 잘못된 차종·문서면 교체를 시작하지 않고 자료/작업 배정을 요청한다.
2. 자신의 수행범위, 해당 설비 격리/허가·다른 작업조 상태를 확인한다. “전원 꺼짐” 외형이나 팬터그래프 상태 하나로 무전압을 생성하지 않는다.
3. 지정 공구와 계측기를 직접 수령하고 규격·상태·교정 정보를 확인한다. 받침·부품 트레이를 충돌하지 않는 작업 위치에 운반해 둔다.
4. 해당 작업서가 허용한 접근 덮개/체결점에 접근해 도구를 맞추고 순차 해제한다. 손·받침이 없는 마지막 지지 해제는 막히며 분리 부품과 체결품은 트레이에 남는다.
5. 장치 표기·외관·접점/검사점을 관찰하고 실제 측정 시료를 기록한다. 육안 관찰을 비파괴검사 결과로 대체하지 않는다.
6. 호환 교체품을 대조→운반→방향 정렬→소켓에 자리맞춤→각 체결점 작업→요구 측정/기능 반응 확인으로 연결한다. 설치와 체결·검사는 각각 끝나야 한다.
7. 공구/분리품 회수와 작업구역 확인 후 정비확인자에게 결과·미확인·부적합을 인계한다. 수행자 완료와 확인자의 승인, 운행 재개는 분리한다.

**세계 증거:** 이전/새 부품 ID와 custody, 빈/점유 소켓, 체결점별 상태, 유효 측정, 회수된 공구, 인수자의 실제 수락. 보고서 문장만 바뀌고 부품이 그대로면 교체 실패이다.
**오류·분기:** 호환품 없음/교정 만료/체결점 손상/다른 조 작업 중이면 보류·교체 요청·전문 인계로 끝낼 수 있다. 근거 없는 현장 임기응변 수리를 합격으로 만들지 않는다.
**공백:** 토크·압력·전기 격리 순서·검사 한도·장비 조작은 미확보 항목별로 표시한다. 연습 지그 조작 완주는 실제 차량 정비승인이 아니다.

### 5.2 청소: 객실/역사 구역 정리·오염 제거·비품 복구

근거: [서비스·안전 보고서 A01–A05·C01–C02](../../../CHOOGuard_FPS_Prior_Research_20260925/RAIL_SERVICE_SAFETY_MANUALS.md). FAQ는 대상/주기 요약이며 SDS·도구 분리·소독 세부 SOP를 대신하지 않는다.

1. 작업할 실제 구역과 현재 이용객·통행을 살핀다. 카트·안내 표지를 직접 배치하고 사람 통로를 막지 않는 작업 범위를 잡는다.
2. 쓰레기와 개인 물품/유실물 의심품을 구분한다. 소유 불명 물건은 별도 기록/인계 대상으로 남기고 일괄 삭제하지 않는다.
3. 허용 폐기물을 집어 운반해 맞는 수거 용기에 넣는다. 용량/구획이 부족하면 새 용기를 가져와 교체하고 가득 찬 용기를 지정 위치로 이송한다.
4. 대상 표면·오염에 맞는 도구/소모품을 수령한다. 물질이 미상인 경우 만능 세제를 적용하지 않고 전문처리 요청/접근 제한으로 분기한다.
5. 테이블·좌석·바닥의 실제 접촉 구역을 닦고 좁은 모서리는 자세/도구를 바꾸어 작업한다. 도구 오염·잔량·습윤을 확인하면서 교체/세척/회수를 수행한다.
6. 잔여 오염과 젖은 구역을 다시 관찰하고, 비품을 해당 소켓/칸에 실제 보충한다. 보기 좋게 texture만 사라졌다고 소독 완료·통행 복구로 판정하지 않는다.
7. 폐기물/오염 도구를 인계하고 작업구역 상태를 확인한다. 표지 철거는 해당 작업의 확인 조건이 충족된 뒤 수행하며 미확인 건조 상태는 보류로 남긴다.

**세계 증거:** 구역별 잔류 오염/습윤, 도구 교체·소모량, 용기 안 폐기물, 보존/인계된 소지품, 실제 보충 비품, 카트·표지의 배치/회수 상태.
**오류·분기:** 더러운 도구 재사용·잘못 버린 개인 물건·젖은 통로 조기 개방은 가능한 실수와 결과로 남는다. 물질 금기/허가 제약은 해당 자료와 모델 범위에서 적용한다.
**공백:** 농도·접촉시간·소독 효과·PPE 조합·오염별 폐기 분류는 승인자료/SDS 확보 전 임의 수치/정답을 주지 않는다. 일반 쓰레기 정리와 화학 소독의 완료 범위를 분리한다.

### 5.3 승무서비스: 출무 수령·객실 정돈·고객지원·도착 인계

근거: [서비스·안전 보고서 A06–A09·B01·B03·D01](../../../CHOOGuard_FPS_Prior_Research_20260925/RAIL_SERVICE_SAFETY_MANUALS.md). 고객승무서비스와 운전/관제/차량정비의 권한을 합치지 않는다.

1. 해당 열차·담당 객실·지원 약속을 확인하고 무전/업무장비와 제공 비품을 직접 수령해 상태/재고를 대조한다.
2. 객실 순회 중 통로 장애물과 물품 소유자를 파악한다. 소유자에게 정리/이동 도움을 제안하고 동의한 물품만 함께 옮겨 지지되는 위치에 놓는다.
3. 고객에게 필요한 서비스를 묻고 제공 비품을 실제 저장 위치에서 꺼내 전달한다. NPC 수락·인수와 창고 잔량/고객 보유물이 함께 바뀌어야 한다.
4. 지원 요청은 당사자에게 먼저 확인하고 짧은 질문·필담/시각 안내 등 선호 채널로 전달한다. 보장구는 사람과 분리된 무주물 취급을 하지 않는다.
5. 동의된 목적지와 경로를 확인해 안내하고 이동 결과를 본다. 사람이 못 들음/거절/동행자 대기로 멈추면 재설명·대기·역무 지원 요청을 선택한다.
6. 설비 이상은 위치·관측 현상·미확인을 기록해 담당자에게 알린다. 고객승무원이 숨은 정비권한으로 수리하거나 임의로 차량 문을 열지 않는다.
7. 도착역 담당자에게 당사자 동의 범위의 지원 내용과 현재 위치를 전달하고 실제 만남·인수를 확인한다. 남은 비품·장비·미해결 요청을 마감 인계한다.

**세계 증거:** 수령/반납 장비, 제공 비품의 custody·재고, 확보된 통로, 시민의 실제 위치/동의/수신, 수신 담당자의 약속 수락과 인수 상태.
**오류·분기:** 좌석/목적지 오해·말을 못 들음·소유자 거절·담당자 미도착은 대사 생성 성공과 관계없이 미완료이다. 잘못 안내한 경우 위치 확인·정정·후속 지원으로 회복한다.
**공백:** 검표/환불·출입문·방송의 세부 권한과 차종 SOP는 별도이다. 물품 수량·리프트 하중·신체 보조·응급처치 수치를 이 체인에서 새로 정하지 않는다.

### 5.4 역무: 시설 외관점검·안내/통로 확보·직원 간 인계

근거: 기존 소화기 콘텐츠와 [서비스·안전 보고서 A09–A10·B01·B03–B05·D01–D04](../../../CHOOGuard_FPS_Prior_Research_20260925/RAIL_SERVICE_SAFETY_MANUALS.md). 기존 소방 조문 인용도 현행 원문/적용범위 재대조가 필요하다.

1. 담당 구역·설비 ID와 점검표를 대조하고 실제 소화기 표기·제원표·계기·외관의 각 면을 접근해 관찰한다.
2. 판정을 직접 기재한다. 부식이 있는데 적합으로 기록하는 실수는 기록될 수 있으며, world truth의 부식을 지우지 않는다.
3. 부적합이면 담당 책임자에게 폐기·교체 요구를 발행한다. **적합/부적합 어느 판정을 기록했든** 실물 점검표를 가져와 올바른 설비의 부착점에 붙인다. 태그를 손에 들거나 다른 설비에 붙인 것은 완료가 아니다.
4. 현장 단말에서 해당 설비를 재확인하고 미충족·오판·인계 미수락을 본다. 요청 발행과 폐기/교체 실물 수행은 같은 상태가 아니다.
5. 안내 요청을 받으면 출발/목적지·지원 선호를 확인하고 현장 통로/설비 가용성을 관찰한다. 미검증 공간을 정밀한 확정 지도로 안내하지 않는다.
6. 필요한 카트/이동 장애물을 권한·동의에 따라 옮기고 안내/통제 도구를 실제 배치한다. 바닥, 개구부, 작업자 접근 공간을 함께 확인한다.
7. 출발역→승무→도착역의 지원 연결을 유지한다. 승객과 인계 담당자가 지정 만남점에 실제 도착하고 당사자 동의/수신/인수가 확인되어야 인계 완료이다.

**세계 증거:** 대상별 관찰/판정·태그 부착, 처리 요청과 담당 수락, 보행 가능한 통로, 현장에 배치된 표지/직원, 실제 시민 이동·지원 인수.
**오류·분기:** 엘리베이터 고장·통로 막힘·인계자 부재·오판은 확인/우회/추가지원 요청으로 이어진다. 역무 역할 전환이 전기 복전·운행재개·전문구조 허가를 만들지 않는다.
**공백:** 역별 집결지·통제 위치·장비 운용·구체 안전거리는 현행 공간/매뉴얼에 종속한다. 부산역의 임의 치수·방 배치·숨은 출입구를 저작하지 않는다.

## 6. 역할 전환과 불완전한 시민·동료

- 역할 전환은 옷/카메라 변경이 아니라 업무 배정·권한 범위·보유 자원·미완료 책임의 변경이다. 먼저 들고 있던 물품을 놓거나 수신자에게 인계하고 진행 중 작업을 안전한 중단점에 둔다.
- 새 역할을 선택했다고 자격·기관 소관·설비 허가가 합집합으로 쌓이지 않는다. 튜토리얼은 해당 실습 역할을 명시적으로 부여하고, 본게임은 역할 배정 사실을 확인한다.
- 사람과 NPC 모두 손이 닿아야 만지고 같은 공구·소모품을 사용한다. 원거리 NPC 작업은 논리 실행/상태 보존을 하더라도 실제 이동/접근 시간과 자원 경합을 생략한 순간 완료가 아니다.
- NPC는 `NpcAgentRuntime`에서 욕구·일정·관측·기억/약속을 바탕으로 목표를 세우고 `GoalPlan`의 다음 행동을 먼저 시작한다. 예를 들어 본인의 목적지로 이동하거나, 장애물을 발견해 우회 정보를 묻거나, 맡은 지원 약속을 이행할 수 있다. 대사/플레이어 버튼을 기다리는 반응형 인형으로 축소하지 않는다.
- 경로 차단·공구 경합·새 보고는 현재 목표와 계획의 차이를 만든다. 목표/약속을 자동 완료·삭제하지 않고 plan revision·막힌 이유·재개 조건을 남겨 관찰/대안/협력을 선택한다. 새 관련 상태 변화 없이 같은 JEV 요청을 반복하지 않으며 NPC/미래는 [통합 설계 §7의 공통 broker 예산](DESIGN.md)을 공유한다.
- 동료끼리도 부분 지식 아래 정보 요청·분담·거절·동의를 교환하고 실제 이동/인계로 협력한다. 한 명이 문 뒤의 막힘을 보았다고 다른 인물과 플레이어에게 숨은 정답을 즉시 공유하지 않는다. 협상 결과의 문장과 물체/지원 책임의 실제 이전은 별개다.
- 상호작용의 변동은 세계 결과로 확인한다. 같은 초기 카트/통로/지원 목표에서 플레이어가 카트를 치우거나 그대로 두면 통행 가능성·NPC 관측/계획·이후 동적 후보가 달라져야 한다. 차이를 대사 표현/난수 seed에만 두지 않으며, 새 JEV 호출이 같은 답을 한다고 보장하지 않는다.
- 시민의 도움 거절·일행 기다림·잘못 들음·물건 떨어뜨림·잘못된 안내 선택, 직원의 오판·누락은 허용 가능한 행동이다. 매 순간 최선의 안전 정답을 강제하는 세계로 만들지 않는다.
- **하드 불변조건**은 벽 통과·물체 복제·잔량 음수·타인 동의 위조·작업권한 위조·증거 없이 완료·옛 revision 덮어쓰기 방지이다. 규범상 바람직함과 물리적 가능성을 혼동하지 않는다.
- 무단/부주의 행동이 사건 원인이 될 수 있어도 그것을 정식 작업승인으로 기록하지 않는다. 허용된 비준수 행동 모델에서 실제 접근·물리 조건·결과를 거치고 시민에게 정비/운행 권한을 발급하지 않는다.
- 전문 신체 이동/의료/위험물 조작이 미검증이면 만능 직접조작을 노출하지 않는다. 통보·안내·보호·전문가 요청의 실제 수행을 제공한다.
- JEV의 `shared_truth_flexible_presentation`은 표현/진행 조언이다. 근거·규칙 승인·물리적 정확도·안전 책임을 대신하는 권위로 사용하지 않는다.

## 7. 중단·재개·되감기·저장 경계

| 상황 | 필요한 동작 | 보존해야 하는 사실 |
|---|---|---|
| 조작 입력 해제/명시 취소 | 공구 작동 정지, grip/지지 안전 상태 확정, action CANCELLED | 이미 풀린 체결점·닦인 면·소비량·옮긴 물체는 그대로 |
| 초점 상실/Esc | 즉시 입력 neutral, 긴 조작 중단; 전체 sim 정지는 모드 정책으로 명시 | 숨겨진 hold 입력이 복귀 프레임에 재실행되지 않음 |
| 경로/시야/공간 변경 | BLOCKED와 원인 표시, 필요한 좁은 예약 정리 | 손에 든 물체 custody·받침·이미 발생한 오염/손상 |
| 역할/권한 회수 | 변경 직전 재검사, 신규 조작 거부, 현재 장치별 중단점 수행 | 이전 수행 이력·현재 책임자·인계 미완료 |
| 일시 중단 후 재개 | 최신 대상/도구/허가·지원 동의 재검사, 남은 동작만 시작 | 과거 측정을 최신 상태의 증거로 재사용하지 않음 |
| JEV 지연/연결 실패 | 현재 로컬 작업은 유효 조건에서 진행; 새로운 원격 선택/미래는 unavailable·stale 표시 | 네트워크 복구가 소모품·완료 상태를 되돌리거나 고정 대본을 JEV 성공으로 위장하지 않음 |
| 튜토리얼 되감기 | 아래 격리 snapshot 복원 + 새 run 분기 | 본게임·외부 NPC 기억·외부 정책학습 데이터 변경 금지 |
| 본게임 잘못된 작업 | 정정 기록·재작업·회수·대체품·담당 인계라는 후속 행동 | 삭제/거짓 undo로 사건·소모·시민 경험을 지우지 않음 |
| 관련 실제 개입 후 예측 변경 | old basis의 가상 branch 폐기, 현재 상태에서 후보/미래 재합성 | 예측했던 플레이어/NPC 행동을 강제하지 않으며 실제 목표·기억·예약은 실제 이력만 반영 |

현재 `TutorialSession.Rewind()`/`ProcedureRunner.Rewind()`는 Done와 의존 단계만 푼다. 태그·기록·소모품·물리 상태를 복원하는 기능이라고 표시하면 안 된다.
설계상 튜토리얼의 되감기 지점은 완료된 미세 클릭마다가 아니라 **안정된 작업 경계의 snapshot**이다. 도구 custody, 부품/체결, 오염/잔량, pose/속도, 관측, 절차, 예약, 실습 NPC의 욕구/목표/계획·약속·기억과 난수 상태를 함께 저장한다. 반복 가능한 초기조건은 이후 모든 NPC 선택·미래를 고정한다는 뜻이 아니다.
복원 가능한 근접 경계로 돌아간다는 범위를 보여주고, 맞지 않는 절차/자산 revision의 snapshot은 억지로 로드하지 않는다. run generation을 증가시켜 늦게 도착한 NPC/미래 응답과 가상 branch를 버린다. old generation은 dedup 조회 전에 거부하고 개인 action receipt 키 `(runId,generation,actorId,intentId)`와 저장 인덱스에 generation을 포함한다. 복원한 intentId가 버린 분기의 receipt를 재사용해서는 안 된다.
진행 중 위험한 joint/contact를 임의의 한 프레임으로 되살리지 않는다. 장치별 안정 상태에서 재개하고 복원할 수 없는 실습이면 그 실습 시작 snapshot으로 되돌린다.
본게임 저장/재개는 정지한 세계의 지속이며 사용자가 선택한 과거로 되감는 기능이 아니다. 정확한 저장 범위는 통합 실행 계획에서 정하되 “다시 열기=완료/공구 자동 회수”는 금지한다.
튜토리얼 기록 playback은 당시 입력·규칙 판본·기록된 모델 결과를 사용한다. 동일 seed로 JEV를 새로 호출하는 실습 반복은 fresh inference이며 의미 재생이나 PhysX bitwise 동일성으로 표시하지 않는다. 목표/계획 복원·예측 무효화도 실습 run 안에서만 일어나야 한다.

## 8. 키보드·마우스, 피드백, 대체 조작

| 행동 | 기본 입력 제안 | 대체/피드백 |
|---|---|---|
| 이동·관찰 | WASD/마우스, Shift 이동속도; 작업 정밀모드 진입 시 시점 속도 완화 | 재바인딩·축 반전·감도 조절; 손 도달 제한은 동일 |
| 대상 행동 선택 | E로 상황 행동 진입, 사용 가능 동사 목록 | 가시 후보 이전/다음 키; 먼/가린 대상을 선택하지 않음 |
| 잡기/작동/놓기 | 좌클릭 press/hold/release를 동사에 맞게 분리 | hold/toggle 선택, 별도 시작/중단 키; 동일 접촉·소모 규칙 |
| 정밀 배치 | 정밀모드에서 마우스/휠 이동, 축 선택 후 회전, 확인키로 놓기 | 방향키·회전키·증감 버튼; 자동 설치/체결은 하지 않음 |
| 체결/레버 | 공구를 맞춘 뒤 휠/drag로 단계적 구동 | 키 누름 지속/개별 증분; 연타 속도를 숙련/토크로 채점하지 않음 |
| 검사·기록 | 가까이 관찰→측정기 조작→값 확인→기록 | 판독 확대·텍스트 대조, 숫자 확인; 미측정 값을 자동 작성하지 않음 |
| 지원·통신 | 대상/위치 선택 후 요청·취소·인계 | 키보드 목록 제공; 위치 핑·요청 발송·수신·수락을 구별 |
| 취소·정지 | 별도 작업 취소와 Esc 메뉴 구분 | 취소 결과·부분 진행·현재 custody 표시; 위험한 자동 던지기 없음 |

- 화면 중앙에는 대상 이름·선택 동사·가장 직접적인 차단 사유, 주변에는 현재 도구/잔량·진행 행동만 둔다. 실제 근거·미확인 항목은 요청 시 열람한다.
- `REQUESTED`는 “요청 접수”, `EXECUTING`은 “작업 중”, `VERIFYING`은 “확인 중”으로 표시한다. 실패·오판을 “성공” 음향 하나로 덮지 않는다.
- 색만으로 정상/불명/불가를 구별하지 않는다. 한국어 텍스트·아이콘·필요한 작업 소리를 함께 쓰고 음성/방송은 자막으로 제공한다.
- 정밀 보조는 떨림 완화·판독 확대·선택 영역 보조·입력 지속 방식을 바꾼다. 소켓 호환·차폐·동의·권한·완료 증거는 같으며 빠른 클릭 능력을 평가하지 않는다.
- “도움 보기”는 관측 가능한 부위와 방법을 설명한다. 본게임에서 미관측 결함/위험을 벽 너머로 표시하지 않는다. 잔여 오염 강조도 해당 표면과 알려진 작업 범위에 한정한다.
- 현재 하드코딩 입력은 Input System action map으로 이행하며 이동/작업/단말 모드를 배타적으로 소비한다. UI 클릭이 포인터 캡처와 공구 가동을 동시에 유발하면 실패이다.

## 9. 저작 데이터와 모델링/Unity 인계면

다음은 저작자에게 필요한 데이터 의미 목록이다. 새 런타임 wire 선언이 아니며 [통합 설계](DESIGN.md)의 필드/버전에 합친다.

| 묶음 | 반드시 저작할 내용 | 금지/검사 |
|---|---|---|
| 대상 식별 | StableId, 설비/부품 instance와 prototype 구분, revision, 부모 설비 | GameObject.name·현재 hierarchy·Unity instance ID를 영속 ID로 쓰지 않음 |
| 작업 socket | 상대 기준 frame, 호환 부품, 삽입축/허용 자세, 점유, 체결점 연결 | 가짜 snap 범위로 벽/다른 부품 통과 금지 |
| interaction anchor | 관찰면·손잡이·공구끝 작업점·자세/작업영역·가시 collider | 관찰면을 외형과 무관한 투명 버튼으로 멀리 이동하지 않음 |
| 기구/충돌 | 움직이는 부품, pivot/자유도, collider와 시각 mesh, 지지/접촉 영역 | joint 정밀도가 실제 장치 공학 검증이라고 표시되지 않음 |
| navigation portal | 연결되는 공간/층 ID, 문/개구부, 실제 통과 영역, 잠금/가용 상태 연결 | 문 열림과 통행 가능은 별도; agent 반경/운반물과 검증 |
| 사실/증거 | 상태 변수·revision, 관측원/유효 조건, 변화·검사 predicate, 판정 근거 | 임의 스크립트 effect·텍스트 “완료”를 기계 증거로 쓰지 않음 |
| 업무 범위 | 기관/역할·담당 작업·필요 허가/자격·인수 역할·동의 조건 | 역할 이름만으로 모든 설비 권한 획득 금지 |
| 실습 초기조건/인물 | `InitialWorldSeed`의 초기 도구/설비/배치·관측, 인물 욕구/목표/약속·지원 조건, 허용된 교육 범위 | 미래 행동 순서/결말·플레이어 cue 의존을 초기조건으로 고정하지 않음; 비상사건 강제 유입 없음 |
| 출처/권리 | 문서/사진/도면 URI, 판본·쪽/프레임, 획득/관찰 수준, 적용범위·권리 메모 | 공개 열람/연구 활용과 게임 에셋 재배포 허락은 별도 |
| 공간 provenance | 관찰/측정/도면/추정 구분, 좌표계·단위·축척 기준, 모델 revision, 미확인 구간 | 부산역 실제 치수·층고·포털 위치를 창작값으로 확정하지 않음 |

모델링 담당자는 mesh/원점/관측 근거와 변동 가능한 부분을 제공하고, gameplay 담당자는 합의된 별도 바인딩으로 anchor/socket/portal 의미를 연결한다. 현재 진행 중인 자산·씬을 이 설계 작업에서 수정하지 않는다.
모델 revision이 바뀌면 바인딩된 작업점·통행영역이 여전히 표면/개구부와 일치하는지 확인한다. 이름이 같다는 이유만으로 오래된 관측점과 공간 증거를 승인하지 않는다.
임의의 연습 작업대/지그는 실제 부산역 복원 모델과 분리해 “조작 연습용”으로 명시한다. 미확보 실제 공간을 그 지그로 대체했다는 주장을 하지 않는다.

## 11. 현 코드 이행 순서와 호출군

1. 현 소화기 흐름을 공통 실행 의미로 옮긴 뒤 다중 대상 binding을 지원한다. 네 직무는 그 위에 작성하며 네 개의 독립 “완료 엔진”을 만들지 않는다.
2. `FirstPersonResponder`는 이동/관찰/입력 의도를 맡고 `IFpsInteraction`/`FpsInteractable`의 업무용 동기 성공을 action 상태 표시로 바꾼다. `SuccessfulInteractions`/`InteractionCount`는 교육 완료 증거가 아니다.
3. `TutorialSession.Bind/Advance/ApplyEffect/Observe` 호출군의 직접 mutation을 단일 실행 경로로 옮긴다. 튜토리얼은 실습 배정·안내·격리 snapshot만 소유하고 본게임을 참조하지 않는다. NPC는 P08의 자율 agent loop를 공유하며 P05 통합 완료는 P03+P08에 의존한다.
4. `FacilityInspectable`의 소화기 도메인 상태는 유지하되 공통 object/observation ID로 연결한다. 다른 직무의 오염/부품/인계를 소화기 bool에 끼워 넣지 않는다.
5. `ProcedureRunner`의 구조/화이트리스트/CAS를 확장하고 v1 콘텐츠를 새 정의 버전으로 명시적으로 변환한다. 모든 현 호출/콘텐츠를 함께 이행한 후 구 effect 경로를 제거하며 이중 writer/상시 호환 alias를 남기지 않는다.
6. `FpsGazeTracker`는 collider별 누적을 관측자·대상 revision에 맞는 관측으로 바꾼다. collider 교체/풀 반환 후 이전 물체의 관측을 승계하지 않는다.
7. `FirstPersonInteractionHud`, `FpsUiFactory`, `AuditTerminal/View`는 같은 상태 projection을 읽는다. 작업 즉시 차단 사유와 사후 단말의 미충족 판단을 구별한다.
8. `Assets/ChooGuard/Editor/FireExtinguisherSliceBuilder.cs`, `Assets/ChooGuard/Art/Procedures/fire-extinguisher-monthly.json`, 관련 scene/prefab의 binding은 자산 담당자와 합의된 별도 구현 변경에서 이전한다. 이름 prefix 삭제/재생성에 의존한 현재 builder를 새 공간 편집 권한으로 확대하지 않는다.
9. 기존 `Assets/ChooGuard/Tests/PlayMode/FpsProcedureTests.cs`, `Assets/ChooGuard/Tests/PlayMode/FpsPromptPipelineTests.cs`, `Assets/ChooGuard/Tests/PlayMode/FpsAuditTerminalTests.cs` 호출군은 변경된 소비자 행동에 맞춰 조정한다. 문자열·배선·반사 구조 단정은 완료 증거로 유지하지 않고 실제 작업/거부/중단 결과를 검증한다.

**반복 할당 방지:** 현재 `RaycastNonAlloc`만으로 전체 경로가 무할당은 아니다. `RefreshInteraction`의 `GetComponentsInParent<MonoBehaviour>()` 배열과 프롬프트 조합, GateReason→Peek→Observe→FactsFrom의 목록/RuleFacts/Decision 생성이 hot path에 있다.
collider→interaction/anchor 바인딩은 로드/등록 변경 시 캐시하고 해제 시 제거한다. 정적 정의/규칙은 한 번 컴파일하며 매 프레임 JSON/SHA/문자열 ID 파싱을 하지 않는다.
가시 초점/접촉 판정은 재사용 buffer로 수행하고, 사실 snapshot과 프롬프트는 관련 revision·현재 관측 완료 전이 때 갱신한다. 성능을 위해 실제 권한/차폐의 변경 직전 검사를 생략하지 않는다.
NPC 판단·절차 평가·UI 문자열을 매 프레임 전원 재생성하지 않는다. 지속 조작은 고정된 simulation step에서 누적하고 저장/감사 출력은 필요한 시점에만 구성한다. 실제 무할당·처리량은 Profiler로 확인하기 전 주장하지 않는다.

## 12. 구현 수용 장면: 결과·실패·경합

다음은 구현 시의 **필수 소비자 장면**이며 이번 문서 작성에서 실행한 테스트가 아니다. native PC의 실제 키보드/마우스 플레이, 상태/증거 기록 대조, 필요한 충돌·Profiler 관찰로 확인한다.
기존 조작 장면과 함께 AC21~AC25의 인과/자율성 경계를 확인한다. 통제한 초기조건·입력·기록된 추론으로 기대할 의미 결과를 먼저 정하고 실제 온라인 연결은 별도로 관찰한다. 기록 fixture는 동적 후보/실행기 검증용이며 본게임 고정 대본이 아니고, 튜토리얼은 교육 목표와 격리를 유지한다.

| 장면/초기 조건 | 행동과 기대되는 관찰 | 실패 판정 |
|---|---|---|
| 벽/문 뒤 같은 이름의 공구 | 보이는 공구만 초점; 벽 뒤 대상은 선택/집기 불가 | buffer 포화/후보 순환으로 벽 통과 집기 |
| 좁은 통로의 긴 물체 | 몸은 지나가도 운반물이 걸리면 실제 pose가 막힘; 돌리기/내려놓기로 해결 | 카메라 parenting으로 관통·갑작스런 반대편 이동 |
| 올바른 소켓에 미체결 부품 | 직접 정렬/설치 후 체결점별 작업·검사를 해야 완료 | snap/애니메이션 종료로 검사 합격 |
| 사람과 NPC의 동일 공구 동시 요청 | 한 명만 확보·집기; 다른 쪽은 이유를 보고 대기/대안 선택 | 복제·잔량 이중 차감·소유권 진동 |
| 체결 도중 취소/권한 회수 | 현재 부분체결 유지·공구 정지·남은 조건 재검사 | 0 또는 100%로 몰래 초기화·계속 작업 |
| 교정 만료/시료 후 대상 변경 | 표시값은 남되 판정 증거는 무효; 교체·재측정 요구 | 옛 값으로 정상/운행가능 승인 |
| 청소 후 모서리 오염·젖은 바닥 | 작업면과 잔류가 구분되고 실제 재작업/건조 확인 필요 | 화면 효과 삭제만으로 전체 구역 완료 |
| 쓰레기 옆 고객 소지품·지원 거절 | 쓰레기만 회수; 동의 없는 물품/신체 이동은 실행되지 않음 | 청소 클릭으로 소지품 소멸·대사로 동의 위조 |
| 승무 지원 수락 후 경로 차단 | 수락은 유지하되 이동은 BLOCKED; 재안내/역무 연결 후 실제 인계 | “안내했습니다” 발화만으로 목적지 도착 |
| 부식 소화기 적합 오판/잘못된 태그 | 오류 기록은 남고 실제 부식/태그 대상 불일치를 단말에서 지적 | 오판 입력이 정상 상태로 덮어씀 |
| 조건부 인계 적용 여부 UNKNOWN/CONFLICTED | 필요한 추가 관찰/확인이 나타나며 절차 종료 보류 | conditional skip으로 전체 완료 |
| 오래된 JEV 답·행동 재전달 | 현재 revision/예약/동의 불일치 답은 거부; 완료 action 중복효과 없음 | 취소한 요청 부활·물품 두 번 지급 |

| focus 상실 중 hold·UI 클릭 복귀 | 작동 중지·입력 중립; 명시적 새 입력만 재개 | 복귀 클릭으로 즉시 드릴/세제 작동 |
| 대체키로 같은 정밀 작업 | 선택/회전/체결/취소가 완료되고 동일 증거 판정 | 연타속도 의존·대체 조작에서 자동 완료 |
| 다수 NPC와 장시간 근접 작업 | 인물 상태/예약 보존, hot path allocation·프레임 지연 실측 기록 | 관찰 안 했는데 규모/무할당 통과 주장 |
