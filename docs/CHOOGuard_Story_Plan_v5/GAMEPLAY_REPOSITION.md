# 게임플레이 재포지셔닝 — 현장 지휘형 운영 RTS

2026-09-21. 동일 Story CS-EXEC.01.01의 설계 변경이다. 사용자가 현재 조작·접근성·UI/UX와 에셋을 거절했으므로 기존 화면을 완료본으로 취급하지 않는다. 아래는 공개 1차 자료, 현재 코드/실행 관찰, 메인의 설계 결정을 구분한 결과다.

## 1. 제품의 중심

플레이어는 부산역–초량–중앙동–남포동–북항의 연속 공간에서 사건을 읽고, 제한된 대응팀에 목표와 우선순위를 지시한다. 팀과 시민은 세계 안에서 행동하고, 플레이어는 그 결과를 보고 계획을 바꾼다. 복잡한 장비 조작이나 승인 서식 대신 공간·순서·자원의 선택에 집중한다.

**주 조작은 직접 팀 지휘, 보조는 전술 일시정지와 자율 수행이다.** JWE3의 팀/시설 선택과 작업 가시성, EMERGENCY의 사건 대상 명령, CoH3/Door Kickers의 계획 가능한 시간 흐름을 결합한다. 시나리오 작성 담당자가 플레이에서 인사이트를 얻는 것이 1차 목적이다. 초안 생성은 MVP 제외, 직원/교육생용 매뉴얼 튜토리얼은 후속이다.

## 2. 현재 버전이 게임처럼 느껴지지 않는 이유

| 실제 근거 | 문제 | 바꿀 행동 |

우클릭 드래그/클릭에는 기존 코드의 4px 구분이 있으므로 “항상 충돌한다”고 단정하지 않는다. 다만 회전과 명령을 같은 버튼에 두는 인지 부담을 줄이기 위해 카메라 회전과 명령 입력을 분리한다.

## 4. 첫 플레이 사이클

1. **상황 파악:** 사건 알림을 누르면 현장으로 이동한다. 기본 일시정지 상태에서 위험·군중·팀 상태를 볼 수 있다.
2. **지시:** 팀을 선택해 현장 대상에 명령한다. 예약된 작업선과 대상 표식이 바로 보인다. 불가능한 명령은 이유와 대안을 표시한다.
3. **실행:** 재개하면 팀이 이동·작업하고 시민이 계산된 경로로 움직인다. 지시는 취소/재배정 가능하며 실행 전후 상태를 구별한다.
4. **개입:** 전체 대피와 집단별 분산 유도 중 선택한다. 병목을 줄이면 기다리는 집단의 노출이 늘 수 있으므로 결과를 보고 다시 판단한다.
5. **복기:** 실제 실행의 시간·밀도·모델 노출량·미도달 인원을 보여준다. 동일 seed를 재실행해 선택 차이를 비교한다. 실행하지 않은 비교 결과는 생성하지 않는다.

기본 한 판은 사용자 확정 20~30분으로, 평시 운영과 장기 대응·복구를 경험한다. 현재 검증된 단기 핵심 흐름은 전체 한 판의 완성을 뜻하지 않는다. 플레이 시간과 물리 시간을 같다고 가정하지 않는다. 전술 일시정지는 계산 요청과 대응팀 진행을 멈추고 카메라·정보 조회·명령 예약은 허용한다. 현재 FDS 데이터의 유효구간은 0~120초이며 그 밖의 값을 연장해서 쓰지 않는다.

## 5. 조작과 화면

- 좌클릭 선택, 우클릭 상황 지시, 숫자키 팀 선택, Space 전술 일시정지, Shift 작업 예약, Esc 취소, F 현장/대상 초점.
- 휠 확대, 가운데 버튼 이동, 회전은 별도 입력으로 분리한다. 텍스트 입력·UI 위에서는 월드 명령을 소비하지 않는다.
- 기본 화면은 3D 현장이다. 선택 팀 카드에는 현재 목표·작업 큐·중단 이유만, 사건 카드에는 변화·목표·다음 선택만 둔다.
- 연기·밀도·동선은 선택적으로 펼치는 오버레이로 제공한다. 엔진 버전·모델 가정·유효범위는 계산 조건 상세에서 확인한다.
- 이동마다 전체 승인 창을 열지 않는다. 명령의 정당성·read-set·중복 key 검증은 보존하며, 실제 지시 입력과 그 결과를 기록한다.

## 6. 구현 순서와 판정

하나의 Story에서 다음을 연결한다: **입력 정리/전술 일시정지 → 실제 보행 엔진의 집단 대기·분산 해제 → 팀 작업/현장 피드백 → 동일 조건 재플레이·결과 비교**. 우선 출구를 임의 추가하지 않으므로 기존 FDS 기하와의 불일치를 피한다. 별도 경로 선택은 실제 계산 기하를 함께 확장할 때 구현한다.

성공은 지원되는 모형의 목표 결과로만 판정한다. 데이터 소진·모델 미지원·필수 결과 누락은 실패나 성공으로 조작하지 않고 판정 불가로 분리한다. 부산역 보정, 실제 접촉 압착력, 임상 결과, 양방향 화재 제어의 미완료는 유지한다.

확인은 반복 전수시험 대신 한 동일 seed에서 전체/분산 정책의 실제 결과가 달라지는지, 명령·일시정지·취소가 화면과 모델에 일관되게 반영되는지에 집중한다. 서로 다른 결과가 나온다는 사실만으로 실제 현장 정확도를 증명하지 않는다.

## Jev 사용과 메인 결정

`jev-gameplay-candidates-013.result.json`: 현장 직접 지휘 후보를 선택했지만 주 정체성 confidence 0.34로 낮아 `escalate`가 반환됐다. 보조 운영 위임, 첫 인과 선택으로 집단 분산 해제, 매 이동 modal 대신 상황 지시는 더 강하게 지지됐다. 메인은 사용자가 반복해 요청한 직접 팀 지휘와 현재 코드의 제약을 근거로 위 방향을 선택했다. Jev 결과를 사용자 승인이나 구현 완료로 취급하지 않는다.

현재 상태: **핵심 루프 부분 구현·실제 Editor 연동 확인**. 50명 평시 이동→동일 인물의 사건 전환→팀 도착·작업 ACK→전원 출구 도달→복구 시간 지속을 실제 워커와 확인했다. 컴팩트 팀 카드·실제 알림도 연결했다. 20~30분 전체 운영·시설 복구·자원 경제 및 최종 조작성 수용은 남아 있다. [벤치마크 이식 현황](BENCHMARK_MIGRATION.md)을 따른다. 모델 생성은 컴퓨터 use를 중단하고 Jev가 고른 제약된 파라미터를 Astra low가 Blender 명령으로 실행하는 방식이다.
