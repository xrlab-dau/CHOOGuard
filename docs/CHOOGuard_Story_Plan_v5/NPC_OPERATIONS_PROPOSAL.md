# NPC와 운영 시뮬레이션 이식 제안

2026-09-21 비교·설계와 첫 이식 현황. 평시 50명→동일 시민 사건 전환→팀 작업→지속 복구의 첫 묶음은 실제 Editor에서 확인했다. 동행·환승·시설 수리 등 아래 확장 설계는 아직 미구현이며, 문서 끝의 실제 이식 현황과 구분한다. 활성 스토리는 하나로 유지하고 시나리오 초안 생성은 제외한다.

**시민은 목적을 갖고 자율 행동하고, 플레이어는 대응팀과 구역 정책을 지휘한다.** 맵의 평상시 움직임이 사고 뒤의 피난·지원 수요로 이어져야 한다. 시민 한 명씩 이동시키는 조작을 기본으로 삼지 않는다.

JWE3와의 비교

표의 오른쪽 두 열은 우리 프로젝트의 설계 제안이다. JWE3의 구현 구조를 복제했거나 동일한 인체·군중 모델을 사용한다는 뜻이 아니다.

NPC는 네 가지 기본 행동 프로필부터 시작한다. 일반 이용객은 출입구–발매–대기–승강장을 이동한다. 환승객은 다음 연결 시간을 고려한 목적지를 갖는다. 동행 집단은 함께 이동하고 분리되면 재합류를 시도한다. 이동지원이 필요한 이용객은 계단을 피하거나 직원의 지원을 요청한다. 구체적인 반응 시간·순응도·보행 수치는 검증 자료와 설계 가정을 구분한다. 외모나 성별만으로 위험도나 능력을 판정하지 않는다.

사건이 생기면 별도의 피난용 캐릭터를 새로 덮어씌우지 않는다. 기존 인물의 식별자·위치·동행 관계를 유지하고 인지, 대기, 우회, 유도 따르기, 지원 요청, 출구 도달로 상태가 바뀐다. 애니메이션은 이 상태를 보여 주고, 실제 이동과 연기 노출은 해당 구역의 계산 결과를 따른다. 군중을 겉모습만 움직여 놓고 피난 성공 인원에 포함하지 않는다.

운영 조작은 `대상 선택 → 지시 → 현장 수행 확인`으로 통일한다. 평시에는 순찰과 대기 위치, 혼잡 구역 지원을 배치한다. 사건 중에는 경고·집단 유도·대기·구역 통제·지원 요청의 순서를 정한다. 한 팀이 동시에 여러 곳에서 일할 수 없고, 현장까지 갈 수 있는 경로와 준비 시간이 있어야 한다. 자동 출동도 이 제약을 따른다. 차량 직접 운전은 후속 선택 사항으로 두고 RTS 지시 흐름을 먼저 완성하는 편이 현재 MVP 예산에 맞다.

확대된 도시의 모든 인물을 매 프레임 고비용으로 계산할 필요는 없다. 먼 구역은 수요와 집단 이동을 간략히 표현하되 사건 영향 구역으로 들어올 때 식별자·인원·위치·기존 노출을 보존하며 상세 계산으로 넘긴다. 이것은 구현 제안이며 아직 검증되지 않은 전환 기능이다. 훈련 평가 인원과 계산 범위는 UI에서 분명히 보여 준다.

첫 구현 묶음은 **평시 NPC 흐름 → 같은 NPC의 사건 전환 → 대응팀 작업 → 결과 되돌아보기** 하나로 잡는다. 이후 실제 경로·통로 용량을 바꾸는 배치 기능을 붙인다. 버튼 접수만으로 불이 꺼지거나 환자가 회복된 것으로 처리하지 않는다. 현재 의료 지원은 요청·도착·인계 절차로 제한하고, 부상·임상 회복 및 압착력 판단은 근거 있는 모델이 추가되어야 한다. 화재 제어와 환기 변경도 해당 물리 모델이 지원한 결과만 반영한다.

공간에는 설명 텍스트를 세우지 않는다. 사람의 옷·소지품·자세·동작, 시설의 실제 형태, 선택 테두리와 UI 아이콘으로 구별한다. 선택한 대상의 역할·현재 작업·요청과 수치는 한국어 HUD에서 표시한다. 모델과 공간은 1 Unity 단위 = 1m로 맞추며, 일반 성인 1.72m·대응팀 1.78m·층간 5m는 현재 제작 기준값이지 부산역 실측값이 아니다.

Jev026은 자율 시민/직접 팀 지휘, 명시적 상태 규칙과 전문 엔진의 결합, 평시에서 사건으로 이어지는 NPC를 첫 묶음으로 추천했다. 메인이 이 결정을 채택했다. Jev를 매 프레임 NPC를 움직이는 엔진이나 훈련 성공의 승인자로 사용하지 않는다.


## 2026-09-21 실제 이식 현황

첫 묶음의 50명 평시 4지점 이동·대기, 식별자/좌표/누적 노출/Unity 개체를 유지한 사건 전환, 승인된 시뮬레이션 시간으로 진행하는 팀 작업, 실제 도착·통제 ACK 알림과 지속 복구 운영을 구현했다. 열린 Unity와 실제 JuPedSim 워커에서 확인한 결과는 `.planning/2026-09-20-integrated-build/ops-native-probe-result.json`에 있다. 이는 실제 입력 장치·20~30분 전체 세션의 수용 검증은 아니다.

아래 본문의 환승 일정·동행 재합류·지원 필요 프로필, 도시 집계↔개별 인물 전환, 시설 격리/수리/제한 재개와 자원 경제는 여전히 후속 설계다. 의료 요청은 임상 회복 판정이 아니며, 출구 도달은 안전한 영업 재개 판정이 아니다.
