# Feature Specification: M0-03 AI 도구·검토·승인 허용목록

**Feature Branch**: `feature/m0-03-ai-tool-allowlist`

**Created**: 2026-09-06

**Status**: Draft (1차 검토 반영, 승인·차단 시험·독립 재검토 미완료)

**Input**: 백로그 v1.3 §4 M0-03, 파이프라인 v1.2 §3·§6~9, AGENTS.md, 기준선 MAP-07·O-04~05, 발견 v1 AIN-01~06, Pi 설정·프로파일·워크플로

**Data Class**: PUBLIC_SYNTHETIC. 실제 계정·자격·민감 저장 위치는 공개하지 않고 역할과 비식별 상태만 기록한다.

## User Scenarios & Testing

### User Story 1 - 재현 가능한 도구 기준선 (Priority: P1)

PM은 후보·미채택·승인 도구를 구분한 허용목록을 만든다. 직접 버전만 같다고 동일 설치로 판정하지 않는다.

**Independent Test**: Pi 설정과 조사 pyproject의 직접 의존성 전부를 대조하고, 전체 전이 의존성·resolved URL·integrity 또는 배포물 해시를 확인한다. 미확인 항목은 실행 비허용이다.

### User Story 2 - 실제 실행 주체별 권한 경계 (Priority: P2)

PM은 작성·검토·검증·민감자료 처리자를 구분해 파일·네트워크·모델 전송 경계를 기록한다.

**Independent Test**: 각 주체의 위치·역할·허용 경로·목적지·전송 등급·승인 게이트가 빠짐없이 있고, 프로파일 값과 실행 시 실제 제공자가 일치해야 한다. 문서 작성 단계에서는 차단 성공을 주장하지 않는다.

### User Story 3 - 차단 시험 기대값 (Priority: P3)

M1-02~04가 실행할 부정 시험을 미리 정의한다. 테스트 ID와 검토된 argv를 사용하며 자유 문자열을 셸 명령으로 실행하지 않는다.

**Independent Test**: 아래 FR-008의 보호 대상과 우회 경로 조합을 대조해 누락이 없고 기대값이 deny인지 확인한다. 비적용은 근거와 승인 역할을 별도로 기록한다.

## Requirements

- **FR-001**: `docs/policy/ai-tool-allowlist-v1.md`에 도구, 후보/미채택/승인 상태, 버전, 소스 URL·리비전, 라이선스·원문 근거, 무결성 해시, 설치 스크립트·권한, 전이 의존성, 위치·실행 역할을 기록한다. Pi 0.85.0, pi-subagents 0.65.1, pi-agents 0.21.0, pi-exa 0.6.1, Spec Kit 1.0.4, BMAD 6.12.0, pydantic-ai-harness 0.29.0, pydantic-ai-slim[openai] 2.40.0, 공식 Unity CLI Editor MCP(학교 관측 1.0.0-beta.8)와 `com.unity.pipeline`(채택 정확 버전 별도 고정), 선택적 pi-mcp-adapter, Node, uv를 모두 등재한다. pi-mcp-adapter는 Pi에서 필요한 경우만 검토하며 native MCP 직접 연결의 선행조건이 아니다. 공식 CLI/Pipeline의 라이선스는 Coplay의 MIT 표기에서 추정하지 않는다. 선택·설치·동작 상태는 [ADR 0006](../../docs/adr/0006-official-unity-editor-mcp.md)을 따른다. Node major 22 이상은 호환 조건일 뿐 설치 고정값이 아니다. uv 허용 버전과 머신별 정확한 런타임은 PM 결정 전 미정이다.
- **FR-002**: 작성·검토·조사·reducer·검증의 실제 제공자와 모델을 등록한다. 임의 override·상속·fallback을 허용하지 않는다. Pi 프로파일뿐 아니라 Python 하네스도 별도 허용목록 검사 대상으로 둔다. 미등록 모델은 네트워크 호출 전에 거부한다.
- **FR-003**: 순수 리뷰어는 read/grep/find/ls만 사용하고 파일 접근은 모델 밖 읽기 전용 실행 경계로 강제한다. verifier는 별도 격리 실행 검증자다. 통합 소스는 불변·읽기 전용이며 승인된 생성 폴더·빌드·임시 로그에만 쓸 수 있다. 확정 증거는 append-only다. 리뷰어 출력은 `outcome, actionable, notes`, 병합 출력은 `outcome, reason, actionable, report`다. 지적의 필수 필드와 enum은 ADR 0003을 따른다. 필수 관점 오류·누락, 스키마·실제 제공자·target manifest 불일치는 cannot_proceed다. 현재 YAML의 나머지 결과 승인 동작은 이 계약과 충돌하므로 수정·시험 전 실행 승인을 금지한다.
- **FR-004**: MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause의 실제 라이선스 원문·고지 의무를 검토한다. NOASSERTION·미확인·제한 라이선스는 자동 허용하지 않는다. vendored 배포물의 재배포 고지·라이선스 파일도 확인한다. 미판정 항목을 목록에서 숨기지 않고 미채택으로 남긴다.
- **FR-005**: 파이프라인 §6.1의 Pi 컨트롤러, Pi 파일·셸·자식 에이전트, 호스트 확장, 공식 Unity CLI·Pipeline·실제로 사용하는 Pi adapter, Unity·Blender 실행자, DA3·Open3D 민감자료 처리자, Independent Verifier, 독립 리뷰어를 각각 기록한다. 열은 실제 위치, 역할, 허용·금지 경로·mount, hostname/IP, port/protocol, 방향, 직접·프록시 경로, 전송 목적·등급, 승인 게이트, 검증 시험 ID다. 기본 네트워크 거부이며 미기재 목적지는 차단한다. school-pc 행은 D-01~09 답변과 사람의 환경 확인 전 미확정이다. 미확정 행이 있으면 그 프로파일의 M1 실행은 금지한다.
- **FR-006**: 보호 경로와 승인 범위를 하나의 정책 목록으로 고정한다. 최소 AGENTS.md, .pi 전체, .specify/memory, .github, scripts/ci, docs/evidence를 포함하며 ADR·조사 코드·기록 추가 보호는 PM이 승인한다. KORAIL 접근·이동·업로드·삭제, 권한·보안·네트워크 변경, 비상업·출처불명·제한 라이선스 도입, 보호 브랜치 병합, 릴리스·외부 배포·게시, 데이터 삭제·마이그레이션은 사전 승인 대상이다. 승인 증거를 모델이 스스로 만들거나 수정하지 못하게 한다.
- **FR-007**: 자료 접근, 모델 전송, 공개·병합의 승인 역할과 대체자를 구분한다. 하나의 승인이 다른 종류의 승인을 대체하지 않는다. 개인 로그인과 매핑은 공개 파일이 아닌 GitHub 권한 설정 또는 별도 비공개 기록에 둔다.
- **FR-008**: BT-nn 행마다 보호 경로 읽기·쓰기·삭제, 각 제한 확장자와 PUBLIC_SYNTHETIC 외 등급의 외부 전송, 비허용 패키지 설치, 원격 코드 실행, 승인 없는 병합을 시험한다. 직접 셸·자식 프로세스·호스트 확장·MCP 직접 및 프록시·Unity/Blender·심볼릭 링크와 junction·스크린샷/이미지 경로를 포함한다. 행은 입력 fixture ID, 고정 test ID/argv, 기대 deny, 실행 주체, 검증 단위, 적용 근거를 가진다. 실제 비밀·KORAIL 자료가 아닌 합성 fixture만 사용한다. 필수 리뷰 실패·대상 변경·허용목록 변조도 차단 시험에 포함한다.
- **FR-009**: 정책 해시는 명세 001 FR-006과 동일한 검토된 `POLICY_GLOBS`를 사용하고 허용목록 문서를 추가한다. 조사 pyproject·uv.lock, 추적된 npm 직접 manifest·전체 lock·integrity를 포함한다. `.pi/npm`의 ignored lock만으로 재현성을 주장하지 않는다. 별도 추적된 설치 manifest에 정확한 직접 버전·전이 그래프·resolved·integrity를 고정하고 검토된 `npm ci` 절차로 동일 결과를 확인한다. 필수 파일 누락은 실패다. 정렬·형식·생성 명령은 검토된 생성기를 단일 출처로 사용한다.
- **FR-010**: 이 단위는 허용목록과 시험 기대값을 정의한다. 차단·격리·공급망 검증의 실제 성공은 해당 M1 영수증 전에는 선언하지 않는다. 표의 존재나 YAML 파싱만으로 실행을 허용하지 않는다.
- **FR-011**: 작성과 다른 제공자의 독립 검토가 필요하다. PM/controller가 반환값 스키마·실제 모델·대상 manifest를 검증하고 정제된 판정을 docs/reviews에 배타적으로 추가한다. 저장 실패는 다음 라운드를 차단한다. 수정·반박·대상 변경 후 반드시 새 독립 검토를 받는다.

## Success Criteria

- **SC-001**: 설정·직접 의존성 및 조건부 도구의 목록 누락이 없다. 미채택 항목은 비허용 상태가 명시돼 있다.
- **SC-002**: 승인으로 표시된 모든 도구는 라이선스·고지·해시·설치 스크립트 검토가 완료됐다. 미판정 항목은 실행할 수 없다.
- **SC-003**: FR-008의 모든 보호 대상·우회 경로가 시험 행 또는 승인된 비적용 근거와 연결된다.
- **SC-004**: 같은 정책·의존성 입력으로 해시를 재생성하면 일치하고 누락·변경 fixture는 실패한다.
- **SC-005**: 조기 차단 성공 주장이 없다. 미확정 학교 PC 프로파일과 필수 관점 오류로는 승인되지 않는다.

## Applicable Definition of Done

백로그 §2 중 1, 2, 3, 4, 6, 7, 8, 11, 12가 적용된다.

## 산출물 추적

허용 도구·의존성 표는 FR-001, 제공자 표는 FR-002, 검토 정책은 FR-003, 라이선스 표는 FR-004, 실행 프로파일은 FR-005, 보호 경로·승인 대상은 FR-006, 승인 역할은 FR-007, 차단 시험 표는 FR-008, 해시 manifest는 FR-009에 대응한다. FR-010·011은 이 산출물 전체의 정직한 상태 표시·독립 검토 요구다.
