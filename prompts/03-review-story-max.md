# 03 · 필요한 변경 코드 검수 — 선택 도구

STORY_ID = CS-EXEC.01.01

필요한 때 변경된 코드에 한정해 검수한다. 모든 항목에서 복수 모델 전수검수·자동 재검수 루프를 돌리지 않는다.
`docs/CHOOGuard_Story_Plan_v5/ACTIVE_STORY.md`, v5 JSON, 실제 변경분·관련 시험과 v4 계약 원문을 읽어라. v5는 개발 절차만 대체하고 v4/basis 제품·안전 요구는 유지한다.

- 실제 변경 revision과 관련 동작·오류 경로·쓰기 범위·데이터 무결성·안전 계약을 대조한다. 구현자 주장만으로 PASS하지 않는다.
- 필요한 관련 시험/반례만 확인한다. 0개 수집·skip·다른 코드의 증거를 성공으로 간주하지 않는다. 문서 보완만으로 Unity·전체 시험·전체 hash·graph를 반복하지 않는다.
- Bootstrap 부분 로컬 결과와 Windows/Player·현장 수용 미완료를 구분한다. 통합 관리가 전체 제품 완료나 기관 승인을 뜻하지 않는다.
- 실질 결함만 정확한 경로/위치, 관측·기대 결과, 영향, 최소 수정 방향으로 짧게 보고한다. 불가능한 검증은 NOT_RUN 이유를 적고 영향을 한정한다.
- v4의 과거 phase·receipt 승인 절차를 새 게이트로 강제하지 않는다. 필요한 코드 검수 1회의 결과를 반환하고 별도 대형 REVIEW 세트는 만들지 않는다.

제품 코드·원시 증거·진행 장부를 검수자가 임의 수정하거나 자동 ACCEPTED로 승격하지 않는다. 설치·commit/push/PR·외부 게시를 하지 않는다.
