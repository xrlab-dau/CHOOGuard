# 01 · 큰 설계 변경 판단 — 선택 도구

STORY_ID = CS-EXEC.01.01

큰 설계 변경이나 안전/데이터 무결성 문제가 있을 때만 사용한다. 작은 구현마다 계획 승인을 반복하지 않는다.
`docs/CHOOGuard_Story_Plan_v5/ACTIVE_STORY.md`와 v5 JSON, 이번 변경에 관계있는 v4 원문·코드만 읽어라.

1. 해결할 문제와 기술적 선후 관계·실제 입력을 확인한다. 과거 phase receipt·parent gate 승인을 전제로 하지 않는다.
2. 포함/제외 범위, 정확한 허용 쓰기 경로, 바뀌는 공개 계약, 정상/반례 시험과 미실행 한계를 짧게 정한다. v5는 개발 절차만 대체하며 v4/basis 제품·안전 계약·AC/AT는 유지한다.
3. 기존 Bootstrap 부분 구현을 재사용하되 전체 제품이나 영역 완료로 올리지 않는다. Windows/현장 입력 부재는 해당 검증만 보류한다.
4. 필요한 결정만 요청한다. 별도 Story·활성 child·스케줄러·PLAN/CONTEXT 인계 세트나 109개 승인 체계를 만들지 않는다.

승인 없이 제품 범위를 확대하거나 모델 설정을 바꾸지 않는다. 전체 자료 재작성·Unity 재실행·graph 재생성·설치·commit/push/PR·외부 게시를 하지 않는다.
