# Seeded material, logical binding and cache contract

This is the current source/portable contract. It does not certify actual subscription NPC behavior, whole-world Unity playback, field calibration or the latest station construction epoch. The active helper/private OAuth accounts were not restarted or migrated for this change. Provider registration/login rules and the strict subscription-only 8-key routing protocol remain unchanged.

The external model proposes at most16 bounded upstream min/max priors. `InitialConditionMaterial` freezes those priors with material schema, sampling version, structural applicability and selected logical model binding into immutable content SHA256. The current sampler is bounded uniform and the bounds are **INFERRED_TRAINING assumptions**, not learned/calibrated railway failure distributions. Every entity contributes to initial input/coverage; only typed supported upstream properties may be changed. No completed emergencies or scenario lists are stored or selected.

The reproducibility tuple is **engine/RNG/materialization version + immutable material SHA + exact applicable source/initial state + seed + ordered player/external inputs**. A fresh LLM response is not determined by a seed and becomes distinct material content. The code never forwards unsupported provider seed controls or describes temperature0 as a determinism guarantee. The same material and seed reproduce local samples; different human actions or fresh model plans remain different external inputs and must be recorded for replay.

`ProviderSelection.Fingerprint` continues to cover the exact8-key routing lease, including `session_generation`. All network calls still require the exact selected provider/account/model and current consent lease, and both success and failure from an old lease are refused. `LogicalFingerprint` separately covers `provider-logical-binding-v1`, provider ID, SHA account reference, model ID, catalog version, selection contract, billing and own-app registration. `CacheVersion` is now `user-subscription-v3` plus that logical fingerprint. An ordinary auth lease renewal does not manufacture a new model/prior identity. Provider/account/model/catalog/contract changes do; no cached material grants credentials or authority to another account.

The process-local `InitialConditionMaterialStore.Shared` pins first accepted entry per key. Its key-v3 includes structural applicability SHA, logical binding SHA, prompt/proposal contract, explicit coverage SHA, **the actual complete model request/prompt SHA**, and revision. The actual input fingerprint covers the client body with model/system/user prompts/source seed and exact basis/output policy, before the transport injects the volatile8-key lease. Original full request/reply hashes are also kept as provenance. No seed, numeric state or NPC pose is silently deleted from model input to obtain a cache hit. Any seed/context/body/coverage change is therefore a miss, even if structural applicability remains equal. A new seed can additionally change capability tags, state schema or relations in the world factory. Reuse is guaranteed for the same exact eligible request key, not every future seed. Explicit saved material can separately sample another structurally eligible seed through local materialization; that is a declared saved-artifact input, not a fresh model query or an implicit online cache hit.

Default ledger limits are64 entries/8MiB/one source factory at a time; each serialized entry is at most512KiB. Capacity is rejected before a new factory when already exhausted. Entries are not silently overwritten or evicted. An explicit revision key can store a distinct proposal; current composer uses its pinned default key and has no product UI command to re-propose priors for the same key. Same-key concurrent misses coalesce into one source factory. Cancellation returns to a caller promptly while an uncooperative source retains its in-flight slot until it actually completes. That late result cannot commit to the ledger or world, and another waiter never causes a duplicate concurrent factory. Factory failures/quota refusals are explicit; no API key, other model/account/provider, JEV or local model inference fallback is called.

On a live cache hit the source factory/budget admission/model inference are zero, but the caller must still have the current local selected consent lease. Source/network authority remains in the helper; cache lookup does not perform a fresh remote entitlement query or guarantee current upstream quota. `PutRecorded`/`ReadRecorded` are explicitly offline, require exact key and entry SHA, and contain only credential-free logical provenance/material data. This class does not read or write files, private accounts or global config. Run records carry the immutable material/entry; persistence beyond the process requires restoring that exact recorded entry. There is no implicit cross-session filesystem cache.

The bound-provider composer implementation follows this sequence:

```text
validate explicit action, stopped initial world, cancellation and exact local lease
capture exact initial digest; build all-world request and exact model-input/applicability/coverage key
lookup pinned material under that logical binding
if eligible cache hit: source calls = 0; token-budget reservations = 0
if cache miss: singleflight source factory on an independent world copy
    reserve the bounded model budget; call exact selected subscription model
    validate reply/usage/basis/priors; freeze immutable material
    require matching key, provenance and still-current owner lease before pinning
verify caller lease, cancellation, stopped state and exact original digest again
sample frozen material with local seed; atomically validate/apply upstream changes
record material/entry SHA, cache disposition, exact state and source usage (if any)
```

The source factory samples/applies to a private copy for validation; the actual play world is written only at the final guarded materialization. A cache-hit record contains materialization data for the identical request and the original material source hashes; it does not invent a newly returned provider model or new provider token usage. Fresh responses have distinct source/provenance entries; identical prior contents can legitimately share a content SHA while their request/reply entry SHA differs.

NPC inference remains separate from initial material sampling: fresh NPC plans are external action proposals. `PlanningCoordinator` now writes `planning-record-v3` with explicit monotonically ordered `RecordIndex`. A `generator_admission`/`evaluator_admission` row is written on the simulation `Poll` tick for admission or budget/affordance deferral. An actual `generator`/`evaluator` row records its original admission tick and the later simulation `Poll` tick that validates/accepts/rejects the asynchronous reply. Backend response time is not substituted for Unity apply tick. The existing host flushes these rows with each Tick after planning and guarded execution. Budget refusals preserve the goal and retry after the20tick cooldown, retaining immediate local plans without another provider path.

The local `ReplyJson` string now has an explicit `ReplyEncoding=local-exact-json-tree-v1` and contains a typed exact reply tree built directly from the CLR provider-reply DTO. Outer tape encoding alone cannot preserve doubles that were already rounded inside an ordinary JSON string. `PlanningCoordinator.ReadRecordedReply` is the shared exact decoder for replay and local benchmark consumers. A `(0,1]` one-ULP operation amount is tested through actual planning admission/reply recording/replay and local suppression effects/digest. Old v2/lossy reply records fail the version/encoding guard; no old record is relabeled or its lost bits claimed recovered. Actual provider request/response JSON remains unchanged.

The local file consumer `model_service/InitialWorldNative.Load` decodes only new typed `.jsonl` headers with the same `LocalTapeCodec.Parse` as the FPS host. ISO date literals, exact IEEE754 values, signed-zero float/double promotion and unsigned counters are tested through the actual CLR `LocalTapeCodec.FromObject` builder, file write and consumer read. Date/string parsing is local-only; provider/native management JSON is not changed. Original implicit-double/JValue sign-loss failure packets were retained separately from the corrected production-builder fixture.

Replay requires exact record version/order/request JSON/admission tick/response apply tick/disposition; it reuses saved responses with provider calls0. `EnsureReplayConsumed()` refuses natural completion while records remain pending/unconsumed. User abort/partial playback is separate from completed replay. Current pure fixtures include defer tick0 → admit20 → apply21 and delayed reply tick5 → apply6. Real Unity asynchronous timing and physics resimulation remain UNVERIFIED.

Executable plan cache geometry/state/request hashing now uses typed JSON and exact-f64 bit strings, so separators inside object IDs/tags/links/keys cannot alias distinct dependencies. Source type, topology, Nav, relevant reads, model/prompt/executor policy and dependency existence/geometry must still match; copied cached plans are checked again by the local executor. This is AgenticCache-inspired guarded reuse, not an import of the entire upstream system or a claim of that paper's reported savings. Canonical hashing is tested within this C# implementation; no cross-language identical-byte claim is made.

Budget admission uses difference comparisons rather than overflowing sums. Reservations are immutable and belong to one budget. Negative usage, overrun or settlement overflow closes the circuit; counters saturate at `long.MaxValue` instead of wrapping negative, and existing reservations are closed even when accounting is invalid. Duplicate/foreign settlement is refused without altering the owner budget. UTF8 admission estimates and reported provider token usage remain distinct, and failed/missing usage stays conservatively charged. Initial user allowance is still one-shot in the helper; a material cache hit does not consume it because no inference is sent.

Input reservation units are payload-based admission estimates, not exact provider tokenizer counts or a guarantee of every provider's billed-input ceiling. Backend prompt overhead and tokenizer behavior can differ; actual usage is settled separately and an overrun stops future calls after the already attempted request. Output limits are the implemented adapter/request-control contract, not evidence about all providers or a universal billing guarantee. The current targeted suites have no dedicated Korean/Unicode tokenizer or billing-bound fixture; no such measurement is claimed.
