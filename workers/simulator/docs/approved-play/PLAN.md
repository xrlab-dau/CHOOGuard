# 비상상황 생성·NPC 이동/행동·랜덤 시드 승인 방향 인계

2026-10-16 사용자 지시와 기존 simulator 설계를 다음 PC에서 이어 구현하기 위한 문서다. 이번 PR에는 계획·아키텍처·의사코드만 포함한다. 로컬에서 작업한 Unity 통합 코드·씬·자산·계정·실행 로그는 이 PR에 포함하지 않는다. 문서 머지가 Game 플레이 구현의 원격 반영을 뜻하지 않는다.

## 사용자가 확정한 방향

- 비상상황은 고정된 사건/시나리오 목록 추첨이 아니라 현재 객체·상태·관계에 기반한 인과 전개로 만든다.
- 초기 상류 조건 생성에는 사용자가 선택한 provider/model을 사용한다. 같은 provider/account/model을 NPC 계획에도 고정한다. 사용자는 구독 사용을 허용했고 이번 작업의 모델로 GPT-6-Luna를 선택했다. 계정별 모델 목록과 사용 허용은 각 PC에서 다시 확인한다.
- NPC는 개인 관측·기억·지속 목표·반응 지연을 가진다. 필요한 행동 계획만 비동기로 생성하고, 유효한 의존 조건에서는 캐시를 재사용한다.
- 실제 이동은 현재 형상에서 얻은 이동 표면과 완전한 경로를 사용한다. NavMeshAgent가 위치/속도를 소유한다. 모델이 좌표를 직접 바꾸거나 통과 불가능한 벽/층간 연결을 만드는 방식은 쓰지 않는다.
- 플레이 시작 뒤 튜토리얼과 랜덤 비상상황 대응을 선택한다. 열차점검 튜토리얼은 오프라인 실습이며 provider 로그인에 종속되지 않는다.
- 기존 공식 객체, 사용자 편집, 승인된 구조 좌표를 보존한다. 건축 수정과 행동/인과 구현은 별도 작업이다.

## 구현 순서

1. 현재 저장 씬과 객체 inventory/의미/능력 대응을 확인하고 원본 위치를 보존한다.
2. 플레이 모드 선택과 동일 provider 선택 lease를 연결한다. 로그인/모델 선택/사용 허용 자체로 추론을 시작하지 않는다.
3. 정지된 tick0의 전체 객체·부모·관계·상태·능력 그래프에서 초기 상류 조건을 명시적으로1회 생성한다. 범위와 seed/basis를 검증하고 immutable material을 만든다.
4. material과 run seed로 초기 값을 샘플링한 뒤 로컬 인과 커널을 고정 틱으로 실행한다. 이후 각 틱이 모델을 호출하는 구조로 만들지 않는다.
5. 개인 관측→기억/목표→유효 캐시 또는 필요한 새 계획→실행 조건 검사→NavMesh 이동/행동→도착/실패 피드백을 연결한다.
6. seed, source/engine/RNG 버전, material, 수락한 모델 응답, 순서 입력과 실제 이동 관측을 기록해 재생 입력을 보존한다.

## 시드와 현재 상태를 혼동하지 않기

시드는 초기 자료 샘플링과 NPC 반응/목적지 선택 등에 사용한다. 독립 RNG stream은 version/seed/stream/tick/entity/draw의 tuple로 파생해 UI나 다른 NPC가 난수를 소비해도 결과가 섞이지 않게 한다.

현재 로컬 저장 씬의 기본 시드는 `20261016`이다. 빈 시드를 새로 생성하는 코드와 준비 화면의 수동 변경은 있으나, 매 근무마다 새 시드를 자동 생성하도록 기본 설정을 전환한 상태는 아니다. 다른 PC에서 새 실행/명시 시드/기록 재생의 시드 선택 UI와 정책을 이어 확정·구현해야 한다. 이 문서가 그 미완료 부분을 완료로 바꾸지 않는다.

외부 LLM의 새 응답은 seed만으로 같아지지 않는다. 동일 자료·동일 구성·동일 seed의 로컬 샘플링과, 새 모델 요청의 결정성은 구분한다. 실제 provider body에 seed가 포함되므로 새 seed는 새 입력 key이며, 모든 새 seed에서 호출0을 보장하지 않는다.
