사용자 요청으로 추가 구현·측정을 여기서 중단하고 `chore/42-school-pc-setup`의 현재 변경을 `develop` 대상 드래프트 PR로 전달한다. 이 문서는 완료한 검증과 재개할 작업을 구분한다. 병합·이슈 종료·제품 수용 기록이 아니다.

## 완료한 변경과 확인

- 기존 학교 PC checkout과 설정 작업을 보존했다. GitHub에서 PR #61의 `develop` 병합을 확인했으며 기준 커밋은 `f2011ac2cd4510a09c78f0de111771fc5aa433e8`이다.
- PowerShell 5.1의 한글 스크립트 파싱에 필요한 UTF-8 BOM, Unix 권한 시험의 Windows 분리, native 명령 실패·무설치 기본값·종료 코드 회귀를 전달한다.
- 실제 Node.js 호출에서 `split(".")`의 따옴표가 소실되는 결함을 발견해 `node --version` 파싱으로 변경했다. 명령 실패·잘못된 버전 출력은 설치/검증 전에 중단한다.
- Git 한글 경로의 CP949 디코딩 오류를 repository policy와 실제 bootstrap 검증기 양쪽에서 수정했다. Git 경로는 UTF-8/NUL로 처리하고 선행 공백을 보존한다. 잘못된 바이트 출력은 검증기에서 명시적 실패로 처리한다.
- [PM 후속 기록](2026-09-08-pm-followup.md)에 #42 D-01~D-09, #55 공통 계약·확장 경계와 보드의 오래된 설명을 정리했다. 그 문서의 시험 수와 미실행 표시는 해당 시점 기록이며 아래 추가 결과가 최신이다.

## 검토와 정책 범위 감사

1. 별도 Codex 세션의 읽기 전용 검토에서 실제 verifier의 CP949 오류, Node 따옴표 소실, 전체 policy glob 누락 검증 부족을 발견했다. 초기 지적을 보존하고 두 실행 오류를 회귀 시험 후 수정했다.
2. 최종 bootstrap/CI 6개 파일의 고정 텍스트·SHA를 다른 제공자에게 전달했다. 설치된 Claude CLI 2.1.263에서 도구 없음·MCP 없음·hooks 비활성·세션 저장 없음으로 실행했고 결과는 exit 0이다. 실행 metadata의 주 검토 모델은 Anthropic `claude-sonnet-5`이며 보조 Haiku 호출도 기록됐다. 모델명만으로 사람 검토나 전체 시스템 승인을 주장하지 않는다.
3. 해당 제공자는 Windows 변경 범위에서 차단 결함을 보고하지 않았다. 명령 실행 없이 제공된 텍스트를 검토했으며 독립 테스트 실행·병합 승인은 하지 않았다. 실제 Windows 시험 결과는 위 표와 별도다. `Write-Error` 뒤 `exit`의 중복, private CPython helper를 사용하는 시험, 미설치 Node의 조건부 제외는 비차단 사항이다.
4. [정책 범위 감사](2026-09-08-policy-scope-audit.json)는 현재 **14개 POLICY_GLOBS**를 하나씩 제거한 합성 실행이다. 필수 4개와 별도 설정 검사에 필요한 `.pi/settings.json` 부재는 실패하고 나머지 9개 부재는 현재 통과한다. 이것은 승인된 기대 동작이라고 판정한 것이 아니다. 단계별 승인·기대 manifest 대조 등은 기존 #52(R-07)의 잔여 항목이다. 제공자 출력의 glob 수 표기 오류는 실제 코드/감사 결과의 14개로 정정했다.

제공자 검토의 원문·입력 manifest·실행 로그는 로컬 ignored 경로에 보존한다. 소스 hash와 정제 결과는 [인계 receipt](2026-09-08-delivery.json)에 결속한다. 아직 PR 동료 검토와 최종 #44 수용은 남아 있다.

## 성능 계측 초안과 실패를 보존한 범위

`SchoolWindowsValidationDriver.cs`는 **별도 검증 checkout의 Assets/SchoolValidation에만 복사**하는 계측 초안이다. 원본 Builder로 만든 장면에 계측기를 추가하고 별도 Windows 실행본을 만든다. 평상시 NPC·사건 상태, 고정 위치의 시점 회전, 120초마다 새 근무를 측정하도록 작성했으며 수동 입력·사건 대응 완주를 대체하지 않는다. 실제 장시간 실행은 시작하지 않았다.

- 20초 batch 파일럿: 프로세스 종료는 정상이나 Update 횟수를 렌더링 FPS로 사용할 수 없었다.
- 20초 일반 실행 파일럿: `cameraRenderCallbacks=0`, OS working/private memory 열도 0이었다. 창 숨김 상태와 계측 경로의 영향은 아직 진단하지 않았다.
- `summarize_profile.py`는 실제 파일럿을 `Update throughput is not rendered-frame evidence` 오류로 거부했다. 따라서 **FPS·메모리 추이·장시간 성능 수치는 수용하지 않으며 결과를 PASS로 게시하지 않는다.**

후속 수행자는 실제 렌더링과 지원되는 OS 메모리 계측부터 검증한 뒤 짧은 파일럿→정해진 장시간 관측으로 진행한다. 현재 계측기는 제품 빌드에 통합하지 않고, `Packages/`·`ProjectSettings/`·공통 게임 코드의 변경 없이 별도 diff로 계속 검토한다.
